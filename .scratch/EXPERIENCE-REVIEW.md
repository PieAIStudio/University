## 二、他对的地方（我照单收下）

1. **"不要做 600 条超级 checklist"** —— 这是全篇最有价值的一句。
   大清单会产出 150 条"可以考虑增加微交互"，最后还是你一条条判断，等于没解决。

2. **State Matrix 是真的缺口。** Journey 回答"走哪条路"，State 回答
   "这条路上所有可能的状态我们设计了吗"。这是两码事，我们确实只有前者。

3. **20 秒放弃遮罩之后到底显示什么** —— **这是他最好的一击。**
   我读了代码：`useMapCover` 20 秒后无条件卸载遮罩。如果 WebGL 真的挂了，
   学习者拿到的是一张空白画布，**没有重试、没有解释、没有降级入口**。
   这是真缺口，不是他脑补的。

4. **Loading Screen ≠ Splash Screen。** 不要为了遮加载做片头动画，
   那会让实际更快的产品体感更慢。对。

5. **Transition 要按语义分类，不要做一套全局动画。** 对。

6. **AI 证明不了"真实学生觉得好用"。** 诚实，加分。

## 三、他错的地方（这部分是我付钱请你听的）

### 错 1 · 这是转化率问题，他当成了 UX 问题

你的原话是"最核心最核心是转化率"。他给的 11 条黄金路径里，
**付费边界排第 10 条**。整套框架里没有任何一个环节在问
"用户在哪一刻开始想付钱"。

一个靠订阅活的产品，**付费路径应该是第 1 条，不是第 10 条**。
而且"支付流程能不能走通"和"用户想不想走"是两个完全不同的检查。
他只有前者。

### 错 2 · 462 格的矩阵，跑一次就再也不会跑第二次

他要求 11 条路径 × 21 个状态 × 桌面/手机 = **462 格**。
他说"AI 先判断哪些适用"——但这个判断本身是不受约束、不可复现的。

**一个流程如果一轮要跑四小时，它会被跑一次，然后永远躺在文档里。**
你自己提的要求是"简洁、高效、以后方便用"。462 格不满足其中任何一条。

打个比方：这就像请了一个体检套餐，462 项，做完要两天，
于是你这辈子只会做一次。**真正有用的是每天早上量一次体重**——
便宜到你不会跳过，而且体重真的变了你立刻知道。

### 错 3 · 没有"结论会死掉"的机制 —— 这是 AI 审查流程的头号死因

他的循环是：发现 → 简报 → 你决定 → 修 → 重跑。
**但没有任何机制阻止第二轮重新报告第一轮的 80% 内容。**

我去查了一下这方面 2026 年的研究。有一篇 UXBench 专门量化
"LLM 生成的 UX 意见有多少是可执行的"，它列出的四大失效模式是：

> 泛泛而谈 / 无法复现 / **重复** / 幻觉

**重复排第三，而他的方案对此毫无设计。**
现实里这就是这类流程的死法：第二轮你发现一半看过了，
第三轮你就不看了。

### 错 4 · "把成熟问题变成 E2E 门禁"只有一行字，但它才是全部的价值

这句话是整个循环里**唯一让它变成复利而不是西西弗斯**的部分，
他给了一行。

真正让这件事成立的规则是：**每修一个 P0/P1，必须留下一个可执行的断言。**
否则三周后你会重新发现它。

### 错 5 · 你说的"卡顿"，他改写成了"感知性能"

你的原话是"有的时候会有卡顿"。他立刻把它翻译成
"perceived performance / 有意义的等待状态"。

**这是两件事。** 卡顿如果是真的掉帧（GC 停顿、shader 编译、
draw call 太多），那是要用帧时间去量的，不是靠走查看出来的。
他那三个技能没有一个在量帧时间，所以这套流程**永远发现不了你实际报告的那个症状**。

### 错 6 · 他假设三个技能能干净地叠加，实际会三倍重复

ScreenWalk、Experience Capture、Impeccable 对同一批屏幕各做一遍启发式评审，
产出会大面积重叠。他把"合并/去重/找根因"画成一个框。
**那个框是整件事最难的部分。**

### 错 7 · 写成 Markdown 的 State Matrix，一周之内就会和代码脱节

他建议 `experience-review-matrix` 作为"项目文档"。
散文写的矩阵会漂移。**能漂移的东西不该是文档，该是测试。**

## 四、所以我建的是什么

一句话：**把体验审查按成本分层，和批改分层是同一个道理。**

这个项目已经有一条"确定性优先 → 小模型 → 开放模型"的批改分层。
体验审查用同一个形状，**因为它对这个代码库是"本地口音"，
不是我从外面搬来的第八套方法论**。

```
第 0 层  探针     机器判定    每次 push 都跑    零模型成本    ~90 秒
第 1 层  差分     只看变了的  探针事实变了才升级
第 2 层  评审     模型判断    只跑差分         赛马
第 3 层  账本     结论会死    每条发现有状态，重复的不再报
```

### 第 0 层：六条跨屏不变量（正在建）

不是清单，是**表驱动的测试**：路由是数据，断言是代码。
每一条都对应一个真实发生过的缺陷：

| 不变量 | 对应的真实缺陷 |
| --- | --- |
| X1 每个对话框都有出口 | **今天早上刚修的课程卡** |
| X2 每条路由都回得去 | 死路 |
| X3 学习者必须碰的东西没被盖住 | **W-001，工具条盖住输入框，至今没修** |
| X4 手指点得到（44px） | 手机可用性 |
| X5 点了要有回应（300ms 内） | **W-002，点登录什么都不发生** |
| X6 axe-core 无障碍基线只准变小 | 对比度、标签、焦点 |

**关键点：这里没有一条需要模型判断。** 全部机器可判定，
所以可以每次 push 都跑，而不是"想起来的时候跑一次"。

### 第 3 层：账本（这是他完全没有的）

每条发现算一个稳定 ID（路径+状态+类别+位置的哈希），带状态：
`open / fixed / accepted-debt / wontfix`。
**每轮只报增量。** 已接受的欠账默认不再出现。

**这条规则是整个设计里最重要的一条**，因为它决定了这个流程
是活三个月还是活三天。

### 什么是我明确砍掉的

- 462 格矩阵 → 每条路径只展开它**真实存在**的状态
- 三技能全量叠加 → 只在探针事实变化时升级，且赛马而非串行
- 散文写的 State Matrix → 状态就写在测试的表里，**没有漂移的余地**

## 五、今晚这套东西已经证明了自己

我不是先写方法论再去验证。我是**先撞上了，才反过来写方法论**。

### 证据 1 · push 闸门抓到了 main 上的真实缺陷

清理完 worktree 准备 push，pre-push 的浏览器 e2e **拒绝了这次 push**：
`F.island-pick` 两条测试红。

`pnpm verify` 是绿的。**绿的子集不是闸门。**

### 证据 2 · 它失败的原因，比它失败这件事更重要

测试断言的是"点海面之后卡片消失"。它失败了——但不是因为这个功能坏了，
而是因为**地图上已经没有海面可点了**。

53 座岛铺满了整个视口。而那张课程卡是 `role="dialog"`，
它的三条退路全部不可靠：

- 点空天空 → 几乎没有空天空
- Esc → 手机上没有 Esc
- 点非画布的 chrome → 学习者不知道

**一张占了三分之一屏幕、关不掉的卡片。** 已经修了：加了关闭按钮，
44×44，粘在标题行不会滚走。

### 证据 3 · 修完必须攻击测试

把 `onClick={onDismiss}` 改成 `onClick={() => {}}`，重跑 → **两条测试变红**，
报错指向新加的那一步。还原 → 绿。

**没见过红的断言不算断言。**

### 证据 4 · 顺手挖出发布通道其实一直是坏的

要发布线上版本时，delivery 构建失败：
tracked 的 `imported.json` 记的是 4,177,694 字节（带 evidence 的本地构建），
而 delivery 通道只支持 `--evidence none`，产出 3,963,039。

于是每次发布都在拿自己和自己比，把差额读成"内容丢了"，然后拒绝写入。
**一个用来防止少发内容的守卫，挡住的恰恰是那个本来就该少发的构建。**

线上一直是 3,963,039——所以这个数字本来就是对的，只是**没写进仓库**。

### 这四条证据合起来说明一件事

前三条里没有任何一条是靠"AI 走查发现的"。
它们是**机器断言抓到的**，或者是**做事的时候撞上的**。

这就是为什么我把钱押在第 0 层，而不是押在三个技能叠加上。
