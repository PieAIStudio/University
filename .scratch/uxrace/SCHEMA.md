# 两位评审共用的产出格式

每条发现写成下面这个块。**不符合这个格式的发现我会直接丢掉。**

```
### <ID> · <一句话说清是什么问题>

- 屏幕：<URL 或路由>
- 视口：desktop 1440x900 | phone 375x812
- 元素：<具体的可见文字、按钮名、或截图里的位置>，不要写"某个按钮"
- 复现：
  1. …
  2. …
  3. …（一个没见过这个产品的人照着做，必须能看到同样的结果）
- 看到了什么：<客观描述，不带判断>
- 为什么是问题：<对谁、在什么心理状态下、造成什么后果>
- 证据：<截图文件名>
- 严重度：挡路 | 难受 | 毛刺
- 把握：确定（我亲眼看到）| 存疑（我推测，没验证）
```

## 三条会让发现被丢掉的规则

1. **没有截图的视觉判断不算数。** 你必须真的打开页面看到它。
2. **不许写泛泛的建议。** 「可以考虑增加微交互」「视觉层级可以优化」
   这类句子一条都不要写。每条发现必须指向一个具体元素和一个具体后果。
3. **不许猜代码。** 你看不到源码。只描述你看到的现象，不要推测实现。

## 严重度定义

- **挡路**：走不下去，或者会让人直接关掉页面。
- **难受**：能走下去，但会犹豫、误解、或觉得这产品不太行。
- **毛刺**：小瑕疵，记下来，不急。
