# 打开项目文件夹，为什么找不到一份「整个产品」？

你点开图灵密约，屏幕上是个能玩的产品。但打开做它的文件夹，却找不到一份写着「这就是整个产品」的总文件——先撞上的几份文件，每一份都在把你往别处指。

## 打开文件夹，你会先看见这些互相点名的文件

下面这几行第一次看会觉得密，不用背。AI 能帮你改文件，但你要慢慢看懂一份文件在把你往哪引，才能让它改对地方。

网页入口 `index.html` 的末尾，并没有把整个界面写在里面，而是去加载另一份脚本：

[[evidence:index.html:31]]

:::detail[`index.html` 末尾那一行在干什么？]
这里的「脚本」就是给浏览器执行的代码文件，不是电影剧本。那一行是在对浏览器说：读完这一页之后，去执行 `/src/main.tsx`。它不画按钮、不排文字，只点名下一份要跑的文件。入口在这里写的只是「下一份读谁」，不是整页界面。
:::

:::detail[文件夹名 `src` 通常代表什么？]
通常是英文 source，中文常说「源码」。日常要改的那些文件，常常放在这个文件夹里。所以看到路径里的 `src`，读法就是：这份启动脚本在源码文件夹里，不在手机上打包好的成品里。以后看到 `/src/` 开头的路径，先把它读成「源码文件夹里的某一份」，而不是「装在手机上的成品」。
:::

那份启动脚本一开头，又立刻从别的文件把东西引进来：

[[evidence:src/main.tsx:1-2]]

:::detail[`import` 在启动文件开头是什么意思？]
可以把它读成「从别的文件把东西借过来用」。开头那两行不是在画按钮，而是在点名：要借的东西从哪份文件来。借进来不是把文字抄进启动文件，只是写清「用的时候去哪份里取」。启动文件负责把借来的东西接在一起；真正画到屏幕上的内容，写在被点名的那些文件里。
:::

第二行点名的 `App`，是整棵界面从哪一块开始长的名字。

:::detail[`App` 在这里指什么？]
它是整棵界面从哪一块开始长的名字。启动文件把它借进来，挂到网页上。看到 `from './App'`，读法就是：从旁边这份 `App` 文件，把界面的起点借过来。你想找界面从哪开始长，顺着这个名字走就行，不用在启动文件开头里找。
:::

管外观的总入口 `src/index.css` 的前几行，几乎全是「再引入别的样式文件」：

[[evidence:src/index.css:1-6]]

:::detail[`@import` 在样式文件里是什么意思？]
样式就是外观规则：颜色、间距、字体怎么摆。`@import` 的意思就是：把另一份样式文件的内容并进来。它不用在总入口里把规则重抄一遍，只管点名。这里点名了字体、现成的样式工具，以及几份更专门的样式文件。总入口本身很短，具体怎么上色、怎么留白，写在被点名的那些文件里。
:::

项目登记名写在另一份清单 `package.json` 里：

[[evidence:package.json:2]]

:::detail[`package.json` 的 `name` 写的是什么？]
写的是 `turing-pact`：给电脑工具认的项目登记名，小写、带连字符。它不是按钮上的字，也不是你在屏幕上看到的游戏标题。你在清单里改这一行，屏幕上的标题不会跟着自动变——标题写在别处。清单和界面是两份东西。
:::

同一个产品里，你至少能看到四处去向：入口、启动脚本、样式拼接点、项目登记名。没有哪一处单独写完整个产品。第一眼看到，常常觉得「这么多文件，是不是乱了？」

## 先猜一下

把这四处全塞进同一个文件，明天你只改其中一件事——比如只改项目登记名——会更好找，还是更难找？为什么？

先写下你的判断，再往下看答案。

## 答案

更难找。挤在一份里，改个登记名也得在不相干的行里翻；分开放，打开清单那一份就行。

## 为什么分开放，改一处反而更好找？

入口只负责让浏览器开始读，并点名启动脚本；启动脚本负责把界面画到页面上；样式总入口负责把外观规则拼成一套；清单负责登记项目名。改外观，优先打开样式那份；改登记名，打开清单那一份。一份文件短、职责清楚，你就少翻到不相干的行。

**打个比方：** 把目录、正文、插图说明、出版社信息全印成一张没有页码的大海报，改一个错字，整张都要重印。分文件像分章节——改外观不必翻启动逻辑，改项目名不必动界面代码。

对照刚才四处：

1. **入口** `index.html`：浏览器先读这一页，再去加载 `/src/main.tsx`。
2. **启动逻辑** `src/main.tsx`：开头把画界面的工具和 `App` 引进来。把界面画到页面上的启动代码在这份文件里，界面从哪一块开始长则在 `App` 里，两处不挤在一起。
3. **样式总入口** `src/index.css`：用 **`@import`** 把字体、现成的样式工具和其它样式文件拼起来。总入口很短，细节落在更专的文件里。
4. **项目登记名** `package.json`：`name` 字段是 `turing-pact`；它和界面长什么样是两件事。

:::detail[为什么拆开之后改一处不容易牵动全身？]
因为你知道该打开哪一份文件。把这四处全塞进同一个文件，明天只改项目登记名，也要在入口、启动、样式的行之间翻找。拆开之后，改登记名去清单那份，改颜色去 `theme.css` 那份，启动文件可以不动。牵一发动全身，常常是因为职责还挤在一起。

**打个比方：** 像一栋楼里你知道该推哪一扇门，而不必把整栋楼拆开找一盏灯。
:::

所以看到文件多，通常表示责任被切开了，不是乱成一堆。
