# 空的 root 盒子，为什么最后会出现整页界面？

## 屏幕上是满的，入口文件末尾却几乎是空的

打开图灵密约的网页，屏幕上是完整界面：按钮、文字、排版都在。

可翻到入口文件 `index.html` 的末尾，真正留给「页面内容」的只有这么一小段——一个空盒子，外加一行叫浏览器「去加载另一份文件」的指令：

[[evidence:index.html:29-31]]

第 30 行那个盒子中间是空的：没有菜单，没有段落，也没有你在屏幕上看到的任何界面。它带着名字 `root`，写在 `id="root"` 里。平时大家口头常把它写成 `#root`：井号 `#` 只是个习惯记号，用来指「叫 root 的那一块」；你在文件里找的时候依然是 `id="root"`，并没有井号。第 31 行只是告诉浏览器：接下来去执行 `/src/main.tsx` 这份文件。

:::detail[入口文件自己写出整页界面了吗？]
没有。浏览器先读 `index.html`，才知道页面上的空盒子在哪、接下来该去执行哪份文件。它自己几乎不写你看到的按钮和文字，只负责标好位置、给下一份文件点个名。

**打个比方：**就像戏院门口的节目单：看了它，才知道舞台在哪、演员该从哪份剧本开始念。你在手机上点开看到的满屏界面，并不是把整台戏都手写在这一页里。
:::

:::detail[盒子中间是空的，那 id="root" 是在干什么？]
它是一个 `div`：网页里用来划区域的通用盒子，自己几乎不带颜色和样式。`id` 就是给这块区域取的唯一名字。这里取名叫 `root`，英文里是「根」的意思。盒子头尾标签之间一个字都没有——不是「里面塞了很长一段界面文案」，就是纯粹的空盒子。名字挂在盒子上，界面却没写在里面。
:::

:::detail[第 31 行那行 script 在干什么？]
`script` 是在告诉浏览器：「别光看这一页，再去执行另一份代码。」`src="/src/main.tsx"` 写的就是那份代码的路径。这一行里的 `type="module"` 是加载方式的标记——现在不用纠结这个词，只要知道：浏览器读完这一页，就会接着去跑 `main.tsx`。这一行本身还没画出任何按钮。
:::

## 先猜一下

满屏界面，究竟是从哪一步被「填」进这个空盒子的？

先写下你的判断，再往下看答案。

## 答案

浏览器执行 `src/main.tsx` 之后，那份文件会按名字找到这个空盒子，再把你看到的整页界面填进去。

## 从空盒子追到满屏界面，中间经过哪几站？

### 第 1 站：入口文件只占位，并点名下一份文件

回到入口文件末尾。这一站只做两件事：摆好空盒子，并点名接下来跑哪份文件。

[[evidence:index.html:29-31]]

单看这一页写了什么，界面还没影呢——但「往哪填」已经定好，`main.tsx` 也被点名了。

### 第 2 站：被点名的那份文件找到盒子，并画上界面

打开 `src/main.tsx` 里真正干活的那一行。代码挤在一起，初看容易绕。你不用背、也不用手写它；以后跟 AI 一起改代码时，只要能认出它大致在干嘛，能判断改得对不对就行。

[[evidence:src/main.tsx:32-32]]

咱们由内向外拆成三个动作：

1. `document.getElementById('root')`：在当前页面里找 `id` 为 `root` 的那块——正是第 1 站那个空盒子。
2. `ReactDOM.createRoot(...)`：在这个盒子上，把后续画界面的入口准备好。

:::detail[代码里写的是 ReactDOM，它和 React 是一回事吗？]
不完全是。React 是这项目用来搭界面的工具库。你在启动文件里看到的 `ReactDOM`，专门负责把界面画到网页上，所以代码写的是 `ReactDOM.createRoot`，而不是单写一个 `React`。你不必急着学会写它，只要认出 `createRoot` 和 `render` 是「找到盒子 → 把界面画进去」的两步就行。项目选了它，启动文件里才会出现这些名字；换另一套工具，写法虽然不同，但「先占位、后由程序填」这件事常常一样。
:::

3. `.render(<App />)`：把名叫 `App` 的界面画进去。之后你在屏幕上看到的按钮和排版，都是在这一步被画进盒子的。

:::detail[`App` 是什么？]
`App` 在这项目里代表「整页界面从哪起步」。画进空盒子的入口就叫 `App`。它里头还会拆成更小的块，这里先不用拆；你只要知道：空盒子之所以被填满，是因为程序把 `App` 画了进去。

**打个比方：**它就像总电闸后面的主面板。面板后头连着很多小开关，但直接接进空盒子的那根主线，写的就是 `App`。
:::

:::detail[为什么括号里会写出 `<App />` 这种尖括号？]
刚才步骤 1 里传的是普通引号参数 `'root'`，到了步骤 3，圆括号里却冒出了带尖括号的 `<App />`，长得很像网页标签。在这份文件里，它的意思就是：把名叫 `App` 的界面放到这儿画出来。末尾的斜杠表示这一笔已经写完，不用再配一个结束标签。你现在只要能认出「这行在画 `App`」，用不着自己手写。
:::

:::detail[如果删掉空盒子、只留脚本，会发生什么？]
程序照样会跑到 `getElementById('root')` 这一步，却扑了个空、找不到这个名字。后面的 `createRoot` 和 `render` 也就没了落脚点。留个空盒子不是偷懒，而是后面代码约定好的落脚地。
:::

顺序并不是「先把整页界面写进入口文件」，而是：

**空的 `#root` → 加载 `main.tsx` → 按名字找到盒子 → 把 `App` 画进去 → 界面出现。**

## 再想想

现在只要你能指着这个空盒子说出「程序从这里开始画」，就算过关了。以后你在别处看到 `#root`，就知道它指的就是叫 `root` 的空盒子。至于 `App` 里面怎么拆成更小的块，后面接着看。如果你还想把「看到的界面」和「改的源文件」整条链路接起来，可以看后面的 [[lesson:from-icon-to-files-journey|点开图标到源文件的那条路]]。
