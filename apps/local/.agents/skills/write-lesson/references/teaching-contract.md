# 教学合同：像一位好老师那样带一节 PRIMM 课

这份文件是写课、查课、修课共用的**唯一教学规则**。`primm-pipeline` 把它原样
贴进 Writer、Detector、Fixer 的提示里；人写课时也读它。改规则只改这一处。

它不含任何一节课的故事。样板课是回归样本，不是模板：不要沿用它们的照片、
通知、人物或句子。

## 0. 谁在学，用什么话讲

学习者：几乎没用过 AI 的普通成年人。会用手机、微信、网购；聪明，但没有技术
背景；时间零碎；看到陌生词会停下来，停两次就关掉。

**字句难度：8–9 岁的孩子能读懂。内容和态度：把他当成年人。**

- 一句话只说一件事。大多数句子不超过 25 个字；超过 35 个字就拆开。
- **短句不等于碎句。** 不要把一个道理剁成五六个没有主语的半截话。用“因为、所以、
  可是、这样一来”把前后连起来，读起来像人在说话，而不是在念清单。
- 用日常词。先说“把照片发给 AI”，不说“进行图片输入”。动词优先，少用抽象名词。
- 不用这些词：场景、维度、要素、输入、输出、交付物、闭环、验收、溯源、赋能、
  提示词工程、模型能力、上下文窗口。确实需要一个新词时，先用大白话把事情讲清，
  再告诉他“这叫……”，而且只在后面真的要用到它时才给名字。
- 产品名、机构名第一次出现时，用半句话说清它是什么：
  “Be My Eyes（一个帮看不见的人‘看’东西的手机应用）”。
- 称学习者为“你”，称 AI 为“AI”。不用“助手”“助理”“它们”替代。
- 先讲字面意思。比喻最多点一句，不能代替解释。
- 不哄小孩：不用“小朋友”“超棒哦”，不堆感叹号，不假装事情很难或很好玩。
- 不吓人，也不夸口：保留“多数时候”“可能”“不一定”；不说“绝不”“一定能”。

## 1. 先找真需要，再找材料

写任何一个字之前，先回答：**普通人在什么时候，真的会想用这一招？**

1. 列出至少 5 个生活时刻。每个写清：谁、什么时候、手里有什么、想做成什么、
   不用 AI 时平常怎么办、麻烦在哪。
2. 逐个做两道淘汰题：
   - **这个月会遇到吗？** 很少人会遇到的，淘汰。
   - **有更简单的办法吗？** 如果直接转发、直接看一眼、直接问身边人就解决了，
     这个需要是假的，淘汰。（例：想让家人知道你在喝什么咖啡——直接发照片就行，
     不需要 AI 描述。）
3. 选最常见、AI 帮得最明显的一个做练习；另选一个**不同的**做最后的独立任务。
4. **材料跟着情境走。** 材料就是这个人手里真的会有的东西：一条留言、一张通知、
   一张拍下的说明、一段写了一半的消息。长度和样子要像真的——真通知常常有多余
   信息，真消息有口语。太短、太干净的材料会让 AI 的帮助显得多余。
5. **教最简单、最可靠的做法。** 学习者平常最自然的做法如果已经能解决问题，就先教
   它（例：想知道一个生字怎么读，直接问“这个字怎么读”就行，不必先学一套提问格式）；复杂的补救写法只在它不够用时再教，或放进“更多”。
   不要为了显得有技巧，教一个普通人不会用的绕法。
6. 如果现有授权素材不适合最好的情境，就选一个有诚实素材可用的真情境；
   **不要为了用上一张现成的图，编一个没人会有的需要。** 素材实在撑不起真情境时，
   就诚实地说这是练习：“这份材料你自己看得懂，正好拿来练，因为你能判断 AI 说得
   对不对。”再说清以后真会用上的时候（看不懂的、看不清的、来不及看的东西）。
   诚实的练习理由，胜过编出来的生活故事。

7. **从学完能做成什么倒推**（先定目标，再定检验，最后才设计活动）：先写一句
   “学完你能……”，再想 Make 里什么表现能证明他真会了，最后才设计前面四段的动作。
   这些生活时刻是我们的假设，不是调查结论；不许许诺省多少时间、一定学会。

开场读完，学习者应该能在心里说一句：“我遇到那种事时，可以这样用 AI。”

## 2. 真实案例：证明这件事有人真在做

- 它回答“现实里有人这样用吗？”：谁，遇到什么，用 AI 做了什么。1–3 句，大白话，
  附链接。只写链接材料真正支持的事。
- 然后用一句话交还给学习者：从别人的事，转到他自己会遇到的事。
- 案例是一扇门，不是整座房子。后面的练习不必用案例里的东西；不考案例的
  人名、年份、机构。
- 案例放在最能帮助理解的地方，通常在开头。

## 3. 老师的话：整节课是一条线

学习者烦躁，多半不是因为字多，而是因为**不知道为什么现在做这件事**。
每一屏都要有老师在说话，而且是接着上一句说。

每一屏开头的一两句，要让学习者很快知道：
- **接着什么**：指向他刚才做的事或看到的结果（“刚才 AI 把三句话都改了。”）；
- **现在做什么，为什么**：理由来自他自己的小事，不来自课程结构；
- **做完看什么**：只在不明显时说。

不必写成四个标题，自然的一两句就够。前一屏的反馈已经交代了过渡，这一屏就别重复。

**做完才讲，讲的是刚才发生的事：**

- `run.debrief`：结果出来后才显示。把预想和结果对上：发生了什么，为什么会这样。
- `investigate.explanation`：动手操作完成后才显示。说出他刚才自己发现的道理。
- `modify.debrief`：改过的请求跑完后才显示。说明改了哪句话，结果为什么跟着变。

结果是真的 AI 当场生成的，每次可能不同。所以 debrief **不能断言结果里一定有
某句话**。更要紧的是：**不要把整节课押在 AI 这次一定出错上。** 它这次可能恰好
做对了。道理要在“做对了”和“出错了”两种结果下都讲得通——通常是把学习者的动作
设计成“检查它有没有保住……”，而不是“看它丢了什么”。后面几屏也不能默认它出过错。用“看看它有没有……”“多数时候……”“如果它……，说明……”这样的说法，
让两种常见结果都讲得通。

**老师连读测试。** 把这些话按顺序连起来读：开场 → 预想问题 → run.note →
run.debrief → investigate.brief → investigate.explanation → modify.brief →
modify.debrief → make.scenario → make.goal → finish.note。它应该像一位老师从头到尾
带人做完**同一件小事**。
- 哪一句放进别的课也照样成立 → 太空泛，改。
- 哪一句用到了还没讲过的东西 → 太早，挪后或先讲。
- 哪两句之间要读者自己脑补一步 → 缺台阶，补一句。

**不写运行失败怎么办。** 没拿到结果、要重试，是界面自己负责说的事；老师的话只讲
拿到结果之后怎么看。“要是这次没有回答，就……”这类话是写课人在防备流程，不是
在教学习者。

**删什么：**界面已经表达的操作（“点击下面的按钮”“在下方选择一个选项”
“选完之后点继续”）。
**留什么：**为什么做、材料是什么、不明显的操作规则（例如“一张卡可以连几条线”）、
重要边界。
判断标准：删掉这句，学习者会不会不知道为什么做、材料是什么、下一步是什么，
或误解一个重要边界？不会，就删。不以字数少为目标，也不以“讲得全”为理由重复。

## 4. 五个阶段，各自做什么

阶段固定为 Predict → Run → Investigate → Modify → Make，不增不减。标题写这一屏
要回答的小问题，用学习者的话，不写阶段名。每个阶段一屏、一个主要动作，整节
8–12 分钟。

**骨架不变，段内的动作按需要挑。** 课程不枯燥，首先靠每节都换一件学习者真会
遇到的事；其次才靠段内动作的变化。动作由“这一步他要弄懂什么”决定，不为变化而
变化。同一单元里相邻两节不用完全相同的动作组合；只换按钮样式、换标题不算换动作。

| 阶段 | 现在能用的动作 | 以后可加（未实现，写课时不能用） |
| --- | --- | --- |
| Predict | 从 2–3 个想法里挑一个 | 先自己试写一句再看；猜哪份结果来自这句请求 |
| Run | 放入材料，实时运行同一句请求 | 同一句跑两次看差别；明确标注的演示（不能或不该实时运行时） |
| Investigate | 对照检查真实结果、看图局部、分类、排版、只改一句、挑资料（见下表） | 在结果里直接划出哪句来自材料、哪句是 AI 加的 |
| Modify | 用可编辑的短句改请求再跑；或直接改写整句 | 接着追问一句 |
| Make | 换材料和用途，自己写请求、运行、改成品 | 改 AI 的草稿成自己的版本 |

### 步骤版（第 3 版）：五段固定，段内步数和玩法可变

Owner 已认可“一屏一句话、一个动作”的步骤版（样板见 journey v5 的“微步骤”）。
一节课是一串**步骤**；每步只属于一个阶段，只做一个动作，做完才出现一句老师的话。

- 阶段顺序固定：猜 → 跑 → 看 → 改 → 做，每段 1–4 步，不能缺段。
- **玩法不绑阶段。** 同一种玩法可以出现在不同阶段，同一阶段可以用不同玩法；
  哪一段放几步、用哪种，由这节课要教的东西决定。约束只有三条：
  跑段恰好一次“发出去”，改段恰好一次“发出去”，做段恰好一次“自己写”。
- 一步的字数：标题一句，说明最多两句；老师的话在动作之后，一两句。
- 依赖真实结果的步骤（在回答里找句子、配对、对照），老师的话只能根据学习者自己的
  选择或操作来说，不能断言这次 AI 写了什么。

第 3 版目前由人按样板写并用原生命令落地；生产线还只会写第 2 版（下面各段的字段）。

### Predict · 先猜

- **猜的是怎么用，不是猜 AI 会怎么说。** 学习者是来学怎么用 AI 的；他还不会用，
  猜 AI 的措辞、顺序、先说哪样，对他没有意义（Owner 2026-09-20 否决）。
  猜一个用法上的选择：哪句问法最能问到、该给哪份材料、要不要写清用途、交给 AI
  之后还要自己做什么。
- 最好让他的选择**真的被运行**：选哪句就发哪句，结果替他验证，而不是老师宣布对错。
- 问一个初学者**真的拿不准**的选择；2–3 个选项，每个都是真实初学者可能会做的。
- **不能照着题面就选出答案**，也不要用“正确答案”的腔调。选得不好也能继续，
  正好是往下看的理由。

### Run · 真的发出去

- 发的就是预想时看到的同一份材料、同一句请求。不偷偷加要求。
- `run.attachmentLabel` 是按钮上的一个动作，写成“把……放进对话”，不写材料名。
- `run.note`（运行前）：一句话说看什么。
- `run.debrief`（结果后）：按第 3 节的方式，把预想和结果对上。屏幕上方已经显示了学习者
  选的那一项；debrief 不能假定他选了哪一项（“你刚才猜的是……”），要对每一种预想都说得通。

### Investigate · 弄明白刚才发生了什么

- 学习者动手操作**和刚才这次运行有关的东西**：同一份材料、刚才的结果、
  或二者之间的差别。不能换成一道与运行无关的题。
- `investigate.brief`：接着 debrief 说，为什么要动手看这个。debrief 已经接住了
  这次结果，brief 不要再猜结果（“不管刚才有没有……”），直接说接下来要弄懂什么。
- 操作完成后才出现 `investigate.explanation`：说出道理，扣住他刚做的事。
- `more`（可选）：初学者此刻真会追问的一两个问题。
- 不假装展示 AI 的“内部想法”。

按学习者要弄懂的事选玩法。写 PRIMM 课选的是**内层**这 13 种，不是外层课文活动
`LessonActivityKindSchema` 那 15 种；两套互不相干。当前产线用内层（第 2 版写
`investigate.game.kind` 的 6 种；第 3 版由人写 `steps[].kind`）。`sort` 在两套里
同名不同物：外层是独立归类引擎，这里是 PRIMM 里把卡放进桶。

| 学习者要弄懂的事 | 玩法 | 这节课必须真有 |
| --- | --- | --- |
| 刚才的结果有没有保住材料里要紧的东西（漏了、改了、多了） | `check-result` | 第 2 版 `investigate.game`。`items` 2–8 项；每项有 `label`、`expected`（材料里的说法）、`why`。通关：每一项判成 `kept` / `changed` / `missing` 之一即可，没有标准答案、不打对错分；判完才显示 `expected`。只在学习者手里有看得懂的原材料时用（听不懂的外语录音不行：他没有尺子，只能瞎猜） |
| 一张图里有哪些地方值得追问 | `inspect-image` | 第 2 版 `investigate.game`。`assetId`、`instruction`、`regions` 1–20；每块有 `label`、`note`，坐标归一化在图内（x/y≥0，宽高>0，右下角≤1），id 不重复。通关：点中**任意**一块并写下观察——不是点对唯一正确答案（要点对用第 3 版 `point`） |
| 几样看起来像、其实不同的东西，各属于哪一类 | `sort` | 第 2 版 `investigate.game`：`buckets` 2–8、`cards` 2–30。第 3 版 `steps[]`：`buckets` 2–4、`cards` 3–10，phase 仅 predict / investigate / modify，必有 `after`。两边都要：桶 id 不重复、卡数 ≥ 桶数、每个桶至少一张卡、每张卡有 `bucketId` 和 `why`。第 2 版通关：每张卡都放到正确的桶。第 3 版通关：每张卡都放入某个桶即过关（放错也继续） |
| 同样的内容，怎么排才好用 | `layout` | 第 2 版 `investigate.game`。`items` 2–20（每条有 `label` 和 `text`）、`formats` 2–8、`instruction`；id 不重复。通关：动过顺序或选过一种排法即可——没有标准答案顺序 |
| 只改一处，别处不动 | `edit` | 第 2 版 `investigate.game`。`sentences` 2–20、`targetId` 必须是其中一句、`instruction`、`replacementHint`。通关：选中 `targetId` 那一句，写出与原文不同的非空替换；点错句不能改 |
| 一堆资料里，哪些和这次问题有关 | `collect` | 第 2 版 `investigate.game`。`cards` 2–30；至少一张 `relevant: true`、一张 `relevant: false`；每张卡有 `label`、`text`、`why`，`sourceId` 必须是 `sources` 里的 id（练习材料在 `materials` 里，不能当来源，那种题用 `sort`）。通关：每张卡的去留必须等于它的 `relevant` |
| 该怎么用（哪句问法、给哪份材料、要不要写清用途）——不是猜 AI 会怎么说 | `choose` | 第 3 版 `steps[]`，任意 phase。`options` 2–4，id 不重复，每项有 `label`；若写 `requestId` 必须是 `starter` 或 `requests` 里的 id；若写 `answerId` 必须是某个 option。通关：选出任意一项即过关（有 `answerId` 时对错会提示，选错也能继续）。若 Run 的 `send.request` 是 `"chosen"`，Predict 里这个 choose 的每个 option 都必须带 `requestId` |
| 同一份材料、同一句请求，发出去之后实际得到什么 | `send` | 第 3 版 `steps[]`，phase 仅 run 或 modify。`request` 是已知请求 id，或 `"chosen"`（仅 run，且前面 Predict 的 choose 每个 option 都有 `requestId`），或 `"built"`（同阶段前面有 `build`）；必有 `attachmentLabel`。整课 run 恰好一次 send、modify 恰好一次 send。通关：真的跑出一次非空结果（有 starter 图时要先按 `attachmentLabel` 放进对话） |
| 刚才这次回答里有没有提到要找的东西，在哪一句 | `find` | 第 3 版 `steps[]`，phase 仅 run / investigate / modify。`terms` 1–6；两种结果都要写：`found` 和 `absent`。前面必须已有一次 send。通关：点中一句包含任一 term 的句子；若这次结果里没有任何一句包含这些词，点「没提到」也过关——课不能假定这次一定写了 |
| 换一句请求，结果会不会跟着变；几份回答各是哪句请求跑出来的 | `match` | 第 3 版 `steps[]`，phase 仅 investigate。`requestIds` 2–4，不重复，每个都是已知请求；必有 `after`。必须出现在第一次 send 之后。通关：先把这些请求都跑一遍，再把每份回答对到它自己的请求上，全部配对正确才过关 |
| 图上哪一块能把这个问题定下来 | `point` | 第 3 版 `steps[]`，任意 phase。`assetId` 必须是 `starter.assetIds` 或 `make.assetIds` 里的图；`regions` 1–8，坐标归一化在图内，id 不重复；`targetId` 必须是其中一块；必有点错时的 `miss` 和做完后的 `after`。通关：必须点中 `targetId` 那一块；点别处或点图片空白只显示 `miss`，不过关 |
| 请求里该留哪几句、按什么顺序拼 | `build` | 第 3 版 `steps[]`，phase 仅 modify。`pieces` 2–8，id 不重复；`answers` 1–4 条，每条 1–8 个 piece id（必须存在、一条内不重复），答案之间不能完全相同。通关：拼出的 id 序列精确等于某一条 `answers`；多一块、缺一块或顺序不对都不过。若 send 的 `request` 是 `"built"`，同阶段前面必须有这个 build |
| 换材料和用途，自己写、自己跑、自己改成品 | `make` | 第 3 版 `steps[]`，phase 仅 make。整课恰好一步 make，且做段第一步必须是它。任务写在载荷的 `make`：`scenario`、`goal`、`promptPlaceholder`、`checklist` 1–12、`exerciseId`，`materialIds` 至少 1 个且指向已有 material。通关：自己写出非空请求并跑出结果，评分 `outcome === "pass"` 才能继续 |

**动作必须练到这节课许诺的本事。** 许诺“挑出和自己有关的信息”，却给一个已经
挑好、只剩排顺序的玩法，就是没练到。先让学习者做那个决定，再看结果变化。

都不合适时，说出想要的动作和缺的能力，选最接近的并说明为什么，不硬凑。
别为了“互动”加无意义点击，不加倒计时、扣分，不编“AI 能力值”“可信度分数”。

### Modify · 自己改请求，再跑一次

- 学习者用刚才弄懂的道理，改原来的请求，真的重新运行，前后对照。
- `workbench.pieces` 是支架：2–4 个短句，用普通人会说的话写；都能改、能删、
  能调顺序。它们不是标准答案；也可以只放方向，让学习者自己补。
- `modify.goal` 说改完要达到什么效果，不把要写的请求原句先写出来（那是先给答案）。
- 若设 `carryObservation`，Investigate 里学习者写下的话会成为一个可用短句。
- `modify.debrief`：对照前后结果。AI 没照已写明的要求做时，指出是结果的问题，
  不说学习者没提要求。

### Make · 换一件事，自己来

- 换材料，也换一点用途（来自第 1 节的第二个情境）。学习者自己写请求、运行、
  检查、修改最后的作品。
- 不给整句请求。`promptPlaceholder` 是一个引导问题，不是答案。
- `checklist` 写“好结果应该做到什么”（从学习者的目的出发），不写要照抄的话。
- `artifactLabel` 写成品是什么（“发给房东的消息”），不写“作业”“练习”。
- Make 就是独立任务，后面不再加同义小测。

### Finish · 带走什么

- 一两句：下次在自己生活里遇到哪种事，可以怎样开口。具体，不喊口号。
  不宣称“你已经掌握了”。

## 5. 材料和事实

- 练习材料是作者编写的，**label 要写明是练习**（例如“房东发来的通知（练习）”），
  而发给 AI 的正文里**不写**“这是练习”“虚构”之类的话——AI 会把这句也当内容处理。
- 真实来源只用输入包里已经核实的网址，不另找链接，不把练习材料说成来源里的事。
- 照片、录音保留原有署名与授权说明。合成语音要标明是合成的。
- 数字、日期、人名在各阶段保持一致；Make 的材料与前面不同。
- 实时 AI 结果、作者写的示例、历史回放是三种东西，不混称。

## 6. 硬拒收：出现就必须改

检查者按这张表找问题；写的人交稿前自查。

| 代码 | 问题 |
| --- | --- |
| F1 假需要 | 练习情境里的人其实不需要 AI（有更简单的办法），或普通人很少遇到 |
| F2 案例绑架 | 真实案例的细节变成了练习对象或考点 |
| F3 预想照抄 | 读请求原文就能选出答案；或只有一个选项像样 |
| F4 结果后沉默 | Run 或 Modify 出结果后，没有老师的话帮他把预想和结果对上 |
| F5 先说答案 | 道理出现在动手之前；或卡片、选项上印着答案 |
| F6 跳题 | 某一步和上一步不是同一件小事，或没说为什么现在做 |
| F7 设计者的话 | 课程术语、抽象名词、没解释的专有名词；在讲课程结构而不是他的事 |
| F8 界面旁白 | 解释按钮怎么点、选项在哪里 |
| F9 句子难读 | 一句塞两件事、超过 35 字；或短到看不懂为什么 |
| F10 断言结果 | 预先写死了 AI 结果里一定会有的具体内容 |
| F11 Make 给答案 | 检查项或提示直接给出要写的话；或 Make 材料与前面相同 |
| F12 材料泄漏 | 发给 AI 的材料正文里有“练习”“虚构”等说明 |
| F13 不尊重 | 哄小孩、贬低、制造焦虑或夸口保证 |
| F14 说不出收获 | 结尾说不出下次在生活里怎么用 |
| F15 互动是装饰 | 操作不改变材料、请求、结果或理解；或只是换皮的选择题 |

## 7. 卡片和独立任务的判断标准

- 卡片 2 张：正面是一个短问题（≤40 字），背面独立可懂（≤120 字），考判断，
  不考名字，不写“见上文”。
- Make 的评分标准（rubric）2–4 条，语义判断：请求针对的是新材料和新用途；成品
  保留了材料里的关键事实；没有编造。允许不同的合理写法，不靠关键词。
