# 互动组件：一张表

这是**唯一**一张组件表。`activities.md` 和 `teaching-contract.md` 里原先各有一张，
都已废除并指回这里；3D 游戏以前哪张表都没有，现在也在这里。登记身份 36 个名字（`sort` 跨两批同名，算一个），
有独立引擎的 33 套玩法。

每一行都是从引擎和 schema 读出来的，不是从组件名推的。名字会骗人：`sort` 在两处
登记而通关条件不同；`point` 和 `inspect-image` 看上去都是"点图"，一个必须点对、一个
指哪块都行；`layout` 和 `edit` 怎么做都算过。曾经有人照着一行描述选组件，九个落点
错了三个。**按「怎么算过」选，不要按名字选。**

## 怎么读

- **要教的动作**：这一列不出现组件名。两行写着同一句，就是同一件事的两种实现。
- **能放哪儿**：四种位置，含义不同，见下表。
- **怎么算过**：引擎里 `passed` / `complete` 的真实判定。这一列才决定组件在教什么——
  「放错也能继续」和「必须全对」不是同一节课。
- **这节课必须真有**：配得上它的最低素材。配不齐就换一个组件，不要编。

| 位置 | 含义 |
| --- | --- |
| `课内活动` | 整节课的一个活动，`role` 决定放课文哪一段（见 `activities.md`）。 |
| `分步·v3` | PRIMM 第 3 版 `steps[]` 里的一步，一步一屏。**第一节课用的是这一种。** |
| `调查关·v2` | PRIMM 第 2 版 `investigate.game`，整个 Investigate 阶段只有一个。 |
| `只在 /play-lab` | **课里放不进去**：既不在 `LessonActivityKindSchema`，也不在 PRIMM 的两个 union 里，93 节课零引用。目录页自己写着「游戏分数不是学习成绩；不写课程进度，也不代表已经独立掌握」。 |

宿主（`primm`、`interaction-path`）不是玩法，是承载玩法的课型，单列在最后。

## 分类：把东西按一条标准分成几类

| 同上 | `sort` | 调查关·v2 | 同一引擎，同样必须全部放对 | `buckets` 2–8、`cards` 2–30，每张卡有 `bucketId` 和 `why` |
| 同上 | `sort` | 分步·v3 | **放错也算做完**：每张卡都有决定就过，对错只改语气 | `buckets` 2–4、`cards` 3–10、必有 `after`；phase 限 predict / investigate / modify |
| 同上（三类写死） | `stack` | 只在 /play-lab | 对错都计入；错的堆在同一通道堆到 4 就输；做完 24 条即胜 | 配不了：三类和 12 条说法写死在引擎旁 |
| 同上（三类写死） | `wire` | 只在 /play-lab | 每局 4 条**全部**接对才通电，三局 | 配不了：同上 |

| 对每条记录决定留下还是丢掉 | `collect` | 调查关·v2 | 每张卡的去留必须等于作者写的 `relevant` | `cards` 2–30，至少一张相关、一张不相关；每张的 `sourceId` 必须是 `sources` 里的真出处（练习材料不算出处，那种题用 `sort`） |
| 把实跑结果的每一项判成还在 / 变了 / 没有 | `check-result` | 调查关·v2 | 每项给出三者之一即可，**没有标准答案**，判完才显示作者写的说法 | `items` 2–8，每项有 `label`、`expected`、`why`；学习者手里得有看得懂的原材料，否则他没有尺子 |

## 选择与权衡

| 要教的动作 | 组件 | 能放哪儿 | 怎么算过 | 这节课必须真有 |
| --- | --- | --- | --- | --- |
| 在二到四个说法里点一个 | `choose` | 分步·v3 | 写了 `answerId` 时选错会弹出该选项的 `after`（没有就提示再选）并清空，**只有选对才完成**；没写时点哪个都过（预测题只记下） | `options` 2–4，id 不重复；若 Run 的 send 用 `"chosen"`，Predict 里这个 choose 每个选项都必须带 `requestId` |
| 同一组选项，在不同处境里选出此处最好的那个 | `weigh` | 课内活动 | 每个处境都选中它的 `bestOptionId` 才过；点错该处境仍留着 | ≥2 个选项、处境数 ≥ 选项数、**每个选项都要在某个处境里赢**；每个输家都要写出它在这一处的代价，赢家不许出现在代价表 |
| 预测两种做法会得到同一结果还是会分开 | `contrast` | 课内活动 | 每个例子最终都要预测对；猜错该例仍开着 | 两种做法、≥2 个例子，**全部例子里既要有结果相同的也要有不同的**——全同或全不同引擎直接拒收 |

## 和真模型打交道

| 要教的动作 | 组件 | 能放哪儿 | 怎么算过 | 这节课必须真有 |
| --- | --- | --- | --- | --- |
| 把准备好的材料贴上，把一条已写好或刚拼好的请求真正发出去 | `send` | 分步·v3 | 真跑出一次非空结果即可，**不看返回内容对不对** | phase 仅 run / modify，整课各恰好一次；`request` 是已知 id、`"chosen"`（前面 choose 每项带 requestId）或 `"built"`（同阶段前面有 build）；必有 `attachmentLabel` |
| 在刚跑出来的文字里点出包含给定用语的那一句 | `find` | 分步·v3 | 点中含任一 term 的句子；**这次结果里一句都没命中时，点「没提到」也过** | `terms` 1–6，`found` 和 `absent` 两种说法都要写；前面必须已有一次 send |
| 把若干次实跑得到的回答分别对回产生它的那条请求 | `match` | 分步·v3 | 每份回答都对回自己那条请求，全部配对正确才过 | `requestIds` 2–4 且都是已知请求、必有 `after`；phase 仅 investigate，且在第一次 send 之后 |

| 自己写一条请求发给模型，改成品，交外部评分 | `make` | 分步·v3 | 评分 `outcome === "pass"` 才过；整课通关也绑在这里 | 整课恰好一步 make 且是做段第一步；载荷 `make` 要有 `scenario`、`goal`、`promptPlaceholder`、`checklist` 1–12、`exerciseId`、至少一份 `materialIds` |

**分步版（v3）表达不了这五件事中的任何一件**——见文末「已知缺口」。

| --- | --- | --- | --- | --- |

| 在坏掉的产品上复现缺陷、换一帖、确认缺陷没了，再亲手走一遍不该被破坏的旧行为 | `ai-repair` | 课内活动 | 证据是 broken 上的真实轨迹且重放结果不同、缺陷检查通过、回归检查通过，三者同时成立 | 一个能跑的产品（模型只有 `booking` 和 `preference` 两种）、一个可复现的故障、若干候选改法、一条必须保住的旧功能 |

## 课内活动：怎么从课文认出形状

下面是形状的**例子，不是要匹配的词表**。课文说「名字对上就能领出来」，字面上没有
"够得着"三个字，但那是一条从名字到元素的路——照样是 `connect`。按字面找词，会把
几乎每节课都判成对不上。

- 够得着 / 伸到哪 / 走到哪 / 经过谁 → `connect`
- 这算不算 X / 它不是 A 也不是 B / 属于哪一层 → `sort`
- A 和 B 有什么不一样 / 看起来一样其实不一样 → `contrast`
- 什么时候该用这个、什么时候该用那个 / 值不值 / 代价是什么 → `weigh`
- 调大调小 / 多了会怎样 / 换个数 → `tune`
- 到哪儿就变了 / 临界 / 边界在哪 → `hunt`
- 有限的钱 / 时间 / 名额怎么分 → `dispatch`
- 先做这步再做那步 / 顺序错了会怎样 → `program`
- 怎么把要求说清楚 → `ai-brief`
- 它记得住多少 / 塞太多会怎样 → `ai-context`
- 它自己会干哪些活 / 该不该放行 → `ai-agent`
- 怎么知道它做得够不够好 → `ai-eval`
- 它做错了怎么救 → `ai-repair`

**决定配不配得上的是「这节课必须真有」那一列**，不是这份词例。那一列是引擎真的会
拒收的东西：配不上的时候，十有八九是这一列里的某一样这节课没有。

`hunt` 和 `ai-repair` 的 `model` 枚举是唯二写死在引擎里的东西。其余十一种，读者看到的
每个字都来自载荷——所以「这个玩法是给别的课设计的」不是成立的拒绝理由，只有缺料才是。

**两个方向都会坏**：硬凑一行，是为了配而配；按字面词找不到就判不配，是把规则用死。
两种坏法都要在 agent report 里说得出来。如果这个单元是动手型的，而你连着判了三节
"不配"，八成是你在按字面词匹配，回去重新问一遍「读者的手该做什么」。

**`sort` 尤其容易被漏掉**，因为术语课和对比课读起来"只是在讲清楚一件事"。判据很简单：
**这节课有没有在说"它不是什么"？** 有，就先想 `sort`。诱饵要写成读者真会犯的那个错，
并说清那一格为什么装不下它——写不出那句话，说明这条界线你自己也还没划清楚。

## 已知缺口（不是写课时能绕过的，是产品还没有的能力）

1. **分步版表达不了课内模拟产品。** 上面五个 `ai-*` 教的是「在一个课内模拟的产品上
   操作、观察、授权、出题或修补」，分步版的 13 种全是「摆弄材料」或「把请求发给真
   模型」，没有一种能承载。要在第 3 版的课里教这五件事，得先给第 3 版加这块能力。
2. **课内活动里还有六件事分步版也没有**：`connect` 的有向关系、`weigh` 的处境翻转、
   `tune` 的数值关系、`hunt` 的规则与实现不一致、`dispatch` 的预算通道、`program` 的
   指令路线。
3. **3D 全部进不了课。** 六套玩法的条目写死在引擎旁，没有按课配置的入口；九个登记 id
   在 93 节课里零引用。要在课里用 3D，先要有一份按课配置的载荷。
