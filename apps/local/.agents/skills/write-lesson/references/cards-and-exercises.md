# 卡片和独立练习 — V2

`SKILL.md` 说这个技能拥有「lesson prose, cards, and exercises」，但十五条不变量
全部只管课文。这份文件补上另外两样。

补它的理由不是对称好看。**课文读一遍就过去了，卡片是几个月里反复回来的那一部分**——
`packages/core/src/scheduling/fsrs.ts` 调度的是卡片，不是课文。房子有十五条规矩管
读一遍的东西，零条管反复读的东西，那是把力气花在了留存更短的那一半上。

## 硬合同：有卡片就必须有练习

`LessonCreationProposalSchema` 会**拒收**带卡片却没有练习的课，理由写在它的
refine 注释里：卡片是在课时**完成**时进入复习队列的，而课时靠答练习来完成。
没有练习的课永远完不成，它的卡片就永远不会被排期——写进磁盘，然后无声地不存在。

这是存储schema的最低条件，不是新课的写作选项。新课按下述卡片／练习合同编写；
历史修订与已有ID保持原样，不能借更新规范删掉旧练习。

## 卡片

**每节 2 到 3 张。** 一张只装一个知识点。装两个的那张，你答对一半也算错。

**正面是一个短问题，不超过 40 个字。**
正面是读者翻面之前那三秒里要读完的东西。它是提示，不是情景剧。

> 实测反例（2026-09-06）：不给正面定长度上限，模型写出的正面中位 68 字，
> 12 张里 11 张超过 40 字——每一张都是一小段场景描述。读者还没读到问号，
> 已经在猜答案了。加上 40 字上限之后，同一节课的正面变成 22 / 28 / 26 字，
> 而且仍然考理解。**情景属于练习，不属于卡片正面。**

**背面要能独立看懂。** 读者是在几天后、脱离课文的情况下看到它的。
所以不许出现「见上文」「如前所述」「这一节说的」「上面那个例子」。
`check-proposal-shape.mjs` 会拦一部分这类写法，但它拦不住语义上的依赖。
背面控制在 120 字以内。

**考理解，不考名字。**
「XX 叫什么」是查得到的东西，不值得占用读者几个月的复习额度。
值得占用的是那种判断：这两样东西什么时候用哪一个、这件事为什么不能那样做。

## 练习

每节保留一个主要的独立应用任务，既有 ID 和记录不删除。相对引导过程更换
输入、目标或条件，不把刚揭晓的正确项再抄一遍。引导通关不等于独立题通过。

按需要的动作选择现有管线真正支持的类型：
- `choice`：读者需要从明确方案中作判断。每个选项有自己的解释；默认不选中，
  提交前不透露正确项，改答与首答分开记录。必须贯通原生作者、修订、恢复、导入
  和判分；一个孤立 ChoiceBlock 或 schema 定义不等于已可写课。
- `short-answer`：真正需要产出一个短结果，而不是界面缺选择按钮。答案必须可由
  当前确定性规则可靠判定，不要求照抄一句已经给出的中文。
- `explain`：需要自己的解释或开放产物，提供明确 rubric，沿用真实的分级判分和
  用量说明；不能用关键词命中冒充语义理解。

V2 最后一轮可以练一次换条件应用，但它仍是引导练习的一部分。独立结构化
exercise 的反馈由原生练习区给出；不要在路径里直接写进 hasPassed，也不要从
“看过答案”直接显示“你现在会了”。适当的总结是“你刚练习了……”或展示实际作品。

存量 prose/V1 的 exact-answer 题保持旧修订；新修订可在保留 ID 的前提下升级为
真实 choice。这是数据/交付管线迁移，不是偷偷填 textarea。变更后验证旧答案记录
不会变成新修订的通关记录、当前语言的选项/反馈完整且正确 ID 不泄露在公开包中。

## 谁来产

和课文同一条流水线，但**不要走 `lesson-pipeline-runner.mjs`**。
那个 runner 按第一个 Markdown H1 把过程叙述和最终答案切开，这是为课文设计的；
卡片的产出是结构化数据，没有 H1 也不该有。硬要模型先写个标题再输出 JSON，
它会在「只输出 JSON」和「先输出标题」之间选前者——于是完全正确的 JSON 被判失败。
直接调模型，从 stdout 里取 JSON。
