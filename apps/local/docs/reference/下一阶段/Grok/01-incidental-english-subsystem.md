# 子系统一：附带英语习得（Incidental English）

> 宏观研究。说明「这门事应如何完成、为何如此」，供其它 AI 审阅。  
> 不含界面线框、存储 schema、接口清单。

**交付状态（2026-08-07–08）：阶段 A/B 核心已交付。** 旁注层默认关；UI 名 **外语模式**；
词来自词表检测 + 可选手写 overlay 的合成（`server/language/detect.ts`、
`server/language/layer.ts`）；预算随学习者熟悉度自适应；统一词汇复习在
`studies/.vocabulary/`。勿按本文当未开工 backlog。仍开放的研究点：用户可调密度
滑条、introducing 混排展示、双轨词库运营。日常用法见
`docs/reference/using-university-local-with-grok.md`。

---

## 1. 这是什么问题？

业主在用 UniversityLocal **学项目与技术**时，希望同时提升英语：

- 教程以中文为主进行时，**时不时**出现可理解的英文词或短语  
- 认识则巩固；不认识则能立刻看到解释，最好有发音  
- 同一词会在后续**再次出现**，而不是「点过一次就永别」  
- 出现的**频率可调**（英语较好则更密；初学者则更浅、更稀）  
- 整件事**可开关，默认关闭**  
- 学过的内容要进入**长期复习**，不能只靠当次阅读的感觉  

这不是「给 Markdown 加 tooltip」级别的功能点。  
它是一门挂在技术学习之上的**第二学科学习系统**：附带词汇习得 + 可控曝光 + 间隔复习。

---

## 2. 为什么值得做成子系统，而不是一个开关？

因为它同时包含至少五块能力，且彼此咬合：

| 能力块 | 回答的问题 |
| --- | --- |
| **词与短语的内容体系** | 学什么词？领域词还是日常词？谁来维护？ |
| **曝光策略** | 何时出现？多密？何时降权、换词？ |
| **即时理解支持** | 点击后看到什么？如何发音？如何不打断阅读？ |
| **长期记忆** | 如何复习？与项目知识复习是什么关系？ |
| **体验策略与设置** | 默认关、密度、级别、与主课完成条件的关系 |

任一块缺失，体验都会塌成：

- 只有高亮没有复习 → 感觉学了，实际不记；或  
- 只有词表没有语境 → 背单词 App，和「边看教程」脱节；或  
- 只有随机英文插入 → 主课阅读崩溃。

所以应作为**子系统**规划边界与原则，再分期长出来。

---

## 3. 成功时世界长什么样？

学习者打开「英文模式」之后：

1. 仍能顺利完成技术课的理解与练习（主课指标不下降）。  
2. 每周稳定遇到一组「正在学」的词，且能在复习日再次主动回忆。  
3. 密度调高/调低时，主观负荷可预期变化，而不是随机惊吓。  
4. 关闭模式后，主教材与主流程看起来与现在一致（无残留干扰）。  
5. 领域英语（如架构与工程常用词）与日常英语**都有进展**，而不是只刷到一边。

失败时世界长什么样（必须避免）：

1. 主课读不懂了，因为生词密度过高或句子被改得支离。  
2. 复习队列被词卡淹没，项目知识卡永远排不到。  
3. 为了「智能」不断改写正式讲义，教材失去稳定与可审计性。  
4. 默认开启或强关卡，使大学变成英语拼关游戏。

## 4. 子系统边界

### 4.1 负责

- 在**阅读/讲解体验**中提供可控的英语曝光  
- 提供即时释义与（本地可得的）发音支持  
- 把值得记住的词条送入**统一复习脊柱**  
- 根据「学习中 / 较熟 / 暂停」调节曝光优先级  
- 提供全局设置：开/关、密度、难度/词库偏好  

### 4.2 不负责

- 完整英语课程（语法体系、写作课、听说考试）  
- 取代技术教学或证据核对  
- 云计算翻译/云发音成为默认依赖（与本地优先哲学冲突）  
- 自研第二套遗忘曲线  
- 强制口语评分、游戏化连胜等与主目标无关的刺激系统  

### 4.3 与主系统的关系（概念接口）

```text
主教学流（课、证据、练习）
        │
        │  只读主内容 + 叠加「英语体验层」
        ▼
附带英语子系统 ──写入──► 统一复习脊柱（与知识卡共存）
        │
        └── 读取 ── 学习者词状态、设置、词库策略
```

关键点：**主内容仍是主内容**；英语是一层可移除的体验与练习。

## 5. 推荐完成路径（怎么做成，而不是做成啥按钮）

### 阶段观：先「旁注阅读」，再「词生命周期」，最后「规模化词库」

**阶段 A — 旁注阅读成立**

目标：证明「开着英文模式仍能学技术」。

- 默认关闭  
- 打开后，在既有中文讲解中出现**少量**可点英文  
- 点击得到短释义 + 本语境一句 + 发音（若环境允许）  
- 课后可选极短回顾，**可跳过**  
- 词进入统一复习，但不追求词库很大  

此阶段成功标准是**主课不塌**，不是「一天学 50 词」。

**阶段 B — 词生命周期成立**

目标：证明「懂了会少打扰，忘了会再来」。

- 学习中的词优先曝光  
- 已掌握的词降权  
- 复习失败的词回升  
- 每日词复习有上限，避免淹没项目知识  

这里的「逻辑」应服从统一间隔重复的思想，而不是另写一套计数器玄学。

**阶段 C — 双轨词库可运营**

目标：领域词与日常词同等优先可长期运转。

- 领域轨：来自项目与课程语境（高迁移到真实工作英语）  
- 日常轨：来自分级通用词/短语体系（提高一般阅读力）  
- 同一密度预算下两轨公平争用曝光名额  
- 内容治理：谁批准新词、如何处理多义与术语冲突  

没有阶段 C，系统只是玩具；没有 A/B，直接做 C 会变成内容垃圾场。

## 6. 为何推荐「旁注层 + 统一复习」，而不是其它常见做法？

### 6.1 做法对比

| 做法 | 优点 | 致命问题 | 结论 |
| --- | --- | --- | --- |
| A. 把讲义改写成中英混排教材 | 实现直觉简单 | 污染正式知识资产；关模式后仍脏；修订爆炸 | 否 |
| B. 独立英语 App，与大学并列 | 边界清晰 | 语境割裂；两套复习；违反「一个学习生活」 | 否 |
| C. 仅阅读高亮、不复习 | 轻 | 附带习得需要重复与提取练习；易「点过即忘」 | 不足 |
| D. 完型填空/强制关卡化主课 | 「强迫学会」感强 | 摧毁主课心流；与大学定位冲突 | 否 |
| E. **旁注阅读层 + 点击理解 + 统一 SRS** | 主课可关层还原；有语境；有长期记忆 | 需要词库与策略治理 | **是** |

### 6.2 外部实践为何支持 E？

研究与产品交叉时，反复出现同一成功配方（名称各异）：

1. **在有意义的文本里遇到词**（不是纯词表空战）  
2. **即时查阅**降低阅读摩擦  
3. **标记学习中 / 已知**  
4. **间隔复习**把「见过」变成「记得」  

LingQ、Readlang 等阅读优先型产品，以及大量「Learning with Texts」传统，都围绕这条链，而不是围绕「把主教材永久改成外语」。  

公开的词汇研究脉络也反复强调：

- **重复**对附带词汇习得很重要，但重复应在可理解语境中发生；  
- 词知有多层（意义、形式、用法等），只点中文意思不等于会用；  
- 文本中未知词比例过高时，理解崩溃，附带习得也失效。  

因此：

- 「同一词后续再出现」是刚需，不是锦上添花；  
- 「频率可调」是保护主课理解的安全阀；  
- 「可跳过的轻测」优于「关卡强迫」。

### 6.3 为何必须接统一复习脊柱？

UniversityLocal 已有明确工程与产品选择：成熟间隔重复、拒绝自研第二曲线、知识卡已走此路。  

若英语另起日历：

- 学习者要维护两套「今日该复习什么」；  
- 两套参数两套失败模式；  
- 与「本地一个大学」心智相反。  

故：英语词是**另一类复习卡片**，不是另一个产品。

### 6.4 领域词与日常词为何同等优先（业主约束下的解释）

更「功利」的默认往往是：先做领域英语（和主课同向，迁移快）。  

业主明确：**同等优先**。宏观上这说得通，因为：

- 领域词服务「读技术与文档」；  
- 日常词服务「一般英语肌肉」；  
- 两者在真实职业中都会用到，只练一边会偏科。  

子系统要做的不是二选一，而是：

> 在同一曝光预算下公平分配，并在复习队列里用标签区分，避免一种词饿死另一种。

### 6.5 发音与本地哲学

理想体验需要发音。但本产品哲学是本地优先、避免默默联网。  

宏观选择：

- 优先使用设备/系统可得的朗读能力与文本音标；  
- 联网音源若存在，只能是**显式可选**，不能成为默认主路径。  

这不是技术洁癖，而是防止「学个单词先变成云服务客户端」。

## 7. 「强迫学会」与「不毁主进程」如何和解？

业主希望有一定强迫力，又怕毁体验。宏观答案：

| 允许的强迫 | 不允许的强迫 |
| --- | --- |
| 视觉上提醒「这是学习中的词」 | 不点词不能翻页 |
| 复习日主动找上门（统一队列） | 不考英语不能完成技术课 |
| 可选的 30 秒级课后回顾 | 默认开启高强度 |
| 用户自己把密度调高 | 系统擅自提高难度「为你好」 |

**原则：** 强迫来自**时间上的再见**（间隔重复），而不是来自**空间上的拦路**（关卡）。

类比：健身教练可以预约你后天再来练（时间强迫）；不能在你上班路上锁电梯（空间强迫）。

## 8. 内容治理（子系统真正变重的地方）

审阅者应重视：长期成本在内容，不在「点击气泡」。

必须预先承认的治理问题：

1. **多义词**（commit、bank、light…）必须带语境，禁止裸词唯一正确答案幻觉。  
2. **术语轨 vs 日常轨** 冲突时，以当前课语境为准，并在释义中点破。  
3. **新词进入学习队列** 应有门槛（人工确认或可信白名单），避免自动抽取垃圾。  
4. **词库来源** 若使用公开分级词表，必须尊重许可证与署名；不能黑箱搬运。  
5. **与 AI 教学对话** 同步：模式开启时，口头讲解也可受控夹词，但同样受密度与「不自动落盘」约束。

## 9. 风险登记

| 风险 | 严重度 | 缓解（宏观） |
| --- | --- | --- |
| 主课理解下降 | 高 | 默关、密度上限、可跳过、阶段 A 以主课指标验收 |
| 复习队列被词卡淹没 | 高 | 每日词复习预算、与知识卡共存策略 |
| 内容噪声与错义 | 高 | 语境绑定、双轨标签、进入队列有门槛 |
| 做成平行英语产品 | 中 | 坚持旁注层 + 统一脊柱，不做独立 App 心智 |
| 本地发音质量不稳 | 中 | 音标兜底；联网音源非默认 |
| 范围膨胀到完整 ESL | 中 | 边界写死：不做语法大全与应试 |
