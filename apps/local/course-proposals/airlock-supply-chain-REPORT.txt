读代码时最反直觉的一点
----------------------
封条 university-local-airlock.json 故意放在 .git/ 里，而不是工作树。

直觉会说「元数据放仓库根目录最显眼、最好读」。但 seal.ts 注释写得很硬：airlock
的中心承诺是工作树与 promoted commit 字节一致；若把封条写进 tree，promote 刚
写完 git status 就会出现 untracked，inspectAirlock 会立刻把「刚创建的合法副本」
判成被改动过（blocked）。

也就是说：计量装置不能放进被称的货物里——封条是度量空气锁的尺子，不能成为
空气锁内容的一部分。这点已经写进第 2 单元「封条为什么放在 .git 里」一课。

次级反直觉（也进课了，供对照）
------------------------------
- materialize 用 fetch --depth=1 而不是 clone：避免 hardlink / --shared 共用对象，
  否则路径隔离了、对象库仍拴在上游。
- import-gate 只拒绝、不跳过：跟踪了密钥时「跳过继续」会制造绿色成功；
  必须整次 promote 失败，逼 owner 用 git rm --cached 修历史跟踪集。
- inspect 的 sealed 与 commitsAhead 正交：副本完好但落后上游仍可 sealed；
  新鲜度不是篡改。
