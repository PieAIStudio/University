读代码时最反直觉的一点（已写进课）
----------------------------------
`invalid_decision_schema` 是合法的 StructuredDecisionErrorCode，却故意不在
`RETRYABLE_STRUCTURED_DECISION_CODES` 白名单里。

直觉上「校验失败 → 再让模型试一次」很自然；TuringPact 的取舍相反：
- 缺提交 / 缺 JSON 对象 / JSON 碎了 → 结构还没成形，随机性值得再花一次模型调用；
- 对象已经成形但字段/语义不合法（如 shouldSpeak=true 却无 publicMessage、cooldown 越界）
  → 同约束下重试命中率低，却稳定 double spend，所以直接 fail closed。

配套的第二层反直觉：`repaired: true` 记的是「走过 repairPrompt 第二枪」，
不是本地 `extractJsonObject` 剥 fence 成功。本地修免费且不打标；模型修昂贵且必须可观测。

这两点分别落在课时：
- retry-whitelist（白名单里没有 schema 错）
- repaired-means-path（repaired 记的是路径不是补丁）
- repair-state-machine（mermaid：最关键的边是 D→E 拒绝重试）
