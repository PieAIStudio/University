# 这门课的出处

课文是我们自己写的。引用的是 MDN 和各家官方文档。**这就是它的全部来历。**

被参考的那门课在这个流程里的角色只有一个：目录。它告诉我们讲什么、按什么顺序讲，
以及——更值钱的——**哪些地方初学者会卡住**。目录不是原文，提纲不是素材。

所以下面这份清单里**不会出现 easy-vibe，一次都没有**。
`datawhalechina.github.io` 已经写进 `forbiddenHosts`，门禁会直接拒。

## 白名单是怎么扩的，以及故意没扩什么

为这门课新加了 8 个域名，每一个都单独验证过：
`docs.stripe.com`、`vercel.com`、`platform.claude.com`、`docs.anthropic.com`、
`docs.github.com`、`code.visualstudio.com`、`docs.npmjs.com`、
`designcouncil.org.uk`、`nngroup.com`。

**三个故意没加，理由比加进去的更值得记：**

- **`github.com` 裸域。**加了它，`github.com/datawhalechina/easy-vibe`
  就成了「权威出处」——那条不能破的规矩会从正门被绕开，而且门禁全绿。
  只加了 `docs.github.com`。
- **`platform.openai.com`。**它对非浏览器请求返回 403，
  `--verify-urls` 永远确认不了它。**一条验不了的出处比没有出处更糟。**
  大模型 API 那几节改引 Anthropic 的文档。
- **`langchain` / `expo` / `flutter` / `godot` / 微信开放平台等。**
  覆盖盘点里有一批选题因为出处建不起来而**永远做不了**，
  这些域名没有进来，那些选题也就结案了，不挂在「下一轮」上。

## 一件必须写下来的事：200 不等于这一页支持你的说法

`--verify-urls` 只证明链接活着。这门课里有三处，如果只看状态码就会写错：

1. **`nngroup.com/articles/jobs-to-be-done/` 是 404。**
   一个看起来完全合理的链接，差点就被引进「他雇你的产品去干什么活」那一节。
   **是 fetch 出来的，不是读出来的。**

2. **苹果的人机界面指南，WebFetch 只能拿到标题。**
   它是前端渲染的页面：状态码 200、域名权威、**正文一个字都读不到**。
   最后是**开真浏览器渲染出来读的**，才敢引它那句
   「理想情况下，人们只要用一下就能明白它是什么」。
   → **凡是引 `developer.apple.com`，都必须用能渲染的浏览器核对，不能用 WebFetch。**

3. **Design Council 那一页没有讲「双钻常见误用」。**
   原计划有一节讲四种走偏，查完之后**整节砍掉**——
   找不到权威出处的说法就不写，这是技能自己的规矩，不是形式主义。

另外两条引用做了逐句核对，因为它们承重最大：

- Stripe 的支付状态页**确实明说**了：不要在客户端做履约，
  因为顾客可能付完款、在履约开始前就离开了页面；要监听 `payment_intent.succeeded`。
- MDN 的输入校验页**原话**是：不能依赖前端校验来兜安全，
  攻击者可以绕过或完全跳过前端代码，所以必须在服务端处理前再校验一次。

## 逐字覆盖率

`check-verbatim.mjs` 拿全部 195 篇原文（约 95 万汉字）比对：

- 最长逐字段 **15–30 字**，上限 40
- 12 字滑窗覆盖率 **0.5%–3.6%**，上限 18%

顺带记一笔：这个门禁本身在这次纳入里被发现有个洞——
去代码的正则能跨行，源里一个落单的反引号就吞掉了 12.9 万字符，
导致它只拿五分之一的原文在比。修好之后视野从 21 万汉字回到 56 万。
详见提交 `6bb5708`，以及 `docs/reference/learnings/workflow-issues/` 下那条。
