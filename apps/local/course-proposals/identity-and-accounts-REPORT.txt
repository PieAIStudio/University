最反直觉的一点（已写入课程）
----------------------------
登录/升级过程中 Supabase 推来的 session=null **不能**当成登出。

authController 里 isTransientMissingSessionPhase 把 bootstrapping / submitting / reconciling
标成「允许暂时没有 session」；handleAuthStateChange 在这些相位收到 null 直接 return，
既不 clearAuthStoreState，也不 bootstrap。

若把每一次 null 都当退出，登录中间态会清掉 store 并拉起新匿名会话，随后到达的目标邮箱会话
会对不上 expectedEmail / expectedAnonymous，用户表现为「登录失败或串号」。

与之配套的另一面（logout-clear-and-rebootstrap）：稳态下的真登出也不是停在真空——
clear + runtime reset 之后会再 bootstrap 出匿名会话。产品目标态是「可玩的干净游客」，
不是 user 永久为 null。
