# 从网页换成手机 App，里面的聊天和按钮会不会变成另一套？

## 先看两份文件各自在说什么

你打开项目里的 `capacitor.config.ts`，里面写着应用名字叫 `Turing Pact`，还写着去哪个文件夹拿网页。它管的是在手机上怎么打开。

:::detail[`capacitor.config.ts` 是什么文件？]
它是一份配置文件，专门写给「把网页装进手机」的工具看：应用在系统里叫什么、屏幕上叫什么名字、去哪个文件夹拿整理好的网页。你玩游戏时不会点开它，这是做应用的人给打包工具留的说明书。Capacitor 是这种工具的名字。文件名带 `config` 就是「配置」：改这里，改的是应用名字、去哪拿网页，以及在手机上怎么打开。

**打个比方：** 像贴在门口的一张说明，写着这里叫什么、东西放在哪个柜子。
:::

你再打开同一个项目里的 `README.md`。它也在谈这个产品，但和刚才的配置回答的是另一个问题：一份说设备怎样打开，一份说项目眼下要往哪里走。先把这个差别记住，具体答案留到后面。

:::detail[什么叫「壳」？]
壳是包在外面的那一层，负责在设备上怎么打开。浏览器是一种壳：点开网址，网页在浏览器窗口里跑。手机屏幕上的图标也可以是一种壳：外面看着像普通 App。这种「怎么打开」就叫打开方式：输网址、点手机图标，还是开桌面窗口。壳去哪个文件夹拿网页，写在配置里。

**打个比方：** 壳就像电影院的大门和座位，管你从哪个入口进去。
:::

这两份文件回答的问题不一样，别把它们混成一件事。

:::detail[「发布门禁」是什么意思？]
发布门禁是 README 里划出的一道线：当前哪些东西算进「对外发布和验收」的清单。项目里能放很多文件和配置，但门禁只圈定眼下真正要过验收的那一批。有配置，不等于今天主推那条路。README 里写成 release Gate：release 是发布，Gate 是门禁——迈过这道门，才算进当前的发布清单。

**打个比方：** 像博物馆门口的「今日开放区域」牌子。抽屉里能有很多展厅的钥匙，但牌子只写今天对外开放哪几间。
:::

一边是给手机用的配置文件，一边写着「现在主推网页」。两份文件摆在一起，打开方式看着不太一样。

## 先猜一下

打开方式从浏览器换成手机壳，而壳依然去配置里写的网页文件夹拿内容——点开之后，里面的按钮、聊天和玩法会怎么变？

先写下你的判断，再往下看答案。

## 答案

大体仍是同一套。壳换掉的是打开方式，并不是另做了一套按钮、聊天和玩法。

## 产品内容和打开方式，一项一项怎么对？

手机壳配置里和「壳」直接相关的几行是这样的：

[[evidence:capacitor.config.ts:8-11]]

这几行看着可能有点陌生。不用背语法，先认准三个名字：`appId`、`appName`、`webDir`。

| 字段 | 它在答什么 | 你怎么记 |
| --- | --- | --- |
| `appId` | 系统里用的编号 | 类似 `com.pieai.turingpact`，平时看不见 |
| `appName` | 手机屏幕上看到的名字 | 这里写的是 `Turing Pact` |
| `webDir` | 壳去哪个文件夹拿网页 | 这里写 `dist`，是整理好的成品目录，不是日常改的文字文件 |

:::detail[壳去 `dist` 拿的网页，是从哪来的？]
写代码时先改项目里的文字文件，再让程序把它们整理成浏览器或壳能直接打开的成品——这一步常常叫打包。`dist` 是打包完成后生成的成品目录。壳去 `dist` 拿的是打好的网页成品，不是你正在改的那摊源码。

**打个比方：** 壳拿的是烤好的面包，不是后厨的菜谱。你现在只要先分清：壳读取的是成品目录。
:::

README 把现在主推哪条写清楚了：

跟上面的配置对照来看：

| | 产品内容 | 打开方式（壳） |
| --- | --- | --- |
| 是什么 | 能打开的那套网页（网页产物）：玩法、界面、聊天 | 负责打开的那一层：浏览器、Capacitor 手机壳、Electron 桌面壳 |
| 你在哪碰到 | 点开后真正玩到的判断、聊天、按钮 | 用哪种方式打开：网址、手机图标、桌面窗口 |
| 在项目里怎么露面 | 日常改的文字文件、整理后的网页目录 | `capacitor.config.ts` 等配置；README 也会点名壳 |
| 当前主推吗 | 网页形态是当前拿去测试的东西 | 手机壳、桌面壳还在，但不在当前发布门禁里 |

:::detail[README 里的 Electron 是什么？]
Electron 是另一类桌面壳：让整理好的网页跑在电脑桌面窗口里。README 提到它，是为了说明壳不只有手机这一种。你现在不用学怎么做安装包，认出「桌面也可以套一层壳」就够了。
:::

:::detail[为什么现在主推网页，项目里还要留手机壳配置？]
因为同一份产品内容，以后可能换一种打开方式。配置放在项目里，只说明「以后能用手机打开」，不说明「现在打开的已经是另一套内容」，更不等于今天就要去学怎么做手机安装包。README 写得很明确：壳可以留着，但眼下要测试的依然是网页。

**打个比方：** 像电影拷贝已经做好了，抽屉里放着「以后要不要换一家放映厅」的说明——说明在，不代表今天放的就成了另一部片子。
:::

**打个比方：** 产品内容像电影本身，壳像放映厅。换个放映厅，不会自动换掉电影；电影在不在，得看放映厅去哪个柜子取拷贝。

## 你现在该盯内容，还是该盯打开方式？

- **聊玩法、界面、好不好用**：盯产品内容——看跟浏览器里玩到的是不是同一套。
- **聊怎么装进手机或桌面**：再切到壳——读 `appName`、`webDir` 这些字段，看壳去哪拿整理好的网页。
- **看见壳配置和「现在主推网页」同时出现**：别把「项目里有手机配置」误当成「打开后就是另一套产品」。先分清你盯的是产品内容，还是打开方式。

## 再想想

网页、手机 App 和桌面窗口可以是不同的打开方式，里面的产品内容却不必做成三套。先分清打开的是不是同一份内容；至于眼下该走哪条路，看 [[lesson:product-sentence-and-gate|项目为什么先从浏览器这条路开始]]。
