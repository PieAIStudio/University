# 项目文件这么多，第一段时间该压在哪条路上？

图灵密约仓库根目录有一份 `README.md`。它写给看项目的人，主要交代两件事：产品是什么，以及现在让真实用户从哪个入口进来做商业验证。眼下选定的这条路，就叫主路径。

:::detail[什么叫「商业验证」？]
写在 README 里给看项目的人读。意思很简单：先拿个真实用户能用的版本，看产品能不能站住脚、值不值得继续投入。所以项目现在先主推这一个入口。

**打个比方：** 像先开一家店试菜单，而不是同一天装修三家分店。
:::

在这个仓库里，网页、手机、电脑桌面的文件都在。几条路看起来都能走，但你时间有限，没法一起走到底。

:::detail[「打开方式」指的是什么？]
就是用户怎么接触这个产品：用浏览器开网页、点手机屏幕图标、点电脑桌面窗口。内容可以是同一套，外面的壳却不同。这节课要问的是：好几条路看起来都能走时，你把第一笔时间压在哪一条。
:::

## 文件夹很长，你的时间很短

打开文件夹，网页、手机、桌面相关的文件都在。根目录那份 README 也在。两边看起来都能带路，但你头一阵时间只能压在一条路上。

:::detail[只看文件夹的话，你会看见什么？]
你会看见一长串文件名和配置。网页、手机、桌面的都能点开。它们并排摆在那，看起来哪一条都能先走。
:::

## 先猜一下

仓库里网页、手机、桌面的配置都在。你会把头一阵时间压在「先把游戏装进 iPhone / Android」上，还是别的地方？凭什么这么选？

先写下你的判断，再往下看答案。

## 答案

README 已经替项目选好了：当前主路径是公开网页。先跟着网页走。

## 先跟网页走，换来什么、又放下什么？

这几行英文是给人读的，不用背。停一下扫一眼就行：它同时交代了「游戏在玩什么」和「现在先验哪条路」。

[[evidence:README.md:3-8]]

文件夹只告诉你「有没有」；README 开头这几句才告诉你「先干什么」。能看到手机和桌面配置，只证明仓库里走过这条路，不证明你今天该先跟它。

:::detail[为什么 README 比文件夹列表更适合当路标？]
文件夹只列出仓库里有什么，不标现在主推什么。README 开头那几句是写给人看的优先级：产品是什么、现在主验哪种打开方式。时间有限时，先读懂这几句，比挨个点开配置文件划算得多。文件列表回答「有没有」；README 才回答「先干什么」。
:::

前两句交代产品：双语社交推理，在聊天室里分清人还是 AI。后几句交代节奏：现在要验的是公开网页试点，英文写成 public Web pilot。

:::detail[public Web pilot 这几个词怎么拆？]
**public**：公开对外，不只是公司内部试。**Web**：网页/浏览器这条线。**pilot**：试点——先小范围验证，再决定要不要继续加码。连起来看：当前拿去见真实用户、看产品能不能站住的，是「公开能访问的网页版」，不是「先上架手机商店」。以后你在 README 里看到「public … pilot」，中间那个词就是打开方式；这里写的是 **Web**。
:::

同一段还提到了两套把网页装进手机外壳、装进电脑窗口的工具：Capacitor 和 Electron。你在仓库里能看到它们的配置，但它们不在今天验收放行的名单里。这个名单叫发布门禁，英文写成 release Gate。

:::detail[发布门禁和文件夹清单差在哪？]
文件夹清单是你打开能看到的文件：各种壳的配置可以都在。发布门禁则是今天验收放行的那批要求：README 写得很清楚，Capacitor 和 Electron 壳**不在**当前门禁里。两边对着看，最容易踩的坑是想当然觉得「文件都在，那今天都要学」——不对。存在只回答「有没有」；门禁才回答「现在验哪条」。

你在文件夹里翻到手机壳配置，只证明仓库里走过这条路；既不代表今天发布要验它，也不代表你该把第一笔时间压在「装进 iPhone / Android」上。跟着门禁走，才是在跟眼下真正要验证的东西走。

**打个比方：** 仓库就像抽屉里放着整栋楼所有展厅的钥匙；门禁则是门口挂的牌子——「今日开放」。钥匙在，不等于今天开放。
:::

**收益：** 你不会在「还没进门禁的壳」上迷路，时间能花在眼下真正要验的网页路径上。

**代价：** 仓库里那些壳文件都在，也能学，但不是今天的主线。忽视 README 的人会付另一种代价：把精力耗在眼下并不主推的打开方式上。

## 什么时候才该把精力拧到手机或桌面上去？

只有当项目把手机壳或桌面壳写成当前商业验证路径时，顺序才会转过来：到那时 Capacitor / Electron 才会进门禁，网页可能变成次要的，或者两条一起跑。

转向的信号依然来自 README（或同等产品说明）里那句「current … path / Gate」，而不是看「仓库里有没有某个配置文件」。有配置 ≠ 当前主路径。

:::detail[什么信号还不够当「反过来」？]
光看到 `capacitor.config.ts` 还在、光看到手机文件夹名字、或者光听到「以后也要上 App Store」——这些都还不够。只有等说明文字把主路径和门禁切过来了，你再把主线拧过去。否则你只是在拿猜测代替项目定好的优先级。反过来指的是「路径声明变了」，不是「文件还在」。
:::

## 再想想

你已经见过：同一款产品可以有网页、手机、桌面好几种打开方式。更关键的是先读懂产品说明和当前主路径，再决定先跟哪一条。后面讲构建和产物目录时，也依然先服务网页这条主路径——见 [[lesson:from-icon-to-files-journey|用户看到的 App，和开发者改的文件怎么连起来？]]。
