# 会使用 App 和会开发 App，差在哪儿？

## 先把“使用 App”和“开发 App”分开

你会点开图灵密约的图标，看见屏幕上的按钮，滑动、输入、发消息。这件事叫**使用 App**。App 是 Application 的缩写，中文常说「应用程序」。

另一件事发生在开发者的电脑上：他们打开项目文件夹，读和改里面的文字文件。

:::detail[什么叫「项目文件夹」？]
你手机上那个图标，是别人做完、打包好、送到你手上的成品。在做它的人的电脑上，它不长这样：只是一个普通文件夹，里面装的是一堆写满文字的文件。做的人就在这个文件夹里改字、加文件，所以叫它项目文件夹。

**打个比方：** 它跟你放照片的那个文件夹没有两样，只是里面装的不是照片，是做这个 App 用的文字文件。
:::

改完之后，还要让工具把这些文件变成可以运行的程序。

:::detail[「变成能运行的程序」是什么意思？]
你点开已经做好的 App，设备里跑的是一份已经整理好的成品。做的人手里往往还是一堆文字文件——别人的手机看不懂这些文件。中间要有一步：用电脑上的程序，把这堆文字文件整理成手机或浏览器能打开的成品。那一步完成之后，才谈得上「能运行」。

**打个比方：** 像一堆还没装订的书稿，要先印成一本你能翻的书，别人才能读。你点图标，点到的是印好的那本，不是桌上那堆稿纸。
:::

:::figure[真实的项目文件夹]{#turing-pact-project-folder}
电脑上打开 TuringPact 文件夹；README.md、package.json、src、index.html 与其他普通文件和文件夹并列出现。
:::

图里同一层里，`README.md`、`package.json`、`index.html` 是文件，`src` 是文件夹。

:::detail[「文件」和「文件夹」差在哪里？]
文件是电脑上的一份独立材料，有自己的名字；点开以后，你看到的是这一份里写了什么。文件夹是一个格子，用来再往里放文件，或者再套一层文件夹。

图里这几个名字可以这样认：`README.md`、`package.json`、`index.html` 的名字里都有一个点，点后面还有一小段尾巴，它们是文件；`src` 没有这种尾巴，它是文件夹。现在不必打开每一份去看里面写了什么。只要记住：做的人改的是文件里的字，文件夹负责把这些文件收在一起。

**打个比方：** 文件像一张写了字的纸；文件夹像装纸的信封。信封可以和纸放在同一张桌上，但你不会把信封也叫做一张纸。
:::

:::detail[`README.md` 是什么？]
很多项目会在最外层放一个叫 `README.md` 的文件——名字就是「先读我」。它只是一份用文字写的说明：这东西叫什么、是干什么的、从哪下手。你不会在手机主屏幕上点到它；它是做的人写给后来接手的人看的说明。

**打个比方：** 像纸箱侧面那张产品介绍，不是箱子里那台已经能用的机器。
:::

这几行是英文说明书，第一次看会觉得密。你不用背单词。先读出两件事：第 1 行的中文名是「图灵密约」；下面几行说，它本质上是一种双语社交推理游戏——你在聊天室里判断谁是人、谁是 AI。

:::detail[为什么现在还要看这几行英文？]
在 AI 也能帮你改这些文字文件的时代，你仍然要逐渐读懂文件在说什么。读懂了，你才能把目标讲清楚，也才能判断别人（或 AI）的解释对不对。这几行是做的人写在最外层的产品说明。
:::

## 先猜一下

有人改了项目文件夹里 `README.md` 的字，你只是重新点开手机或电脑上的图灵密约图标。屏幕上某个按钮上的字，会不会变成 `README.md` 里新写的那些字？为什么？

先写下你的判断，再往下看答案。

## 答案

不会。你点图标打开的是已经做好的界面，而 `README.md` 是写给做的人看的说明；改这份说明，不会让屏幕上的按钮字跟着变。

## 把“会使用”和“会开发”逐项放在一起看

把「会使用」和「会开发」并排放在一起，差别会更清楚。会使用的人碰到的是图标、按钮和屏幕；会开发的人碰到的是文件、文件夹、说明文字，以及给电脑执行的文字。

:::detail[什么叫「代码」？]
代码是项目文件夹里写给电脑执行的文字。人写出这些文字，电脑上的工具读它们，再变成你能看见、能点的按钮和屏幕。不是每一份文字文件都是代码：`README.md` 就是写给人看的说明。

**打个比方：** 代码像一份机器会照着做的步骤清单；说明文件像贴在文件夹封面的便签，人读得懂，机器不会拿它当步骤。
:::

| | 会使用 App | 会开发 App |
| --- | --- | --- |
| 你会接触到哪些内容 | 图标、按钮、屏幕 | 文件、文件夹、说明文字、代码 |
| 你在什么地方操作 | 装好之后的界面里 | 项目文件夹里 |
| 做到什么才算完成 | 功能用顺了 | 改对了文件，再让程序跑起来，并能说清为什么是这样 |
| 在图灵密约里是什么样 | 进聊天室、判断谁是 AI | 打开 `README.md`，看见产品名和玩法一句 |

:::detail[「跑得起来」是什么意思？]
改完文件不等于事情做完。还得让电脑上的程序把改过的文件整理成能打开的样子，并且真的打开看一眼：按钮还在不在、字对不对。这一步通过了，才叫跑得起来。只改字、却不去打开看，不算会开发。
:::

会使用的人可以一辈子不打开 `README.md`。会开发的人却往往从这里起步：先确认「我们在做什么」，再去改那些真的控制屏幕的文件。

:::detail[为什么会使用的人可以一辈子不打开它？]
因为说明文件是给做的人看的。你当用户时，拿到的是装好的 App：点图标、看界面就够了。产品叫什么、玩法是什么，界面自己会告诉你——不必翻那份写给后来接手的人看的说明。
:::

## 只想使用 App，和要修改 App，分别该看什么？

- 只想使用、体验玩法、判断好不好用时，看界面和操作结果。
- 要改文字、找按钮、解释为什么会这样时，打开项目文件夹，对着文件和代码工作。
- 改说明文件，只改给接手人的字；要改屏幕，还得改负责界面的文件并重新跑起来。

## 一句话

**会使用 App 是在已经做好的界面里操作；会开发 App 是在项目文件夹里找到对的文件、改它，并确认改完还能跑。**
