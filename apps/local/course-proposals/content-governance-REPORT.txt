Most counter-intuitive finding (already in the course)
-----------------------------------------------------
The status value "stale" is NOT only "source evidence went bad".
openCourseForEdit deliberately moves a still-fresh active course to stale so
human revision shares the same reactivation door as freshness failure
(reactivateCourse + full audit).

A close second: status updates are idempotent no-ops when the requested status
equals the current one. That was not a convenience — partial reactivation used
to die on illegal transition active -> active and leave the shelf half-activated
with no command able to finish (see comments on updateCourseStatus). Process
re-entrancy matters as much as the pretty state diagram.
