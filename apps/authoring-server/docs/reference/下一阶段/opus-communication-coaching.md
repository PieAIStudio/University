# 沟通能力研究

你问了三件事：那个教「跟 AI 沟通」的技能还在不在系统里、怎么用、能不能跟教程结合；
以及要不要为沟通增加课程。本文逐条回答，并给出你选定方向（点评我真实写下的东西）
的具体设计。

## 一、那个技能在，叫 comm-coach，位置在这里

**它确实装着，而且是你记忆中的那个。**

- 文件：`.agents/skills/comm-coach/`
- 它是一个符号链接，指向 PGS 的共享技能库
  （`ProjectGovernanceSystem/agent-assets/skills/pie-skills/comm-coach`），
  所以它是**集中管理**的，不是本项目私有的。
- 内容：一个 `SKILL.md` 加一份 `references/methods.md`。

它定义了三种模式：

| 模式 | 什么时候用 | 做什么 |
| --- | --- | --- |
| 表达门诊 | 有一段现成文字要评 | 只评这一段 |
| 角色扮演 | 要练一场对话 | AI 扮演对方，短回合 |
| 复述教学 | 事实已经确认，要改进复述 | 评清晰度、结构、表达缺口 |

反馈流程是固定的六步：目标和听众 → 你先写 → 指出一个具体优点 → 只给 1–2 条最高
杠杆的改进 → 演示或下一句 → 重写并对比。

它明确排除的东西也很重要：不做通用润色代笔、不做心理咨询/法律/危机、
**不扫描整段对话除非你要求**、**不自动写盘**。

## 二、它和教程的接线已经写好了，只是从来没被触发

`teach-from-study` 技能的第 35 行写着（原文英文，大意）：

> 教学负责事实准确性。当用户要求排练或表达反馈时，先对照证据核实，然后调用
> `comm-coach`；不要默认两个都跑。

所以「跟教程结合」这件事在规则层面**已经做了**，而且做得很克制：教学不会顺手变成
点评，点评也不会篡改事实。

**那你为什么感觉不到它？** 因为它满足三个「没有」：

1. **没有入口。** Web 界面里没有任何按钮通向它。它只能在 AI 对话里被自然语言唤起。
2. **没有提醒。** `teach-from-study` 的规则是「当用户要求时」才调用——如果你不知道
   可以要求，就永远不会要求。
3. **没有记录。** 它自己的规则写着「不自动写盘」。所以每次点评都是一次性的，
   不累积、不复盘、没有进步曲线。

打个比方：这就像你家里有一台跑步机，放在储藏室最里面，没有插电，而且用完不记录
里程。它确实在，但它等于不存在。

**它的「不自动写盘」是对的，别改它。** 一个会自动把你写的东西存进知识库的教练，
会让你在写的时候开始自我审查。它把保存交给你显式发起——而项目里已经有这条路了：
`knowledge-node` 技能 + `capture` 工作流。comm-coach 的规则里也写了，遇到「记一下」
要指向**当前项目已有的保存路径**，不硬绑定兄弟技能。这个设计是干净的。

## 三、为什么我不建议做「沟通课程」

你问「这块是不是应该增加课程」。我的答案是**现阶段不做**，两个理由。

### 理由一：课程 schema 会拒绝它，而且拒绝得有道理

这个系统里每一节课、每一张卡、每一道练习都**必须**至少挂一条证据
（`src/domain/schemas.ts:239`、`:256`、`:284`），证据必须指向某个真实仓库某个提交
的某个文件。这是整个系统最值钱的一条规则——`current-work.md` 里记着零基础课程时
的原话：一节讲「什么是变量」的课因此**无法存在**，因为它没有东西可引用；当时的
选择是宁可去 TuringPact 里找三行的真文件来教，也不给这一层开证据豁免。

「怎么跟 AI 沟通得更清楚」同样没有源码可引。**除非**你做了第三个方向——一旦
UniversityLocal 自己成为 study，`.agents/skills/*/SKILL.md`、`docs/policy/`、
`AGENTS.md`、`docs/reference/execution/current-work.md` 就都变成合法证据了。
（详见 [自学本项目](opus-self-study-recursion.md)。）

所以「课程」这条路不是被永久堵死，是**要先修路**。

### 理由二：更根本的——沟通不是知识，是技能

就算证据问题解决了，我仍然不建议先做课程。

打个比方：游泳的知识可以写成课，「换气要在划水到腰侧时」这句话你三分钟就背下来了，
而且能通过任何一次测验。但你还是不会游泳。**知识和技能之间隔着一层，只有反馈能
穿过去。**

沟通就是这样的东西。一节讲「提需求要说清楚约束」的课，你读完会点头，会通过卡片
测验，然后下次跟 AI 提需求时照旧说「帮我优化一下这个」。真正让你改变的是有人看着
你写的那句「帮我优化一下这个」，告诉你它为什么让对方猜。

**你选的方向正好绕开了这一层。** 点评真实写下的东西，天然是反馈而不是知识。

## 四、你选的方向：素材已经在你的数据库里了

这是本次调研最让我意外的一个发现。

**你每做一次练习写下的作答，系统已经原样存下来了。**

- `exercise_attempt` 表有 `response_json` 字段
  （`server/learning/sqlite-learning-store.ts:638`）。
- 写入点在 `server/http-server.ts:1208`：`response: { answer: body.answer, met }`。
  短答题存你的答案；**explain 题存你写的整段解释，外加你自评勾了哪几条 rubric**。
- 卡片复习的作答也存着：`retrieval_attempt` 表有 `answer` 字段，还带
  `startedAt` / `revealedAt` / `durationMs` / `usedHint`
  （`server/learning/types.ts:208-233`）。

也就是说：**这个系统一直在忠实地记录你写下的每一句话，但从来没有任何一条路把它们
读出来过。**

`LearningStore` 接口（`server/learning/types.ts:257-288`）证实了这一点。关于练习
作答，它只有两个方法：`countExerciseAttempts`（数了几次）和
`hasCorrectExerciseAttempt`（对了没有）。**没有任何方法能拿回你写了什么。**
retrieval attempt 稍好，有 `getRetrievalAttempt(attemptId)`，但需要你先知道 ID。

打个比方：你写的每一封信都被完好地锁进了保险柜，但保险柜从出厂那天起就没配钥匙。

## 五、设计：三步接通

### 第一步：配一把钥匙（最小改动）

在 `LearningStore` 加一个只读方法，比如
`listRecentWrittenAttempts(limit, options)`，返回最近 N 条**带文字作答**的记录：
练习作答（含 explain 全文）和卡片作答。只读、不改任何现有行为、不碰 append-only
日志。

配套一个 CLI 出口，走现有的 `learner` 动词组（现在有
`learner backup` / `reset` / `restore`）：

```bash
pnpm university learner attempts --study turing-pact
```

### 第二步：把它交给 comm-coach

有了输出，你在 AI 主机里说「点评一下我最近写的解释」，主机就能：

1. 读回你最近几条 explain 作答；
2. 按 `teach-from-study` 的规则**先核实事实**（这一步不能省——如果你的解释里有
   知识错误，那是教学问题，不是表达问题，混在一起点评会误导你）；
3. 再调用 comm-coach 做表达点评；
4. 如果出了值得保留的洞察，问你要不要用 `knowledge-node` 存下来。

**这一步不需要写任何新代码**，因为技能规则已经写好了（第二节）。缺的只有第一步的
那把钥匙。

### 第三步：给它一个入口

在 Web 界面里，explain 练习自评完成之后，加一个轻量按钮——「让 AI 点评我这段表达」。
它不自己做点评（Web 端没有模型，也不该有），它做的是**把这段文字和上下文准备好，
复制到剪贴板**，你粘到 AI 主机里。

这符合项目一条明确的规则：AI 主机负责研究和教学，不要为了模仿主机而在产品运行时
加模型调用。按钮只是把「你刚写完的这段」和「让我点评」两件事在时间上接上——而这
正是第二节里那三个「没有」中最要命的一个（没有提醒）的最小修复。

## 六、你那个「跟 AI 沟通和跟人沟通很像」的判断是对的，而且比你说的更具体

你说跟 AI 沟通的过程「其实跟人沟通很像」。这不是类比，它们共享同一个结构，
而且失败的方式也一样：

| 沟通的组成部分 | 跟 AI 说 | 跟人说 |
| --- | --- | --- |
| 目标 | 我要什么产物 | 我要对方做什么决定 |
| 约束 | 不能动哪些东西、必须满足什么 | 预算、时间、不可谈判的底线 |
| 上下文 | 相关文件、当前状态 | 背景、前情、对方需要知道什么 |
| 成功标准 | 怎么算做对了 | 怎么算这事了了 |
| 反例 | 我**不**要什么 | 我担心你误解成什么 |

最常见的失败也是同一个：**把「目标」说了，把「约束」和「成功标准」留在自己脑子里，
然后觉得对方没领会。**

`current-work.md` 里正好有一条你自己项目的实证。零基础课程那一节写着：让 Grok
产出可用内容的不是模型，而是简报——每份简报点名了确切的文件、行数、以及每个文件
能教什么。翻译成沟通语言就是：**上下文 + 约束 + 成功标准写清楚了，产出就可用。**

这条经验有日期、有上下文、可引用，比任何「提示词十大技巧」都硬。如果将来真要做
沟通课程，这就是第一节课的证据。

## 七、明确不做的事

- **不自动扫描你的对话历史。** comm-coach 自己的规则就禁止这个，而且理由充分：
  一个会背着你分析你所有聊天记录的教练，会让你在打字时开始表演。
- **不做固定评分卡。** comm-coach 的反模式清单里点名了「八个固定维度」和
  「60%→90%」这类假量化。沟通质量没有绝对刻度，只有「针对这个目标和这个听众，
  这次比上次好在哪」。
- **不做代笔。** 点评的目的是让你下次自己写得更好，不是替你写。
- **不进「今日学习」的任务数。** 同 [英文模式](opus-english-mode.md) 第十节的理由：
  一旦变成待办，它就会挤占主线。

## 八、风险

| 风险 | 严重度 | 缓解 |
| --- | --- | --- |
| 读取历史作答的接口被误用成「导出全部学习记录」 | 中 | 只读、限条数、只返回有文字作答的记录 |
| 事实错误被当成表达问题点评 | 中 | 强制先核实证据再点评（技能规则已有，需在出口处再声明一次） |
| 点评变成打分，制造焦虑 | 中 | 沿用 comm-coach 的反模式清单，不做维度评分 |
| 个人作答文本离开本机 | 中 | 复制到剪贴板由你手动粘贴，产品自身不外发 |

## 九、待决问题

1. **点评的粒度：单条作答，还是一次会话的全部作答？** comm-coach 明确说「一次
   只改进一个样本」。倾向：默认单条，允许你显式指定多条。
2. **要不要把 AI 主机对话里你写的提示词也纳入素材？** 那是价值最高的素材，但系统
   不存它、也不该自动存。可能的路：你觉得某条提示词值得复盘时，主动用 `capture`
   存下来。需要确认这条路走不走得通。
3. **explain 练习的 rubric 自评，本身就是一次表达练习。** 要不要在自评之后直接给
   出「你勾了 3 条，但你写的第二段其实没覆盖到第 2 条」这类反馈？这需要模型参与，
   属于主机的活，Web 端只能准备素材。
4. **将来真要做沟通课程时，证据从哪来？** 依赖第三个方向先落地。
