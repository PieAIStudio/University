## 跨子系统的共同原则（比任何单点功能都重要）

### 1. 主课主权

技术（或证据学习）永远是主进程。英语、沟通、甚至「学自己」都不得把主进程改成附属品。

**类比：** 高速公路上可以有收音机学英语；不能把每三米插一个关卡考单词。

### 2. 一条记忆脊柱

项目已经选定成熟的间隔重复思路（FSRS 族），并拒绝第二套自研曲线。  
凡是「要长期记住」的——项目知识、英语词、沟通原则——都应挂在**同一条复习脊柱**上，用标签/领域区分，而不是三个 App 三套日历。

### 3. 工厂与书架分离

被学习的源（工厂图纸）与学习产物（课本、笔记、成绩册）必须概念分离。  
学外部项目时如此；学本系统自己时**尤其**如此。

### 4. 旁注层，而非改写真理

正式教材是可审计的知识资产。副能力（英语叠加、表达点评）优先做成**可开关的体验层/练习层**，而不是不断改写主教材正文。

### 5. 默认保守、显式开启

英语模式默认关。沟通教练按需触发，不全会话偷听打分。学自己需要显式登记为元学习对象。  
个人本地工具的默认值应偏向：**安静、可预期、不突然变难**。

### 6. 先子系统边界，后功能清单

每个方向都先回答：

1. 它解决什么学习问题？  
2. 它不解决什么？  
3. 输入/输出/与主系统的接口是什么？  
4. 成功长什么样？失败长什么样？  
5. 有哪些外部成熟实践支持这样切？  

然后再谈界面按钮与存储细节。

## 总优先级（战略顺序，非排期表）

```text
P1  元学习子系统
    理由：解锁 dogfood；边界问题已暴露；不引入新的学习科学产品形态

P2  协作表达子系统
    理由：技能已存在；缺口主要是「体系化与可复习」，不是从零发明

P3  附带英语子系统
    理由：最像「新学科产品」；误伤主课风险最高；需更完整的内容与词表策略
```

审阅者可挑战此顺序，但挑战时请给出**风险与收益**，不要只谈实现难度。

## 给审阅 AI 的阅读建议

1. 先读本文原则与优先级。  
2. 按 P1→P2→P3 读三份专题。  
3. 每份专题用同一审阅清单：  
   - 问题定义是否成立？  
   - 边界是否够锋利？  
   - 与主系统耦合是否过重或过轻？  
   - 证据是否支撑结论，还是只有口号？  
   - 有无更简单的子系统切法？  
4. **不要**在本轮要求补齐表结构、API、类图；那是下一阶段规格的事。
