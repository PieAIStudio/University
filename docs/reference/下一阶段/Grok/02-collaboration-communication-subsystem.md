# 子系统二：协作表达（主：对 AI；辅：迁移到人）

> 宏观研究。说明「这门事应如何完成、为何如此」，供其它 AI 审阅。  
> 不含实现规格。

---

## 1. 这是什么问题？

业主正确指出：大学不能只教代码与架构，还要教**怎么把事情说清楚**。

这里的「说清楚」有两条相关但不等同的能力：

| 能力 | 场景 | 典型失败 |
| --- | --- | --- |
| **对 AI 协作表达** | 提需求、给约束、要输出形状、迭代修改 | 含糊动词、缺上下文、缺非目标、一次改十个变量 |
| **对人协作表达** | 汇报、对齐、反馈、请求支持 | 背景先行、无结论、不可执行、情绪与事实缠在一起 |

业主决策：

- **主练对 AI**  
- 对人：不建完整第二主线，只在恰当处说明**迁移启发**（「同一结构换成对人时…」）  
- 练过的原则与句式要进入**统一间隔重复**，不能练完就扔  

因此本子系统的产品定位是：

> **AI 协作表达的训练与复习体系**，并带一条很细的「迁移到人」注释带。  
> 不是通用情商课，不是心理咨询，不是全自动沟通评分平台。

---

## 2. 为什么是子系统，而不是「有个 skill 就够了」？

仓库里已经有沟通教练技能（即时、单样本、可角色扮演、可点评复述）。  
这解决了「此刻帮我改这一段」——像**教练在场**。

它还没解决：

| 缺口 | 说明 |
| --- | --- |
| **可发现性** | 学习者不知道日常何时该唤教练 |
| **节奏** | 与正式课程、复习日如何交织 |
| **累积** | 原则如何变成可复习记忆，而非聊天烟花 |
| **课程化** | 从零到稳定习惯的学习顺序 |
| **与事实教学的分工** | 何时先对证据，何时才练表达 |

所以：现有技能是子系统的**执行器之一**；子系统还包含课程叙事、复习内容、触发礼仪与边界伦理。

类比：

- 技能 = 健身房里的私教（你来了才教这一组）  
- 子系统 = 训练计划 + 动作库 + 打卡复习 + 与「主项目训练」的排期关系  

---

## 3. 成功时世界长什么样？

1. 学习者能稳定写出**可执行的 AI 委托**：目标、约束、证据、非目标、输出形状清楚。  
2. 在学完技术概念后，能做简短复述；表达问题由教练处理，事实问题由教学/证据处理，**不互相冒充**。  
3. 关键原则在日后复习中再次出现，形成习惯，而不是「那次聊天好像说过」。  
4. 偶尔看到「对人也可以这样说」的迁移句，扩展迁移，但不感觉被强行上了情商课。  
5. 关闭或不用教练时，主学习流完全正常。

失败形态：

1. 全会话被监视打分，学习者不敢自然提问。  
2. 沟通教练擅自改技术事实， halu 成「说得漂亮的错」。  
3. 假精确进步（「今日沟通力 72→89」）污染信任。  
4. 与人对话主线膨胀，挤占 AI 协作主目标。  
5. 又一套独立复习系统。

---

## 4. 子系统边界

### 4.1 负责

- 定义「对 AI 说清楚」的能力目标与练习循环  
- 规定与事实教学的先后秩序  
- 把沟通教练的使用嵌入学习节奏（发现性 + 礼仪）  
- 沉淀可复习的原则卡与正反例  
- 用短注释完成「向人际沟通迁移」的启发  

### 4.2 不负责

- 心理治疗、亲密关系、危机干预  
- 真实职场 HR 结论或法律建议  
- 无人值守的全历史沟通审计  
- 固定多维人格/沟通雷达作为真理  
- 替代项目证据学习  

### 4.3 概念结构

```text
┌─────────────────────────────────────────┐
│ 协作表达子系统                            │
│  ┌─────────────┐  ┌──────────────────┐  │
│  │ 即时教练层   │  │ 课程与原则层      │  │
│  │ （单样本练习）│  │ （顺序、例子、卡）│  │
│  └──────┬──────┘  └────────┬─────────┘  │
│         │                  │            │
│         └────────┬─────────┘            │
│                  ▼                      │
│         统一复习脊柱（原则/句式卡）        │
└─────────────────────────────────────────┘
          ▲ 事实已对齐之后才进入表达层
          │
   主教学 / 证据学习
```

## 5. 推荐完成路径（宏观阶段）

### 阶段 A — 让教练「被用起来」

目标：发现性与礼仪。

- 在学习指南中讲清：何时唤沟通教练、怎么描述目标与受众  
- 在技术课的「复述」环节：先核对事实，再**可选**进入表达打磨  
- 明确反模式：别让教练默认代写一切；学习者先产出一版  

此阶段几乎不增加新学科内容，却能立刻提高现有资产利用率。

### 阶段 B — 可复习的原则层

目标：从「聊过」到「记得」。

- 将少量高杠杆原则写成可回忆卡片，进入统一复习  
  例：先给目标再给背景；声明非目标；一次只改一个变量；输出要可验收  
- 正反例成对出现（糊 prompt vs 清楚 prompt）  
- 业主要求：**要进间隔重复**  

原则：卡片测的是**可迁移结构**，不是背诵某次聊天原文。

### 阶段 C — 薄课程（AI 协作主线）

目标：从零到习惯的路径。

建议叙事顺序（宏观大纲，不是课表 UI）：

1. 什么是「可执行委托」  
2. 目标 / 非目标 / 约束  
3. 证据与猜测分开  
4. 输出形状与验收  
5. 迭代：一次一变  
6. 复述技术概念时的表达结构  
7. **迁移带**：同一结构如何变成对人的短汇报（点到为止）  

课程形态应复用大学已有的「课 → 练 → 卡」思想，而不是外挂论坛式社群课。

### 阶段 D — 有节制的情境练习

- 以 AI 协作场景的角色演练与改写为主  
- 人际困难对话保持附录级，避免子系统变味  

---

## 6. 为何这样切？研究与既有资产依据

### 6.1 产品内已有正确分工（应保留）

现有教学技能已规定：

- 教学拥有**事实正确性**  
- 表达反馈在事实对齐之后  
- 默认不同时混跑，避免角色打架  

这与认知劳动分工一致：先「说得对」，再「说得好」。  
子系统必须**强化**这一秩序，而不是用沟通课覆盖技术课。

沟通教练技能自身的克制也值得保留：

- 一次一个样本  
- 不自动全聊天挖掘  
- 不自动持久化  
- 拒绝假百分比进步  

这些不是功能残缺，而是伦理与认知上的安全设计。子系统的「累积记忆」应通过**学习者显式同意的原则卡/笔记**进入复习，而不是背后偷记。

### 6.2 方法内容从哪里来？

技能已引用的结构足够支撑主线，无需发明伪商学院框架：

| 结构 | 主用途（本子系统） |
| --- | --- |
| 目标·受众·约束（通用） | 任何点评前先对齐 |
| CO-STAR 一类 prompt 结构 | **对 AI 主教材** |
| 结论先行 / SCQA / 金字塔思路 | **迁移到人的注释与少量卡** |
| STAR | 讲清「发生了什么」时的迁移 |
| 观察→影响→请求 | 附录级，不主练 |

业主决策「主 AI、辅迁移」要求我们**抑制**把 SCQA/困难对话做成主线课程的冲动。

### 6.3 为何要进统一复习？

表达能力的敌人是**用过即忘**。  
间隔重复被广泛用于程序化与半程序化知识；沟通原则属于「可识别的结构习惯」，适合轻量卡片，不适合复杂心理测量。

统一脊柱的好处：

- 与项目知识同一「今日学习」生活  
- 避免沟通 App 化  
- 强制内容作者写出**可检验的回忆问题**（写不出正面问题的原则，说明还太飘）

### 6.4 为何不对人建完整主线？

不是因为「与人不重要」，而是：

1. 范围会迅速膨胀到软技能平台；  
2. 与人对练的真实反馈无法被本地 AI 诚实提供（AI 角色扮演 ≠ 真人结果）；  
3. 业主当前痛点与使用场景更集中在 AI 协作；  
4. 迁移注释能以极低成本保留「启发」，而不承诺「练会职场政治」。  

审阅者若主张做人完整主线，需说明如何避免范围爆炸与虚假精通。

## 7. 与另外两个子系统的关系

| 关系 | 说明 |
| --- | --- |
| vs 附带英语 | 正交。可组合（用英语写短委托再教练），但默认不绑死 |
| vs 元学习 | 学本系统时，会大量练习「如何向 AI 描述刷新/证据/边界」——天然教材 |
| vs 主教学 | 永远后置于事实；是增益层 |

---

## 8. 风险登记

| 风险 | 缓解 |
| --- | --- |
| 教练代写导致学习者不产出 | 流程要求先有学习者版本 |
| 事实与表达缠车 | 固定「先证据后表达」 |
| 卡片空洞（正确废话） | 原则必须带正反例与可操作下一句 |
| 迁移带变成人际主线 | 篇幅与课比例上限（战略上压住） |
| 偷记全聊天 | 坚持显式保存；教练默认不落盘 |

---

## 9. 审阅焦点问题

1. 「即时教练 + 原则复习 + 薄课」三层是否过重？能否合并？  
2. 主练 AI 是否应在战略上写死，还是保留未来扩展点即可？  
3. 沟通卡与项目知识卡争用复习时间时，默认配额如何定才不伪科学？  
4. 迁移到人的「只解释不深练」是否对业主长期目标过窄？  
5. 现有技能克制（不自动评分、不自动保存）在子系统化后是否仍应硬约束？
