# 岛屿观感合同：可以量的漂亮

## 名字先对齐（三层，各有确切的代码对应）

| 叫法 | 代码 | 看到什么 | 在这一层选什么 |
| --- | --- | --- | --- |
| **星球页** | `packages/world/src/planet/PlanetPage` | 一个星球 + 一列「学习」 | 选哪个学习 |
| **岛群图** | `Maps.tsx` 的 `WorldScene`，`detail="world"` | 一片海上好几座岛，每座挂一个课程标题 | 选哪门课（一座岛 = 一门课） |
| **课程岛** | `Maps.tsx` 的 `CourseScene`，`detail="course"` | 一座岛的近景，一串圆盘排成蛇形 | 选哪一节（一个圆盘 = 一小节） |

代码里管岛群图叫 `WorldScene` / "world map"，是历史叫法。**文档里一律用上表这三个词。**

## 这份文件解决什么

`docs/plans/active/island-v2-vertical-slice.md` 定的是**语义**：一条主线、双投影、unit 不靠地形切开、LOD 合同。那些都对，也都不管画面好不好看。

第一版切片跑完之后画面仍然不好看，原因不是算法失败，是**没有人写下「好看」是什么**，所以执行方只能优化它能读到的东西。六十张迭代截图里，`course-grass-*`、`course-dirt-path-*`、`course-mossy`、`course-desert`、`course-natural-soil-v3/v4`、`course-topmesh-*` 全部是地表材质的变体，**没有一张是镜头、光比、阴影或天空的变体**——而参考图之所以好看，主要就靠后面这四个。

本文件补上那四个，并且**每一条都必须能从一张 PNG 或一个单测里量出来**。量不出来的形容词不写进来。

## 一、诊断（带行号，不是感受）

### 1. 光比是 1.3:1，应该是 3:1 以上

`packages/world/src/Maps.tsx`：

- `directionalLight intensity={2.1}`（key）
- `hemisphereLight ... 1.35` + `ambientLight ... 0.22`（fill）

key : fill ≈ **1.3 : 1**。这个比例下阴影几乎不存在，所以所有物件看起来像贴纸，地形看起来像一块布。参考图的立体感来自 **3:1 到 5:1**。

补充：`shadow-camera` 只覆盖 `±0.3 × extent`，也就是说岛群图上只有中间 60% 的地方有影子。

### 2. 主体和背景一样暗

岛群图背景是 `PALETTE.seaDeep` 的一块圆盘 + 云。岛是中绿。两者明度接近，所以再多细节都糊在一起。参考图的岛之所以「跳」出来，是因为它坐在**接近白的云海和亮蓝天**前面——这一条和建模无关。

### 3. 密度差一个数量级

`packages/world/src/island/island-blueprint.ts`：`slotCount = Math.max(18, lessons * 3)`。
`packages/world/src/Maps.tsx` 再按 `hash > 0.58` 丢掉 42%，再丢掉离节点 3.15 以内的。
18 节课的岛最后大约 **20 个物件**。参考图上能数出来的在 **150–250** 之间。

### 4. 最该密的一圈被代码明确排除

同一文件：`radial = Math.sqrt(random()) * 0.78 * edgeScale`。物件永远放不到半径 78% 以外。
参考图里岛的「好看」有很大一部分来自**边缘**：树冠探出悬崖、灌木压在岩壁上、剪影是毛的不是光的。现行规则保证那一圈是秃的。

### 5. 镜头没有取景

课程岛的截图里根本看不到岛的边。参考图是一个 **diorama**：整座岛在画面里，四周留白，一眼能看出这是一座浮岛。

## 一点二五、岛群图不是拿来对标参考图的那一层

我算了一遍现有数字，结论跟直觉相反，**值得先写下来免得派错活**：

- 课程之间的间距 `STUDY_PATH.step = 7.4`；
- 岛半径 `radiusForLessons(n) = 0.55 + sqrt(n) * 0.42` —— 18 节课的岛直径 4.7，41 节课的 6.5。

也就是说**沿着那条路，陆地已经占了六成到九成的长度**，岛几乎是挨着的。排版没有问题，岛也不小。

真正的原因是：**那是一条一维的链，却被塞进一个二维的方框里取景。**
`Maps.tsx` 用 `extent = max(hypot(x, z)) + 8` 求一个外接半径去框它。一条斜着走的链
外接出来的方框，一多半是空海——3.2% 就是这么来的。

由此有三条推论，都写进任务里：

1. **参考图和 donor 白天场景都是一座岛的近景，对标的是课程岛，不是岛群图。**
   拿岛群图去比，是拿「整片海」比「一座岛特写」，比出来的差距不是缺陷。
2. **A1（陆地占比 ≥ 55%）只对课程岛的设计机位生效。** 岛群图本来就该一眼看到很多门课，
   硬把镜头推近去凑这个数，等于用信息量换画面——那是把好事做坏。
3. **岛群图真正要修的是 A4（背景层次），不是陆地占比。** 参考图里岛之外的部分不是「空」，
   是**有层次的云海加远景岛影**。我们的背景明度跨度只有 15–17，那是一块平涂，
   所以那片海读起来才像空白画布。**把背景做得值得看，比把前景放大更对。**

## 一点五、标杆是 Elemental-Serenity 的实拍，不是那三张 AI 生成图

三张 AI 生成图只说明「大概想要什么感觉」，它们不是 3D 渲染出来的，拿它们当验收基准会永远差一口气。
真正的标杆是 donor `elemental-serenity` —— 那是**真的用 Three.js 渲染出来的**。

我把它 README 的四季合成图解码测了一遍（安全内区取样）：

| 面板 | 陆地占比 | 陆地 L\* 中位 / p95 | 背景明度跨度 | 全画面 p2 / p98 | 标准差 | 草地明度跨度 / p95 |
| --- | --- | --- | --- | --- | --- | --- |
| **秋（白天，我们的基准）** | 84.3% | 64.7 / 89.5 | 74.5 | **17.9 / 99.9** | **21.1** | 82.1 / 99.8 |
| 冬（高调雪景） | 19.9% | 77.1 / 99.7 | 41.4 | 33.3 / 99.9 | 15.6 | 41.6 / 99.8 |
| 夜 | 73.9% | 24.7 / 80.2 | 95.3 | 4.7 / 100.0 | 23.5 | 30.5 / 39.4 |
| 雨（刻意压暗） | 78.9% | 14.4 / 19.7 | 14.2 | 11.5 / 33.4 | 5.7 | 4.5 / 16.5 |
| **我们线上** | **3.2%** | **36.8 / 66.2** | **15.1** | **36.2 / 63.9** | **7.0** | **31.5 / 42.5** |

**这张表最重要的一行是「秋」：p2/p98 = 17.9 / 99.9，标准差 21.1。**
和两张 AI 生成图（21.2 / 23.0）在同一档。也就是说——

> **实时 WebGL 完全做得到这些数字。门槛不是幻想，是别人已经渲染出来的现实。**

（「雨」那一栏也值得记：它标准差只有 5.7，和我们线上一样平——但那是**有意**压暗的情绪场景。
所以门槛只对**白天的设计机位**生效，刻意的暗场景不适用。这条要写进来，不然会有人拿它当挡箭牌，
也会有人误伤一个本来对的暗场景。）

### 但它的结构学不了，只有它的观感能学

donors.md 里已经写清楚了：它的地面是 **5×5 平面上的 fragment paint，不是真实高度**；水面是固定平面；
整个是**一个手工编排的场景 + 固定机位**，没有岛、没有路线、没有 LOD、不是程序化的。

所以「以它为中心做程序化地图」要翻译成一句精确的话：
**拿它的光、色和四个 shader，不拿它的场景结构。**

而 donors.md 里允许拿的那四样，恰好一对一地对上我们不及格的四项：

| 能拿的 | 修的是 |
| --- | --- |
| `Shaders/Materials/skydome/*` 天空配色与大气 | A4 背景明度跨度 15.1 → ≥ 40 |
| `Shaders/Chunks/grass/*` 草叶风变形与颜色 ramp | 草地明度 p95 42.5 → ≥ 85 |
| `Shaders/Materials/bush/*` billboard 灌木与 ramp | A1 陆地占比 / 密度——billboard 便宜，才买得起十倍的植被 |
| `Shaders/Chunks/water/*` ripple / Voronoi | 海面与云海，A4 的另一半 |

**它的媒体：owner 已决定先用（2026-08-28），同时在与作者沟通授权。** 按「隔离可用、来源待确认」
处理，规则写在 donors.md 的 `elemental-serenity` 一节。三条硬要求：

1. 每个进来的文件登记进独立清单，带 `provenance: "author-permission-pending"` 与日期，
   **和已确认 CC0 的 Kenney 分开放**，授权有结论时能精确拿掉或转正。
2. **八个 GLB 全要，贴图按需取。** 它一共只有 8 个 GLB（约 260KB）：
   `bridge` / `camp` / `tent` / `rocks` / `treeTrunks` 直接进道具库——桥和营地本来就是
   参考构图里的东西；`grass_blade` / `leaf` / `bushEmitter` 合计 4.7KB，是 shader 的几何载体。
   贴图只取 shader 和道具实际引用的那些，**不整目录搬**：目录里有多少张没人用的图，
   将来就有多少条要回答的来源问题。真正值钱的是
   `public/textures/{grass,bush,ground,water,noises}` 里的噪声与 ramp。
3. 丰富度的主力仍然是 **Kenney（CC0，逐包记了许可证与 sha256）+ billboard 植被**。
   donor 媒体是补充，不是地基——地基不能建在一个还没确认的授权上。

**待确认的关键事实不是「作者是否同意」，而是「这些素材是作者自己做的，还是他从别处下载的」。**
该仓库 README 没有任何 credits 章节。如果是下载来的，作者的许可不构成转授权。

## 一点七五、实验记录：三条死路和一个真正的杠杆

这一节是**跑出来的**，不是推出来的。方法：`pnpm dev` 起交付端，`Stage.tsx` 在 DEV 下把
R3F 的 state 挂在 `window.three`，所以可以**不改一行代码**在运行时改灯光/阴影/曝光，
截图，再用同一套指标量。每一行都是实测。

判据用「**陆地 L\* 中位 → p95 的落差**」（现状 5.2，donor 24.8，门槛 15）——
它量的是整块地有没有被照亮，撒深色草点绕不过去。

| 我改了什么 | 落差 | 结论 |
| --- | --- | --- |
| 主光强度 2.1 → 3.2 → 4.0 → 6.0 | 5.2 → 5.7 → 5.8 → **5.4** | **没用。** 整块地一起变亮，对比度纹丝不动 |
| 阴影相机 ±15.8 → ±40（覆盖全岛） | 5.2 → **5.2** | **没用。** 一点没动 |
| `gl.toneMappingExposure` 1.0 → 1.25 → 1.5 | 三张图**逐像素相同** | **这个开关是死的**，见下 |
| 太阳仰角 56° → 17°，补光归零 | 5.2 → **18.8** | **这才是杠杆** |

### 为什么强度和阴影范围都没用

**这座岛是一个圆滑的穹顶，太阳几乎在正上方**（实测光源位置 `(26.4, 47.5, 18.5)`，仰角
**55.9°**，接近正午）。正午的光打在穹顶上，镜头看到的那片顶部**朝向几乎一致**，所以
N·L 处处相同——**再强的光也只是把同一个亮度整体抬高**。摄影里正午被称作最难看的光，
就是这个道理。

阴影相机没用是因为投影本来就少：只有 63 个网格 + 173 个实例在投影，而且落在地上的
面积很小；换句话说，**在没有起伏、没有密集植被之前，阴影不是地面对比度的主要来源**。

（但阴影相机仍然是个真 bug，只是不在这一轮：`±15.8` 对上一座**约 70 单位宽**的岛，
只覆盖约 20% 的面积。等植被密起来之后它会立刻变成瓶颈。）

### `toneMappingExposure` 是死的，亮部天花板在 grade 里

三个曝光值渲染出**逐像素相同**的图。原因写在 `Stage.tsx` 的注释里：颜色管线是
`grade.ts` 的 `createGradePass()`——场景先渲进一个 linear target，再由 SwimmerRenderKit
的独立 blit 做 ACES → grade → 一次 sRGB 编码，**并且在 blit 期间把 renderer 的
`toneMapping` 强制成 `NoToneMapping`**。所以 renderer 上的曝光旋钮根本不参与成像。

**亮部的天花板在 `WORLD_GRADE`**（`grade.ts`，`contrast: 1.06`、`contrastPivot: 0.34`、
还有一个 `edgeGain: 0.76` 的 vignette 在压暗四周）。实测：**任何灯光组合都没能把
陆地 p95 推过约 80，全画 p98 推过约 85。** 要过 85 / 90 这两条线，**必须动 grade**，
而 grade 来自 SwimmerRenderKit——按品牌 kit 优先，改不动就改 kit 发版本，不在这里 fork。

### 目前找到的最好一组（仍然只过 4/6）

`太阳仰角 16° · 主光 5.0 · hemisphere 0 · ambient 0.05`：

| | 结果 | 门槛 | |
| --- | --- | --- | --- |
| 陆地中位 | 52.3 | 50–70 | ✓ |
| 陆地中位→p95 | 17.2 | ≥ 15 | ✓ |
| 全画标准差 | 18.2 | ≥ 18 | ✓ |
| 全画 p2 | 0.0 | ≤ 25 | ✓（偏低，补光归零导致暗部死黑，需要回一点） |
| 陆地 p95 | 69.6 | ≥ 85 | ✗ |
| 全画 p98 | 72.8 | ≥ 90 | ✗ |

**这组数字把第二轮的任务拆成了两半**：
一半是**把太阳放低、把补光压掉**（灯光就能拿到落差与标准差）；
另一半是**抬高亮部天花板**，那必须动 grade / kit，不是调灯光能解决的。

### 第二轮跑起来之后我又量了一组：光能修四项，修不了第五项

赛马发车后我用同一个运行时回路继续试了「低太阳 + 低补光 + 强主光」，
这是任务书让两个 agent 走的方向。结果（`measureScene` 的场景线性比值 / 像素指标）：

| 配置 | 场景比值 | 背景跨度 | 标准差 | 陆地落差 | 全画 p98 |
| --- | --- | --- | --- | --- | --- |
| 现状 | 1.77 | 14.7 | 13.4 | 11.4 | 72.3 |
| 仰角 14° · 主光 10 | **11.4** | **66.3** | **20.5** | 10.8 | 79.5 |
| 仰角 14° · 主光 20 | **20.8** | **79.7** | **24.0** | 9.5 | **90.0** |
| 仰角 20° · 主光 20 | **15.7** | **85.5** | **23.7** | 6.5 | **91.9** |

**四项一次解决**：场景比值（1.77 → 11–21）、背景跨度（14.7 → 66–85）、标准差（13.4 → 24）、
全画 p98（72 → 90+）。**背景跨度尤其值得注意——它不需要单独去做天空，
太阳一放低，海面和航拍底板自己就有了明暗层次。**

**但陆地自身的落差没动**（11.4 → 9.5），而且主光一强，陆地中位数就冲出 50–70。

**结论，并且这条要影响赛马的评分**：

> **A 段（光）能修四项，修不了「陆地落差」。**
> 那一项要的是**地形起伏**和**密集植被投下的影子**——也就是 B 段（密度）。
> 评审时不因为 `landLightnessRise` 没达标而判一个 agent 输。

还量到一件事：**补光归零会让 p2 掉到 0.0**（暗部死黑）。门槛是 `≤ 25`，
数字上过得去，但画面上是把暗部压没了。**补光要留一点**，这一条门槛拦不住，得靠看图。

### 草的固有色本身就太亮了——光还没打上去，它已经在上限

把 `island-geometry.ts` 的草地调色板换算成 L\*：

| 常量 | 十六进制 | L\* |
| --- | --- | --- |
| `GRASS_LIGHT` | `0x9cc66a` | 75.6 |
| `GRASS_WARM` | `0x87b85a` | ~70 |
| `GRASS` | `0x74a957` | **63.9** |
| `GRASS_DARK` | `0x507c4b` | 48.3 |

**基准色 `GRASS` 是 L\* 63.9，而合同要求整块地的中位数落在 50–70。**
也就是说——**在任何光打上去之前，草的固有色已经顶在允许区间的上沿了。**
光一强，它立刻冲出去（实测主光 12 时陆地中位 78.1）。

这是一个经典错误，有个名字：**把光画进了贴图里**。
调色板是照着「最终画面应该长什么样」painted 的，而不是照着「光会在它上面做什么」painted 的。

正确的做法是把固有色整体压暗一档：**基准色降到 L\* 45–50 左右**，
让阳光把它抬到 65、让阴影把它压到 35。**这样明暗才是光造出来的，不是画上去的。**
donor 的草之所以能从 18 跨到 100，靠的就是这个。

**这一条是 A 段可以做的**（材质在允许改动范围内）。

**但我把它也验了，它解不开「陆地落差」**——在运行时把所有固有色整体乘以 0.72 / 0.55：

| 固有色系数 | 陆地中位 | 陆地 p95 | **落差** | p2 | p98 |
| --- | --- | --- | --- | --- | --- |
| 1.00（现状） | 78.0 | 85.2 | **7.1** | 11.4 | 86.3 |
| 0.72 | 71.9 | 79.9 | **8.0** | 5.5 | 81.3 |
| 0.55 | 66.4 | 75.1 | **8.7** | 2.2 | 77.0 |

**中位数确实回到区间里了（78 → 66），但落差几乎没动（7.1 → 8.7），而且 p2 掉到 2.2。**
压暗固有色只是把整块地一起搬下去，仍然是一块均匀的布。

### 「陆地落差」的结论：四条路试完了，只剩一条

| 试过 | 落差 |
| --- | --- |
| 主光强度 2.1 → 6.0 | 5.2 → 5.4 |
| 阴影相机 ±15.8 → ±40 | 5.2 → 5.2 |
| 固有色 ×1.0 → ×0.55 | 7.1 → 8.7 |
| 低太阳 + **补光归零** | 5.2 → **17.2**（但 p2 = 0，暗部死黑） |
| 低太阳 + 正常补光 | 9.5 – 10.8 |

看最后两行就清楚了：**落差来自受光地面与背光地面的比值。补光一回来，背光那部分被抬起来，落差就没了。**

所以要同时拿到落差**和**有细节的暗部，只有一条路：**让更多地面真的处在投影里**——
也就是**整块地上都站着会投影的东西**，而不是只有一角有树。

> **这就是 B 段（密度）存在的理由，而且它现在有了一个可量的目标，不再是「多放点树好看」。**
> 判官量到的现状：每个课程节点 **2.39** 件装饰，门槛 7。

### 判官已知的一个测量缺陷（先记下，不在赛马中途改）

陆地是按色相分割的，而背景那张航拍底板上**画着绿色和土黄色的远景小岛**——
这些像素会被算进「陆地」。所有配置受影响一致，所以横向比较仍然成立，
但「陆地中位/p95」的绝对值偏了。

精确解是让渲染器出一张**只有岛的遮罩**（我们自己的场景可以免费渲）。
**赛马期间不动判官**——中途改尺子对两边都不公平。这条留到赛马结束后修。

### 用仓库里已有的 `measureScene()` 量了一次，结果解释了前面所有现象

`window.measureScene()` 是 `Stage.tsx` 里的 DEV 工具，返回 **grade 之前**的场景线性亮度分位数。
它是为了「grade 的常数必须是量出来的」那条基线规则写的，而这次是第一次真的拿它读数：

```
p05 0.186 · p25 0.231 · median 0.287 · p75 0.311 · p95 0.329 · max 1.346
```

**中间 90% 只跨了 0.186 到 0.329，比值 1.77 : 1——不到一档光圈。**

一个有太阳有阴影的真实场景，这个比值通常在 10:1 以上。也就是说：

> **在任何调色发生之前，场景本身就没有明暗。**

这一条把前面所有实验串起来了：

- **加强度为什么没用**：强度是乘法，把 0.186 和 0.329 一起乘大，比值仍然是 1.77。
- **放低太阳为什么有用**：它改变的是受光面与背光面的**比值**，不是乘一个系数。
- **为什么调色救不回来**：`PALETTE` 上方那段注释自己写过一句正确的话——
  「一张没有中间调的图，任何 grade 都救不回来，因为根本没有东西可以展开」。
  同一句话对亮部同样成立。

### 所以增加一条在调色之前量的门槛

| # | 标准 | 门槛 | 现在 |
| --- | --- | --- | --- |
| **S1** | `measureScene()` 的 **p95 / p05**（场景线性，grade 之前） | **≥ 4.0** | **1.77** |

**S1 是这份合同里唯一一条调色动不了的指标**，因为它在调色之前读数。
它也是最上游的一条：S1 不达标，后面所有像素指标都只能靠硬拉，拉出来也是假的。

### 更正一条我自己刚写的结论

我先前写「亮部天花板必须动 SwimmerRenderKit」。**这句话过头了。**
查了 kit 的类型定义：`GradeConfig` 确实没有 exposure，但它有 `contrast`、`contrastPivot`、
`saturation`、`vignette`——而 `WORLD_GRADE` 现在是 `contrast: 1.06`（几乎等于不做）、
`vignette.edgeGain: 0.76`（在压暗四周，正好压的是 p98）。**这些都能在 `grade.ts` 本地改，不用动 kit。**

而且 kit 对 `contrastPivot` 的文档写着：这是「最项目相关、也最常被设错的一个值」，
正确做法是量未调色的 p50 再换算——**而 `measureScene()` 给的正是那个数**。
仓库里工具和文档都齐了，只是没人跑过。

## 二、三层各自的取景合同

| 层 | 看的是什么 | 镜头 | 主体占画面 | 密度 |
| --- | --- | --- | --- | --- |
| 星球 | 有哪些学习星球 | 已有 | 已有 | 不在本轮 |
| 岛群（岛群图） | 课程之间的关系与进度 | 俯角 40–50° | 单岛 ≤ 12% | **语义 LOD：轮廓 + ≤5 个地标**，不是缩小的课程岛 |

**岛群图的密度规则和课程岛不是同一条。** 52 座岛各放 150 件物件会打死手机。岛群图走既有的 `detail: "world"` 投影。这一条写在前面，因为它是最容易被执行方误解成「到处都加密」的地方。

## 三、能从 PNG 量出来的验收标准

判图一律用 **no-post（关掉后处理）** 的那张，避免用 bloom 把亮度刷过线。

在设计镜头下截图，取两个区域：
- **主体区** = 画面中心 40% × 40%
- **背景区** = 画面外圈 20% 宽的环

| # | 标准 | 门槛 | 参考图实测（宽 / 竖） |
| --- | --- | --- | --- |
| A1 | 陆地占画面比例（**只对课程岛设计机位生效**，岛群图不适用，理由见下） | **≥ 55%** | 秋 84.3%；AI 图 32.6% / 48.0% |
| A2 | 陆地 L\* 中位数 | **≥ 50** | 秋 64.7；AI 图 53.6 / 50.2 |
| A3 | 陆地 L\* p95——受光的那一面必须真的被照亮 | **≥ 85** | 秋 89.5；AI 图 94.6 / 91.8 |
| A4 | 背景 L\* 跨度 p5..p95——天空和云海不是一块平涂 | **≥ 40** | 秋 74.5；AI 图 63.8 / 66.9 |
| L2 | 全画面 L\* 的 p2 / p98 | **p2 ≤ 25 且 p98 ≥ 90** | 秋 17.9 / 99.9；AI 图 21.5 / 94.4 |
| L3 | 全画面 L\* 标准差 | **≥ 18** | 21.2 / 23.0 |
| C1 | 草地色相跨度（p5..p95） | **≥ 35°** | 91.6° / 50.5° |
| C2 | 草地明度跨度（p5..p95）——「有没有光影」最直接的像素证据 | **≥ 45** | 秋 82.1；AI 图 34.0 / 50.7 |
| C2b | 草地 L\* p95——阳光那一面 | **≥ 85** | 秋 99.8；AI 图 62.5 / 64.3 |
| C3 | 高饱和强调色占**陆地**面积 | **≥ 1.5%**，且 ≤ 15% | 9.5% / 1.2% |
| R1 | 课程节点被遮挡比例 | **≤ 5%** | 需守住 |
| R2 | DOM 标签底下的画面对比度 | **≥ 4.5:1** | 变亮后有回归风险，必须测 |

**陆地与背景怎么分**：用渲染器出的岛遮罩，这是精确解，我们自己的场景可以免费渲一张。
参考图没有遮罩，用色相分割近似（陆地 = 黄绿到青绿加暖色，其余为背景）。

**为什么用中位数和分位数，不用最大最小**：一个黑像素加一个白像素就能骗过最大最小。中位数骗不过。

### 这些门槛是量出来的，不是拍出来的，而且已经改过两轮

第一版是**看着参考图写**的，两条数字当场被参考图自己证伪：

- 原来的 L1 写「画面中心 40% 对外圈 20% 环」。竖版参考图在这个定义下只有 **11.7**，不及格——
  但它不难看，只是岛顶到了画面边缘，外环里有一半还是岛。**固定裁剪量的是构图，不是观感。**
- 原来的强调色写「2%–5%」。两张参考图是 **9.5%** 和 **1.2%**，把这个区间从两头包在外面。

第二版换成色相分割真的去测，又推翻了一条**我自己刚下的结论**：

- 我曾经拿「中心 vs 外环 = 3.9」说「岛和背景是同一个亮度」。**那个数不成立**——线上岛群图
  97% 是海，中心和外环取到的都是海，所以它量的是「整幅画面很均匀」（这一点 L3 = 7.0 已经说得
  更清楚），不是「岛 vs 背景」。真按遮罩分割，线上的岛与背景差是 **15.9**，而两张参考图是
  **19.8 和 13.7**——**线上这一项其实落在参考图区间里，根本不是问题所在。**
  差一点就派人去改一个没坏的东西。

**一个自己都通不过自己门槛的合同是坏合同；一个没被数据推翻过的诊断是没验过的诊断。**
先量，再定门槛，量完了要敢推翻自己。

### 现状基线（2026-08-28，**本地 main**，DOM 全部隐藏后只测渲染画面）

**两条更正，都记在这里：**

1. **一开始量的是岛群图，量错了层。** 参考图和 donor 白天场景都是一座岛的近景，对标的是课程岛。
   「陆地只占 3.2%」这条**撤回**——它描述的是一个不该拿来对标的取景。
2. **接着量的是线上，而线上落后 main 很多**（island-v2 从未部署）。基线必须量 main。

| | 陆地占比 | 陆地 L\* 中位 / p95 | 背景跨度 | 全画 p2 / p98 | 标准差 | 草跨度 / p95 |
| --- | --- | --- | --- | --- | --- | --- |
| 线上（旧岛） | 64.1% | 63.9 / 68.5 | 17.1 | 24.5 / 70.9 | 9.5 | 22.9 / 68.4 |
| **main（当前）** | **72.0%** | **66.1 / 71.3** | **14.7** | **17.7 / 72.3** | **13.4** | **48.2 / 71.2** |
| **donor 秋（基准）** | 84.3% | 64.7 / **89.5** | **74.5** | 17.9 / **99.9** | **21.1** | 82.1 / **99.8** |
| 门槛 | ≥55% | 50–70 / ≥85 | ≥40 | ≤25 / ≥90 | ≥18 | ≥45 / ≥85 |

**先给 island-v2 记一功**：标准差从 9.5 提到 13.4，草地明度跨度从 22.9 提到 48.2（已达标）。
那一轮不是白做的，它把两项推动了。

**然后是这份基线真正说清楚的一件事——`p2 = 17.7` 已经达标。**

暗部是够的。缺的**全部在亮的那一半**：

| 不及格项 | 现在 | 门槛 | 差多少 |
| --- | --- | --- | --- |
| 陆地受光面 p95 | 71.3 | ≥ 85 | 13.7 |
| 全画面 p98 | 72.3 | ≥ 90 | 17.7 |
| 背景跨度 | 14.7 | ≥ 40 | 25.3 |
| 全画面标准差 | 13.4 | ≥ 18 | 4.6 |

**所以方向不是「整体调亮」，是「把太阳和天空加进去」。** 整体调亮会把 `p2 = 17.7` 顶过 25，
反而弄坏一项已经达标的指标——这条门槛就是为了拦住这个动作而存在的。

**还有一个数字最能说明地面的状态：陆地明度中位 66.1，p95 71.3，只差 5.2。**
占画面 72% 的那块地，从头到尾几乎是同一个亮度。donor 那块地中位到 p95 差 24.8。
它是**一块平铺的绿桌布**，上面撒了一些深色草点。

**注意一个指标陷阱**：草地明度跨度 48.2 已经达标，但它是被**深色草簇**（albedo）撑起来的，
不是被**光影**撑起来的。真正不会被这样绕过去的是「陆地中位 vs p95」那一对——
它量的是整块地，撒多少深色点都改变不了它没被照亮这件事。

## 五、判官（怎么跑）

一条命令，固定 seed、固定镜头，产出一组 PNG 加一份 metrics JSON：

1. 冻结输入：`foundations-before-zero`，seed 固定。
2. 拍 no-post 基线 + 最终图。
3. 拍近 / 设计 / 远三个机位。
4. 至少一个压力 seed（41 节课的岛）。
5. 桌面 + 390×844 各一组。
6. 输出 `metrics.json`，逐条给出上表每一项的实测值和是否达标。

这一步的意义：**把「太差了」变成「L1 = 11，门槛 25」。** 没有这一步，每一轮反馈都是一句感受，循环不收敛。

参考已注册技能：`threejs-visual-validation`（固定视角合同与拒收条件）、`threejs-camera-direction`、`threejs-exposure-color-grading`、`threejs-atmosphere-aerial-perspective`、`threejs-shadow-systems`。它们是**手册参考**，不是可安装的运行时；`threejs-awesome-graphics-agent-skills` 的降雨示例含 GPL 派生代码，不得复制进产品。

## 六、明确不许做的事

1. **不许出现第二份实现。** `island-blueprint` 与 `island-blueprint-v2`、`island-geometry` 与 `island-geometry-v2`、`cloud-layout` 与 `cloud-sea-v2` 必须先合成一份，再谈观感。合并前做的每一个数字都要做两遍。
2. **不许用后处理刷指标。** 判图用 no-post。
3. **不许把课程岛的密度规则套到岛群图。**
4. **不许让物件盖住课程节点**（R1）。
5. **不许因为画面变亮而牺牲 DOM 标签的可读性**（R2）。
6. **可读文字一律是 DOM，不是几何体。**
7. **`packages/ui` 的 `three` 依赖保持 0。**
8. 参考图是 AI 生成的插画。合同要的是它的**结构**——光比、明度跨度、密度、剪影、边缘——不是它的渲染精度。低模 CC0 资产做不出插画的细腻，也不需要做出来。
