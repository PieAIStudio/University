# 岛屿观感合同：可以量的漂亮

## 这份文件解决什么

`docs/plans/active/island-v2-vertical-slice.md` 定的是**语义**：一条主线、双投影、unit 不靠地形切开、LOD 合同。那些都对，也都不管画面好不好看。

第一版切片跑完之后画面仍然不好看，原因不是算法失败，是**没有人写下「好看」是什么**，所以执行方只能优化它能读到的东西。六十张迭代截图里，`course-grass-*`、`course-dirt-path-*`、`course-mossy`、`course-desert`、`course-natural-soil-v3/v4`、`course-topmesh-*` 全部是地表材质的变体，**没有一张是镜头、光比、阴影或天空的变体**——而参考图之所以好看，主要就靠后面这四个。

本文件补上那四个，并且**每一条都必须能从一张 PNG 或一个单测里量出来**。量不出来的形容词不写进来。

---

## 一、诊断（带行号，不是感受）

### 1. 光比是 1.3:1，应该是 3:1 以上

`packages/world/src/Maps.tsx`：

- `directionalLight intensity={2.1}`（key）
- `hemisphereLight ... 1.35` + `ambientLight ... 0.22`（fill）

key : fill ≈ **1.3 : 1**。这个比例下阴影几乎不存在，所以所有物件看起来像贴纸，地形看起来像一块布。参考图的立体感来自 **3:1 到 5:1**。

补充：`shadow-camera` 只覆盖 `±0.3 × extent`，也就是说世界地图上只有中间 60% 的地方有影子。

### 2. 主体和背景一样暗

世界地图背景是 `PALETTE.seaDeep` 的一块圆盘 + 云。岛是中绿。两者明度接近，所以再多细节都糊在一起。参考图的岛之所以「跳」出来，是因为它坐在**接近白的云海和亮蓝天**前面——这一条和建模无关。

### 3. 密度差一个数量级

`packages/world/src/island/island-blueprint.ts`：`slotCount = Math.max(18, lessons * 3)`。
`packages/world/src/Maps.tsx` 再按 `hash > 0.58` 丢掉 42%，再丢掉离节点 3.15 以内的。
18 节课的岛最后大约 **20 个物件**。参考图上能数出来的在 **150–250** 之间。

### 4. 最该密的一圈被代码明确排除

同一文件：`radial = Math.sqrt(random()) * 0.78 * edgeScale`。物件永远放不到半径 78% 以外。
参考图里岛的「好看」有很大一部分来自**边缘**：树冠探出悬崖、灌木压在岩壁上、剪影是毛的不是光的。现行规则保证那一圈是秃的。

### 5. 镜头没有取景

课程岛的截图里根本看不到岛的边。参考图是一个 **diorama**：整座岛在画面里，四周留白，一眼能看出这是一座浮岛。

## 二、三层各自的取景合同

| 层 | 看的是什么 | 镜头 | 主体占画面 | 密度 |
| --- | --- | --- | --- | --- |
| 星球 | 有哪些学习星球 | 已有 | 已有 | 不在本轮 |
| 岛群（世界地图） | 课程之间的关系与进度 | 俯角 40–50° | 单岛 ≤ 12% | **语义 LOD：轮廓 + ≤5 个地标**，不是缩小的课程岛 |
| 岛内（课程岛） | 这门课的学习路线 | 俯角 **32–40°**，整岛入画，留白 8–12% | 60–75% | **≥ 7 件 / 每个课程节点** |

**世界地图的密度规则和课程岛不是同一条。** 52 座岛各放 150 件物件会打死手机。世界地图走既有的 `detail: "world"` 投影。这一条写在前面，因为它是最容易被执行方误解成「到处都加密」的地方。

## 三、能从 PNG 量出来的验收标准

判图一律用 **no-post（关掉后处理）** 的那张，避免用 bloom 把亮度刷过线。

在设计镜头下截图，取两个区域：
- **主体区** = 画面中心 40% × 40%
- **背景区** = 画面外圈 20% 宽的环

| # | 标准 | 门槛 | 参考图实测 |
| --- | --- | --- | --- |
| L1 | 岛与背景的 L\* 中位数差（**用渲染器出的岛 mask 分割，不要用固定裁剪**） | **≥ 25** | 29.8 |
| L2 | 全画面 L\* 的 p2 / p98 | **p2 ≤ 25 且 p98 ≥ 85** | 21.5 / 94.4；8.8 / 93.9 |
| L3 | 全画面 L\* 标准差 | **≥ 18** | 21.2；23.0 |
| C1 | 草地色相跨度（p5..p95） | **≥ 35°** | 91.6°；50.5° |
| C2 | 草地明度跨度（p5..p95）——这是「有没有光影」最直接的像素证据 | **≥ 25** | 34.0；50.7 |
| C3 | 高饱和强调色占**岛**面积 | **≥ 1.5%**，且 ≤ 15% | 9.5%；1.2% |
| S1 | 崖壁岩带占岛可见高度 | **≥ 25%**，与草地交界处 L\* 落差 ≥ 15 | 无明显岩带 |
| S2 | 打断剪影的物件数（从设计镜头看，投影超出岛轮廓） | **≥ 8** | 0 |
| A1 | 远景岛相对近景岛：彩度衰减 / 明度向天空靠拢 | **≥ 30% / ≥ 15 L\*** | 无 |
| R1 | 课程节点被遮挡比例 | **≤ 5%** | 需守住 |
| R2 | DOM 标签底下的画面对比度 | **≥ 4.5:1** | 变亮后有回归风险，必须测 |

**为什么用中位数和分位数，不用最大最小**：一个黑像素加一个白像素就能骗过最大最小。中位数骗不过。

### 这些门槛是量出来的，不是拍出来的

上表最后一列是把两张参考图（`docs/reference/island-art-reference/target-island-wide.png` 与
`target-island-tall.png`）真的解码测出来的值。门槛取在两张之下、留出余量的位置。

**并且第一版门槛已经被这次测量改过一次，这件事本身要记下来**：

- L1 原本写的是「画面中心 40% 对外圈 20% 环」的固定裁剪。`target-island-tall` 在这个定义下只有
  **11.7**，低于门槛——但它并不难看，只是构图上岛顶到了画面边缘，外环里有一半是岛。
  **这说明固定裁剪量的是构图，不是观感。** 所以 L1 改成用渲染器出的**岛 mask** 分割；
  我们自己的场景可以免费渲一张只有岛的遮罩，这是精确解。
- C3（强调色）原本写「2%–5%」。两张参考图分别是 **9.5%** 和 **1.2%**，把这个区间整个包在外面。
  改成下限 1.5%、上限 15%：要有点睛，但不许满屏霓虹。
- 新增 C2。草地自身的明度跨度是「有没有光影」在像素上最直接的证据，比任何间接指标都好用。

**一个自己都通不过自己门槛的合同，是坏合同。** 先量参考图，再定门槛——顺序反了就会拿一个想当然的数字去骂执行方。

## 四、只能从代码里量出来的验收标准

| # | 标准 | 门槛 |
| --- | --- | --- |
| D1 | 课程岛物件数 / 课程节点数 | **≥ 7** |
| D2 | 物件分四层：canopy / mid / ground / rim | 每层至少占总数 **10%** |
| D3 | 半径 > 0.8 的物件占比 | **≥ 20%** |
| D4 | key : fill 光比 | **≥ 3 : 1** |
| D5 | `shadow-camera` 覆盖范围 | 覆盖设计镜头可见的全部地面 |
| D6 | 世界地图单岛物件数 | **≤ 8**（语义 LOD 不变） |
| P1 | 移动端帧预算 | 不劣于当前基线 |

## 五、判官（怎么跑）

一条命令，固定 seed、固定镜头，产出一组 PNG 加一份 metrics JSON：

1. 冻结输入：`foundations-before-zero`，seed 固定。
2. 拍 no-post 基线 + 最终图。
3. 拍近 / 设计 / 远三个机位。
4. 至少一个压力 seed（41 节课的岛）。
5. 桌面 + 390×844 各一组。
6. 输出 `metrics.json`，逐条给出上表每一项的实测值和是否达标。

这一步的意义：**把「太差了」变成「L1 = 11，门槛 25」。** 没有这一步，每一轮反馈都是一句感受，循环不收敛。

参考已注册技能：`threejs-visual-validation`（固定视角合同与拒收条件）、`threejs-camera-direction`、`threejs-exposure-color-grading`、`threejs-atmosphere-aerial-perspective`、`threejs-shadow-systems`。它们是**手册参考**，不是可安装的运行时；`threejs-awesome-graphics-agent-skills` 的降雨示例含 GPL 派生代码，不得复制进产品。

## 六、明确不许做的事

1. **不许出现第二份实现。** `island-blueprint` 与 `island-blueprint-v2`、`island-geometry` 与 `island-geometry-v2`、`cloud-layout` 与 `cloud-sea-v2` 必须先合成一份，再谈观感。合并前做的每一个数字都要做两遍。
2. **不许用后处理刷指标。** 判图用 no-post。
3. **不许把课程岛的密度规则套到世界地图。**
4. **不许让物件盖住课程节点**（R1）。
5. **不许因为画面变亮而牺牲 DOM 标签的可读性**（R2）。
6. **可读文字一律是 DOM，不是几何体。**
7. **`packages/ui` 的 `three` 依赖保持 0。**
8. 参考图是 AI 生成的插画。合同要的是它的**结构**——光比、明度跨度、密度、剪影、边缘——不是它的渲染精度。低模 CC0 资产做不出插画的细腻，也不需要做出来。
