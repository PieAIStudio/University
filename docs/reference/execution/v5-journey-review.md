# V5 用户旅程复盘：哪些继续，哪些降级，哪些砍掉

这不是把 `docs/reference/player-journey/v5/index.html` 复述一遍。
它是对 v5 每一条施工项的**逐条判断**：还成立的说成立，被现实推翻的说清楚哪一条前提塌了，
投入产出不值的直接建议砍。

## 怎么读这份文件

- v5 仍然有效。这份复盘**不自动修改 v5**；标成「建议砍」和「建议降级」的条目，
  拍板之后才回去改 v5，这是「先设计后实现」的顺序，不是绕过它。
- 每条都写了**谁能拍板**。写「已可执行」的，是我按用户授权直接做掉的；
  写「待拍板」的，攒进一次性清单问人。
- 判断依据只用两种东西：仓库里的代码，和已经写下来的缺口文档。没有凭印象的结论。

## 一、被现实推翻的两条前提

v5 里有两处推理当时成立，现在不成立了。它们不是执行没跟上，是前提本身塌了。

### 1. §06 假设「提醒最终会送到」

§06 的整个论证建立在一句话上：提醒是复习价值的延伸，所以在价值兑现之后问，就值得问。

这句话有个没说出口的前提——**问完之后，提醒真的会来**。

现实是：University 没有推送服务端，`REF-REVIEW-REMINDERS-BACKEND-GAP` 已经把这个缺口
写清楚了，而后端本身正在重整。所以今天问完的最好结果是**零**：学习者点「好」，
走完浏览器权限流程，然后永远收不到一条提醒。

代码是诚实的——预提示里明写「当前服务端还没接上；打开后会先登记这台设备，
暂时不会真的收到提醒」。但**诚实不能让这笔交易变划算**。见下面第三节。

### 2. §03/§04 假设「ASR 卡在设计上」

§04 把学习者口述列为「开放」，措辞是等一个明确的选择加入设计完成。
这假设**设计是瓶颈**：把同意流程、处理位置、保存与删除想清楚，就可以做了。

现实是设计从来不是瓶颈，**平台已经把这件事做完了，而且做得比我们能做的好**。
见下面第二节。

## 二、建议砍掉：ASR（学习者口述复述）

**判断：不做。不是推迟到某个版本，是这条线不存在。**

### 为什么

**第一，我们要重造的那个轮子，用户手上已经有了，而且更好。**

「讲一遍」的输入框是一个普通的 `<textarea>`。iPhone 的听写、Android 的 Gboard 语音输入、
搜狗和讯飞输入法的语音键——**今天就能往这个框里说话**，一个字的代码都不用写。
它们对「普通话夹英文标识符」这种混说场景的识别，比浏览器 Web Speech API 好得多，
因为那正是中文输入法厂商十年来在优化的场景。

我们自己接 ASR，等于把一个平台**免费提供、质量更高、同意模型归操作系统**的能力，
重造成一个更差的版本，并且顺手把隐私责任揽到自己身上。
这一条同时踩中两条铁律：不要重造轮子，和一份实现永远只有一份。

**第二，v5 自己列的五个问题，每一个都是钱。**

§03 列了 ASR 上线前必须先回答的五件事：去哪处理、什么时候同意、保存什么、
识别失败怎么办、学习者能否反悔。这五件事加起来不是一个输入框，
是一个**隐私产品**：同意界面、数据生命周期说明、删除路径、浏览器能力矩阵、
中英混说的错误处理。

**第三，最弱的场景恰好是我们最常见的场景。**

v5 §03 自己写了：Chrome / Edge 的语音识别把音频流向 Google 或 Microsoft，
Firefox 根本没实现；而这个产品里最常见的口述不是干净的单语句子，
是普通话夹着 `turing-pact` 这样的私有仓库名和英文标识符。

**第四，也是最关键的一条：现在做 ASR 是本末倒置。**

「讲一遍」这个功能的全部理由，v5 说得很清楚：「保存本身不是学习，回来再答才是」。
我们**还不知道有没有人回来**（见第四节）。
在一个回访率未知的功能上先投资输入方式，是先修台阶再看有没有门。

### 这一刀砍下去，顺手关掉三个开放问题

v5 §04 的开放清单里有三条，全部由这个决定一次性关闭：

| 原开放问题 | 关闭后的答案 |
| --- | --- |
| 学习者口述复述是否默认开启 | 不开启，也不做 |
| ASR 的处理位置与服务商 | 不适用，University 不接 ASR |
| 录音 / 转写的保存与删除 | 不适用，University 不保存音频或转写 |

### 要做的只有一句话

v5 §03 明确禁止「用没有按钮掩盖能力不存在」。所以这不是悄悄不做，
而是在「讲一遍」输入框旁边说清楚：

> 想说不想打？用你键盘上的听写。我们不录音，也不上传声音。

一句提示，替代一整条产品线。

## 三、建议降级：复习提醒的主动预提示

**判断：保留全部客户端实现，但在推送服务端就绪之前，结算页不再主动弹预提示。**

### 为什么不是「反正文案诚实，就先放着」

浏览器通知权限是一次性资源，而且**拒绝之后基本不可逆**：Chrome 记住 denied 之后不再弹，
学习者必须自己钻进浏览器设置里改回来。v5 §06 自己也承认这一点，
所以写了「浏览器已经返回 denied 后，结算页永远不再自动出现预提示」。

把这两件事并排放：

- 我们花掉的是一个**不可再生**的许可。
- 我们换回的是一个**已知为零**的回报。
- 支付这笔账的时刻，是一个人刚学完一节课、心情最好的时候，
  而我们递给他的是一句免责声明。

诚实的文案让这件事不算欺骗，但不能让它变成好交易。

### 具体怎么改

- 结算页的**主动**预提示挂在一个「推送服务端是否就绪」的开关后面，默认关。
- 设置页里**学习者自己去点**的入口保留。那是他主动要的，不消耗惊喜，
  也不违反 v5「控件不许消失」——控件在，点开有诚实解释。
- 服务端接通那天，把开关打开即可，UI 一行不用改。

订阅按 endpoint 合并、iPhone 主屏幕 web app 能力检测、Service Worker 不接管 fetch——
这些都是对的，全部保留。这是降级，不是砍。

## 四、保留但降级为观察对象：「讲一遍」

**判断：实现是对的，一行不用改。但它现在处在「我们不知道它有没有用」的状态，
而这个状态是可以直接修好的。**

`RecapPrompt.tsx` 做得很干净：用单元现有的第一人称能力句当提示，
零模型调用，答案直接进共享的 FSRS 队列。v5 对它的辩护也站得住：
选择题把「生成一个解释」换成「认出一个选项」，AI 判卷会给免费层带来无法封顶的成本。

问题在别处。这个功能的**全部**价值主张是「到期时回来再答，并排看自己两次的答案」。
而 `apps/university/src/analytics/productAnalytics.ts` 现在的 14 个事件里，
**没有任何一个能回答「有人回来了吗」**：

- 没有「复述卡被保存」的事件。
- `review_graded` 有 `rating` 和 `cardCount`，但**不区分**这张卡是复述卡还是生词卡。

所以我们建了一个功能，它成立与否取决于一个我们测不到的行为。

**已可执行**：补两个事件——复述卡保存、复述卡到期被重答（带上是不是复述卡这个维度）。
跑一段真实数据再决定要不要在这条线上加码。

在那之前，任何「给复述加 AI 判卷 / 加语音 / 加提示词」的提案都应该先被这个问题挡住：
**有人回来吗？**

## 五、保留、不要动的几条

- **§01 读完与答对分开。** `packages/core/src/progress/source.ts` 里
  `readConfirmed`、`exercisesPassed` 和给老文档兜底的 `legacyComplete` 都在。
  多一次「我读完了」的点击确实多一步摩擦，但这一步换来的是「完成」这个词不撒谎，值得。
- **§03 TTS 四档。** `packages/ui/src/language/speech.ts` 已经实现，
  自动存的是请求而不是某次解析结果，高品质在钱包接好前置灰并解释。这条不用再想。
- **源码证据 ≤16 行内联。** 这是 v5 里论证最扎实的一条：先扫 1,597 条 anchor
  跑出分布（中位数 9 行、P75 17 行），再把常量定在 P75 之前的最后一个完整值，
  还留了「分布变了就重跑同一份审计」的复查路径，并且有真实浏览器截图证据。
  以后所有阈值都该这么定。
- **§07 世界头像与路径方向。** 已实现。其中「第一座岛不享有装饰特权」与用户另一个
  Codex session 的 `codex/island-v2`（程序化岛屿生成）scope 完全重叠——
  **这边不要再动**，等那条线的结果再对齐，否则两边会互相拆台。

## 六、保留但有真实成本的一条：匿名账号地基

§06A 的实现和文案边界都对：匿名会话只在真正产生学习价值时静默建立，
匿名不能购买，绑定失败保住两边文档，并且明确拒绝把它说成跨设备安全。

但有一笔账要写在明处：**孤儿匿名用户会累积，而且直接计入账单。**
Supabase 的匿名用户一旦认证就计入 MAU；清掉 localStorage 的人回来算一个新的匿名用户、
新的一个 MAU。免费档是 50,000 MAU。这不是 University 能在自己仓库里补一条迁移解决的，
它需要 SwimmerBackend 侧的保留期和清理策略，已登记在 `REF-PAYMENT-BACKEND-GAP`。

在那之前，这是一条**已知的、会随流量线性增长的成本**，做增长预估时要带上它。

## 七、v5 没写、但现在必须写下来的一条

`work/addressable-lessons` 把地址从 hash 路由改成了 path 路由——
这件事本身是对的，hash 后面的内容 Googlebot 在发请求前就丢掉了。

但**地址修好了，域名还是临时的**。挂在 `*.vercel.app` 上攒的权重是白攒的：
换域名等于重新开始。所以路由这条线**没有真正完成**，它的完成线在域名上，不在代码里。

这条待拍板，且拍得越早越省。

## 需要拍板的

1. ASR 整条线砍掉，同意吗？（同意则回去改 v5 §03/§04，把三个开放问题标为已关）
2. 提醒预提示挂到「服务端就绪」开关后面，同意吗？
3. tier-2 每天 400 power units 的免费额度，定在多少？（和定价是同一个问题）
4. delivery 站的真实域名是什么？
5. 匿名用户的保留期与清理策略，谁在 SwimmerBackend 侧负责？
