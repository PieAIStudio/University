# 多语言：策略与架构决定

这是从本轮 scratch 策略记录提升的唯一策略住处。它拥有产品边界、
课程译文的版本语义、locale 发布闸门和分期决定；执行收据也合并在本文末尾。
具体的 catalog 实现与测试仍以代码为准。

主控（产品 / 架构）。初始决定于 2026-08-31。

## 当前实现核对（2026-09-03）

在当前 HEAD `9cb6f79` 运行 `node scripts/check-i18n.mjs`，输出为：

```json
{
  "sourceCatalogKeys": 1145,
  "englishCatalogKeys": 0,
  "unextractedChinese": 0,
  "physicalCssDeclarations": 0
}
```

因此本文第 9 节里的 **1,105** 是 Phase 1 收尾时的快照，不是当前 key 总数；
当前目录仍是英文 scaffold，尚未成为可选 locale。第 9 节和第 1.5 期的范围
判断仍然有效：`packages/core` 的界面文案尚待纳入，而 `concepts/data/` 的
281 条概念散文仍属于课程内容，不能混进 UI catalog。
产品负责人的命题：**在线学习支持的语种越多，长尾越大**；小语种用户缺好应用，
那是机会。他自己钉中英文，其余交给 AI，出问题靠小语种用户提意见再改。
问了两条路线：**先搭框架占位后填** vs **即时翻译（像 Google 那样）**。

## 0. 先把命题拆对——这不是一个选择，是三个

这个问题被当成一道单选题问出来，但产品里要翻译的东西有三种，
**它们的量级、成本结构和纠错方式完全不同，必须用三套机制。**

| 面 | 量 | 机制 | 边际成本 |
| --- | --- | --- | --- |
| **App 界面文案** | 初始盘点 **1,213 条**中文字面量，散在 **146 个文件** | 预翻译的消息目录，随构建发布 | 每条每语言一次 |
| **课程内容** | 巨大且带版本（单是 turing-pact 就 3,705 个 md） | 预翻译成**已发布的产物**，走同一条唯一生产者管线 | 每个 revision 每语言一次 |
| **AI 批改与辅导** | 运行时按人生成 | **告诉模型用学习者的语言回答** | ≈ 0 |

第三条是免费的：那本来就是一次模型调用，加一句"用学习者的语言作答"不额外花钱。
**这一条今天就能做，而且它可能是小语种用户最先感受到的尊重。**

## 1. 决定：课程内容**不做**即时翻译

理由不是成本（虽然成本也压倒性）——**理由是产品负责人自己的纠错计划**。

他说："**小语种用户提意见，我们再把它改**"。

**要改，就必须有一个可以被改的东西。** 即时翻译的输出：

- 不能被审阅
- 不能被修正
- 不能被版本化
- 不能钉在某个 `contentRevision` 上
- 每个读者每次打开都重新生成一遍

一节课被读一万次，即时翻译就付一万次；预翻译付一次。
**但更要命的是：一万个读者看到的是一万个略有不同的译文，
一条"这里翻错了"的意见没有对象可以指向。**

而且它违反 ADR-0002：**课程内容只有一个生产者**。
一个运行时翻译器就是第二个生产者，SPEC-0001 会随之瓦解。

## 2. 决定：译文是**源 revision 的一个 revision**，陈旧是一等状态

这条是整套设计的脊椎。

一节课的中文改了，它的 20 个译文**当场全部过期**。
如果系统不知道这件事，产品会在无人察觉的情况下，
向小语种用户长期供应与中文版本矛盾的内容——
**那比不翻译糟糕得多，因为它看起来是对的。**

所以每一份译文必须钉住**它是从哪个源 revision 译出来的**，
并且 `sourceRevision ≠ 当前 revision` 是一个**可见、可查询、可测试**的状态。
过期时的行为要明确（回退到源语言 / 标注"这一节的译文落后于原文"），
**不许静默地继续供应。**

## 3. 决定：一个语言要么完整，要么不出现

**半翻译的界面比不翻译更糟。** 60% 越南语 + 40% 中文的屏幕读作"坏了"，
而纯中文界面读作"这个产品还没支持我的语言"——后者诚实，前者掉信任。

所以：**locale 的完整度是一道发布闸门。**
某个语言的目录对当前构建不是 100% 完整，它就**不出现在语言列表里**。
这条要写成测试。

这同时回答了产品负责人"先占位、框架搭好、以后再填"的想法：
**对，但占位不许被看见。** 脚手架 = 机制 + 抽取 + 完整度闸门，
真正完整的先只有中文（源）和英文。

## 4. 决定：不引入 i18n 库

需要的能力是插值、复数、日期数字格式、RTL。
其中复数/数字/日期，浏览器原生的 `Intl.PluralRules` / `Intl.NumberFormat` /
`Intl.DateTimeFormat` 已经覆盖，而且覆盖得比任何库都准。

剩下的就是"一个 key 查一个字符串"。为这件事引入 i18next
是在项目最核心的可读性规则上做减法。**一份目录 + `Intl.*` 就够，而且更好读。**

## 5. 决定：RTL 从第一天做

阿拉伯语、波斯语、乌尔都语、希伯来语是从右向左书写的，
而**阿拉伯语恰恰是"人多 + 优质开发教育稀缺"这个长尾论点最强的一格**。

初始审计：`packages/ui` 的 CSS 里物理属性 **143 处**，逻辑属性只有 **18 处**。
**现在不做，以后要回头改 143 处。** 抽取文案的时候顺手把它们改成
`padding-inline` / `margin-inline` / `inset-inline` / `text-align: start`，
成本几乎为零；等到有阿拉伯语用户再改，就是一次专门的返工。

## 6. 支持多少种语言：这不该是我来猜

**正确答案不是一个数字，是让"加一种语言"的成本趋近于零，
从而让数量变成商业决定而不是工程决定。**

加一种语言应该是：放一个目录文件 + 注册一个 locale。**不改一行代码。**

至于顺序，有一个比我猜测强得多的信号：**访客浏览器请求的 locale**。
框架落地后记录 `navigator.language`（只记语言码，不记任何个人数据），
让真实需求决定顺序。这和已经在做的 usage ledger 是同一种纪律：
**把猜测换成事实。**

**第一波真正完整的只有两种：中文（源）和英文**——
正是产品负责人说他会亲自钉好的那两种。其余是脚手架加测量。

## 7. 分期

| 期 | 内容 | 依赖 |
| --- | --- | --- |
| **一** | 消息目录机制 + 1,213 条抽取 + 完整度闸门 + RTL 逻辑属性 + locale 请求测量 | 无 |
| **二** | AI 批改/辅导用学习者语言作答 | 一（拿到 locale） |
| **三** | 课程译文管线：译文即 revision、钉源 revision、陈旧可见、走唯一生产者的发布闸 | 一、二 |
| **四** | 小语种用户的意见回路接到译文上（意见指向"这一节这一语言的这一版"） | 三 + 反馈后端 |

**第一期不翻译任何课程内容，也不真的翻译 100 种语言**——
正是产品负责人说的"先占位"。区别在于：占位的东西不许被用户看见。

## 8. 一条要警惕的

这个产品教的是编程，而**技术术语在很多语言里没有好的本地化译法**，
硬翻会让内容更难懂而不是更易懂。产品里已经有一个现成的答案：
**外语模式**（`packages/ui/src/language/`）——在母语文章里标出并解释外语术语。

那套机制原本是为"中文学习者顺便学技术英语"做的，
**但它恰好就是小语种用户需要的东西**：用母语讲解，术语保留英文并给出解释。
第三期设计译文管线时，**先读那套机制，不要另造一套。**

## 9. 第一期落地后发现的范围缺口（2026-08-31，主控）

第一期交付：**1,105 条**中文源 catalog、完整度闸门（正反两向都验过：
不完整的 locale 不出现，完整的 locale 会出现）、**218 处** RTL 逻辑属性转换、
locale 需求测量（只记语言子标签）。三屏浏览器 before/after 无回归。

**但闸门只扫 `packages/ui/src` 和 `apps/university/src`。**
那是我在简报里划的范围（1,213 条那个数就是这么量的），
所以这不是执行缺陷，是**我的范围划漏了**。

`packages/core` 里还有两类用户可见文字，性质完全不同，**不要一起处理**：

| 在 core 里的东西 | 它属于哪个面 | 怎么办 |
| --- | --- | --- |
| `billing/plans.ts` 的方案文案、`ports/payment.ts` 的解释、grading 的解释文案 | **界面文案** | 进 catalog。这是**第一期漏掉的部分，补成 1.5 期** |
| `concepts/data/*.ts` 的 281 条概念词条散文 | **课程内容** | 走第三期的译文管线，**不要塞进 UI catalog** |

第二类如果误当成界面文案塞进 catalog，会把一份 UI 目录撑成课程语料库，
并且丢掉课程内容那套"译文是源 revision 的一个 revision、陈旧是一等状态"的机制——
**那正是第 2 节说过的、最贵的那个错误。**

### 1.5 期（第二期之前做）

把 core 里那批**界面性质**的文案接进同一份 catalog，
并把 `check-i18n.mjs` 的扫描范围扩到 `packages/core/src`，
**但要显式排除 `concepts/data/`**，并在脚本里写清为什么排除——
否则下一个人会以为那是遗漏。

## 10. Phase 1 完成收据（2026-08-31）

Phase 1 建立了 catalog 与 locale 注册机制、正反向完整度闸门、匿名
`navigator.language` 需求测量和 RTL 逻辑属性改造；没有翻译课程正文，
也没有改 `packages/ui/src/language/`、`apps/local/studies/` 或 AI grading
语言切换。收尾快照为 1,105 个 source key、218 处 RTL 转换、三屏浏览器
before/after 复核，且当时的 `pnpm verify` 通过。当前计数见上面的核对节，
不要把这份历史收据中的数字当作现行目录大小。
