# 岛群取景不避让界面，四门课只画得下三个标签

这是一份产品缺口说明。合并 `codex/interaction-first` 后，两条地图用例第一次走到
**四门课的岛群**（`browser-ai`），暴露出两件事：其一，四门课里有一门的名字
没有被画出来；其二，被拖到右边缘的岛，旁边放不下「进入」按钮。

**本轮不修。** 修它要动岛群层的相机取景，而取景和界面遮挡分处
`apps/university/src/app/scene-camera.ts` 与 world 包的 Canvas 内部，跨边界。
2026-09-21 凌晨判断：不在无人复核时把相机改动推给所有人。

## 为什么这一轮才暴露

`e2e/harness/domain-catalogue.ts` 的 `PRIMARY_DOMAIN_ID` 由
`CATALOGUE_ROLES.settlement` 推出，而那个角色要求「第一节课有一道确定性练习」。
`understanding-ai` 的第一节改成 PRIMM + `explain`（开放题，按设计没有确定答案）后
不再符合，角色自动改选：

```
settlement study : browser-ai        （原 ai-literacy）
该 study 的课程数 : 4                （原 2）
```

于是这两条测试第一次走到四门课的岛群。**不是回归，是新暴露的限制。**

## 已经验证的事实

- 这次合并**没有改动**任何放置或投影代码：`MapEntryAction.tsx`、
  `map-entry-action.css`、`labels/path-overlay.ts`、`WorldMapCanvas.tsx`、
  `Maps.tsx` 均未改；`browser-ai` 的内容也是逐字节相同。
- **不是标签数量上限**：`--map-label-limit` 桌面为 9，候选只有 4；
  `island` 锚点每个标签会尝试 27 个候选位置。
- 交付端地图页上 **`.app-shell__aside` 根本不存在**（实测读到 1440，即视口右缘）。
  我先前把「右栏挡住了侧边位」写进这份文档，那是错的，已改正——右侧真正的遮挡是
  `.app-shell__east-stack`。
- 1440 宽视口下，一次完整走查实测到的全部遮挡块（视口坐标，x,y,w,h）：

  | 块 | x | y | w | h |
  | --- | --- | --- | --- | --- |
  | `.nav-rail` | 16 | 16 | 248 | 778 |
  | `.counter-row` | 33 | 684 | 214 | 34 |
  | `.map-breadcrumbs` | 0 | 16 | 1440 | 44 |
  | `.app-shell__east-stack` | 1360 | 266 | 64 | 277 |
  | 学习者头像（投影后 ±10） | 1362 | 223 | 65 | 70 |

- 被拖到右边缘的岛标签实测 **203×48 @ (1221,534)**：它的右段正压在 east-stack
  与头像底下，右侧位确实没有。「进入」按钮最终落在 **64×44 @ (1276,404)**，
  即**贴着岛的正上方 86px**，没有被裁切。
- 同一步在**本地端**是**翻到左边**的：岛标签 136×48 @ (1262,512)，按钮
  64×44 @ (1202,460)，边缘间隙 **8px**。所以「翻边」这条路径本身是通的，
  交付端那一次是这个具体取景下侧边都用不上。
- 仓库里已有正确做法：`camera/course-overview.ts` 的 `overviewViewport()`
  会算出「排除界面遮挡后的最大可用矩形」，但**只用于单个课程岛的总览**
  （`CourseOverview.tsx`），岛群层的 `camera/frame.ts::frameWorld()` 不用它——
  它只按「学习者所在岛 + 最近邻居」求质心，完全不看遮挡。

## 还不确定的事

没有定位到「第四个名字为什么没被画」的确切拒绝原因，也没有定位到交付端那一次
「左侧位为什么也没用上」——按视口坐标算，左侧位看上去是空的。

原因是这两个问题都**不能从浏览器测量里反推**：`placeLabels` 算的是
**stage 坐标系**里**岛的投影峰点**，以及头像的投影包围盒；而测试能量到的全是
**视口坐标系**里**标签**的矩形。两套坐标、两个锚点，对不上。我在这上面连续两次
给出了错误的解释（先说是右栏挡的，后说是头像占了两个侧边位），两次都被数据推翻。

要下结论，只能在 `controls.tsx` 那一帧里把候选槽位、遮挡框和拒绝原因打出来。
**不要在没有这份数据之前动放置算法。**

## 闸门现状

- `e2e/avatar.spec.ts` 原本点名一门固定的替代课程，现在改为**向地图要**它
  实际画出来的替代课程，并在一门都没有时明确失败。
- `e2e/island-pick.spec.ts` 的「贴着岛」不再猜投影器选了哪个槽位——那正是上面
  说的、从测试里做不到的事。它改问学习者真正在意的那件事：按钮是否还**跟着这座岛**。
  契约是**一个落位步长（< 96px）**，来自 `slotsFor("aside")` 自己的偏移量
  （侧边 `宽/2 + gap + clearance` = 96px，上下 `高/2 + gap` = 30px）。
  实测 4.8 / 0 / 0 / 8 / 86px 全部通过，而「停止跟随」那次实测的 214px 仍然红。
  另外两条不变：按钮不得压在岛上（按真实重叠面积算，< 20%），不得越出岛的右缘。

两条都仍会在情况变坏时失败，但都**不再要求**四个标签全部画出。所以这份文档是
「四门课只画得下三个」这件事**唯一**的记录点。

## 补它的时候要一起决定的事

1. 岛群取景是否也该用 `overviewViewport()` 的可用矩形，还是右栏在地图页就该收起。
2. 若取景避让后仍放不下，名字是缩短、换行、还是按距离分层显示。
3. 学习者表面规则要求缺失的能力可见并可解释——一门课在岛群上没有名字，
   等于它在这一屏不可达，需要一个明确的兜底。
