# 一节课怎么写

这份文档是写课文的人（我、Grok、或以后任何 AI 宿主）必须遵守的结构。
它不是风格建议，是**验收标准**。

## 0. 先说问题出在哪

现在的课文是这个顺序：

```
学习目标 → 先给结论 → 一个类比 → 工作示例 → 自检 → 重点
```

对写的人来说这很合理：先声明要教什么，再给答案，再解释。
对读的人来说这是**倒着的**。

打个比方。这就像看侦探小说，第一页写着：

> 本章学习目标：理解凶手的作案手法。
> 先给结论：凶手是管家。

后面 20 页你还读得下去吗？读不下去。不是因为文字差，
是因为**悬念被作者自己拆掉了**。

学习和读侦探小说共用同一个心理机关：**你得先有问题，答案才有地方安放**。
没有问题的答案，只是一段需要背诵的文字。

## 1. 方法论的来源

用户提出的直觉——「先抛问题和现象，让人先猜，再讲」——不是拍脑袋，
它和编程教育里被反复验证的做法几乎重合。我没有自己发明方法论，
而是采用了成熟方案：

**主结构用 PRIMM**（Predict → Run → Investigate → Modify → Make）。
2017 年提出，专门针对文本编程教学，是目前英国计算机教育的主流课堂结构。
它的第一步 Predict——先看代码、先预测会发生什么——正是用户说的「先让他答」。

**「先猜再教」有独立的实验支持**：这叫 pretesting effect / prequestion effect。
2025 年的多层元分析给出：针对被预先提问的内容，学习效果 g ≈ .66。
关键细节有两个，直接决定我们怎么写题：

- 增益**主要落在被问到的那个点上**，对没问到的内容效果不稳定。
  → 所以预测题必须**正对这节课的核心**，不能随便出一道。
- **答错也有效**，前提是**紧接着能看到正确答案**。
  → 所以预测题后面必须马上跟解释，不能让人悬着。

**但有一条重要的反向约束**：认知负荷理论和 expertise reversal effect 说明，
**新手在缺少引导的环境里会过载**。所以这里的「先猜」必须是
**低成本、低风险、一道题、马上给答案**，而不是「你自己摸索半天」。
用户的直觉是对的，但如果做成「让学习者自己探索」，对零基础的人是灾难。

一句话总结这三条研究的合力：

> 制造一个**很短**的悬念，让人**猜一次**，然后**立刻、完整地**讲清楚。

## 2. 强制结构（辩体）

每节课按这个顺序。章节标题用下面的原文，不要改写。

### 2.1 标题：必须是一个问题

不是名词短语，是一个**外行看得懂、且会想知道答案**的问句。

| 不合格 | 合格 |
| --- | --- |
| 页面上的空盒子：id="root" | 明明页面上什么都没写，为什么打开却是满的？ |
| package.json 的作用 | 这个项目叫什么名字，是在哪里登记的？ |
| 文件与文件夹 | 一个 App 拆开，为什么是几千个文件而不是一个？ |

判准：**把标题单独拿给一个没学过编程的人看，他会不会想知道答案。**

### 2.2 `## 现象`

先给**可观察的事实**，不给解释。三到五句，必须包含一个具体的、
学习者能自己去看的东西（文件名 + 行号，或一段真实输出）。

目的是把悬念**坐实**：不是「有个抽象概念叫挂载点」，
而是「这个文件第 30 行确实是空的，可你看到的页面确实是满的」。

### 2.3 `## 先猜一下`

**一道题，只有一道。** 正对本课核心。写成 `predict` 类型的 exercise。

- 必须是开放问答，不是选择题——选择题会把答案泄漏在选项里。
- 提示语固定用：**「随便猜，猜错不影响任何进度。」**
  这不是客套，是设计：pretesting 的增益在猜错时同样成立，
  但只有当人真的敢猜时才会发生。
- 这道题**不计入完成度**，也**不进 FSRS**。它是学习手段，不是考核。

### 2.4 `## 答案`

**立刻**给出上面那道题的答案，一到两句，不铺垫。

这一段是整个结构的承重墙。省掉它，前面的悬念就变成了折磨。

### 2.5 `## 为什么是这样`

现在才开始正经讲解。这里可以放原来「先给结论 / 一个类比 / 工作示例」的全部内容，
顺序自由，但要求：

- **类比必须有**，且必须是日常生活里的东西。
- **代码块必须有出处**：紧跟一个 `复制位置` 锚点（见 §3）。
- 超过三段就插一个小标题，不要让人面对一堵墙。

### 2.6 `## 再想想`（可选）

引申一步的问题。可以是 exercise，也可以只是一个问句加答案。
用来把这节课和别的课勾连起来——这是放跳转链接的**首选位置**。

### 2.7 `## 自检`

一到两道 `explain` 类型的题，交给 AI 宿主批改。
这是**计入完成度**的那道。

### 2.8 `## 一句话`

一句话，加粗。不是总结全文，是这节课**唯一**要留在脑子里的那句。

## 3. 正文里的「复制位置」

证据侧栏保留，但**正文里也要有**。规则：

> 正文每出现一个代码块，如果它对应真实文件，
> 就在紧跟的那一行放一个内联锚点。

理由：侧栏是「这节课整体的依据」，正文锚点是「**你现在读的这一句**在哪」。
读到某句想去 IDE 里看一眼的人，不应该被要求先去侧栏里找对应项。

## 4. 跨课跳转

语法：`[[lesson:课程内id]]` 或 `[[lesson:课程id/单元id/课程内id]]`，
可加标签：`[[lesson:xxx|浏览器怎么读 HTML]]`。

设计意图（用户原话「线性 + 网状」）：

- 课程**默认仍是线性的**，下一节永远存在，不跳也能学完。
- 跳转是**邀请，不是分叉**。跳过去能跳回来，回来后继续原来的位置。
- 一节课的跳转链接**不超过 3 个**。超过 3 个就不是网状，是迷路。

放置位置优先级：`## 再想想` > `## 为什么是这样` > 其他。
**不要**放在 `## 现象` 和 `## 先猜一下` 里——那两段的任务是制造悬念，
把人送走等于放弃这节课。

## 5. 不要做的事

- 不要在标题或前两段出现「学习目标」「本课将介绍」。
- 不要在 `## 先猜一下` 之前泄漏答案（包括在标题里）。
- 不要出多于一道预测题。
- 不要把 `## 答案` 往后拖。
- 不要为了套模板硬凑 `## 再想想`。它是可选的。
- 不要把类比写成第二个技术解释。类比里出现新术语就说明它失败了。

## 6. 怎么验收一节课

按顺序问这六个问题，任何一个答「否」就退回重写：

1. 标题是问句，且外行会想知道答案？
2. 读到 `## 先猜一下` 之前，答案没有被泄漏？
3. 预测题正对本课核心，只有一道，且提示了「猜错没关系」？
4. `## 答案` 紧跟在预测题后面？
5. 每个真实代码块都有正文内的位置锚点？
6. `## 一句话` 是一句话，且是本课唯一要记住的那句？

## 7. 为什么不换一套更花哨的

考虑过并放弃的：

- **Gagné 九事件**：完整但太重，九个环节写进每节小课会把课文撑爆。
  它的前三步（引起注意 → 告知目标 → 唤起旧知）已经被本结构的
  标题 + 现象 + 先猜覆盖。
- **5E（Engage/Explore/Explain/Elaborate/Evaluate）**：结构上和本文几乎同构，
  但它是给课堂实验设计的，Explore 阶段假设有教师在场兜底。
  自学场景下会退化成「自己摸索」，正好踩中上面说的新手过载。
- **纯 Use–Modify–Create**：适合有编辑器在手的动手课。
  本项目的课很多是「读懂一个已有项目」，没有 Modify 的位置。

PRIMM 的 Predict/Investigate 两步是我们真正需要的，
Run/Modify/Make 在「读懂别人项目」的场景里没有对应动作，因此不强制。
