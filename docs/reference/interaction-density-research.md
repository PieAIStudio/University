# 互动密度研究：要不要把课改成「互动为主、讲解为辅」

这是一份研究与评估，不是裁决。裁决要 Owner 下，下完之后应该落成 ADR。
本文只做三件事：把现状量出来、把「多邻国那套」拆开看清、给出一个我认为对的方向和它的代价。

## 0 一句话

**该改，但要改的不是互动的数量，是互动的「单位」。**

现在的课不是互动太少——active 的两门 AI 课 100% 每节都配了互动件。
问题是：**一节课里读者只有 2 次真正需要产出答案的动作，而第一次出现在第 559 个汉字之后。**
互动件本身做得很好，但它是 3 分钟的「关卡」，一节课只塞得下一个，
于是它无法承担节奏，只能当句号。**缺的是 5–15 秒的「节拍」这一层，它现在一个都没有。**

---

## 1 现状：量出来的，不是感觉

以下全部由本次实测得出（2026-09-16，扫描 `apps/local/studies/*/courses/**`，只取每节最新修订）。

### 1.1 互动覆盖率

| study | 课节数 | 有 `::play` | 课程状态 |
| --- | ---: | ---: | --- |
| `turing-pact` | 362 | **0（0%）** | 32 门中 3 门 active，其余 stale |
| `ai-literacy` | 66 | 66（100%） | 2 门全 active |
| `ai-foundations` | 61 | **0（0%）** | stale |
| `browser-ai` | 27 | 27（100%） | 4 门全 active |
| `general` | 19 | **0（0%）** | stale |
| **合计** | **535** | **93（17.4%）** | |

**先纠正一个可能的误读**：如果 Owner 读到「互动太少」的那门叫「AI 基础」的课，
指的是 `ai-foundations`（《AI 到底是什么》），那门课是 **stale 且一个互动件都没有**；
如果指的是刚发布的 `ai-literacy`（《认识 AI，从这里开始》《用 AI，把日常事情做好》），
那门课是 **100% 每节都有互动件**。

**两种情况都指向同一个结论，而且后一种更要紧**：
即使做到了每节一个互动件，读者仍然觉得互动太少。
所以这不是覆盖率问题，**覆盖率已经到顶了**。

### 1.2 一节课里读者到底动了几次手

以 `ai-literacy` 66 节为准（中位数）：

| 事件 | 次数 | 性质 |
| --- | ---: | --- |
| `::play` 互动件 | 1 | **产出型**（要给出答案） |
| 正文下方 exercise | 1 | **产出型**（打字） |
| `:::detail` 展开 | 2.9 | 揭示型（点开就看到答案，不算回想） |
| 「我读完了」 | 1 | 确认型 |
| 卡片 | 2–3 | **明天**才进 FSRS 队列，不在本节内 |

**一节课内的产出型事件：2 次。**

- 正文汉字中位数 **980**（`browser-ai` 1772）；
- `::play` 出现在全文 **55%** 的位置，它之前有 **559 个汉字**；
- 也就是说：**读者要先读大约两分钟，才被要求第一次表态。**

### 1.3 已经设计好、但被写成散文的两个互动时刻

`write-lesson` 的课文骨架里，每节固定有这两段：

```
## 先猜一下     ← 恰好一道，低成本 —— 100% 的课都有
## 答案
...
## 自检         ← 换输入/条件/例子，只提问不给答案 —— 100% 的课都有
```

**这两段都是纯文字，没有输入框、没有提交、没有判定、没有反馈。**
课文原话是「先写下你的判断，再往下看答案」——然后读者往下滚，答案就在那里。

这是整份报告里杠杆最高的一处：
**教学设计已经在正确的位置放了两个回想点，产品把它们实现成了排版。**

### 1.4 已经写进 schema、但一条都没用上的两样

| 能力 | schema | 实际用量 |
| --- | --- | ---: |
| `choice` 选择题 | `ChoiceExerciseSchema` 已存在，并已带「三选项 / 正确 id 必须在列 / id 不重复 / **每个选项都要有解释**」四条校验 | **0 道**（968 道 `short-answer` + 123 道 `explain`） |
| `cloze` 挖空卡 | `CardContentSchema.kind` 明确是 `z.enum(["basic","cloze"])` | **0 张**（2109 张全是 `basic`） |

`ChoiceExerciseSchema` 没被用，不是没人想用——它**被故意排除在 `ExerciseSchema` 的 union 之外**，
注释写着「等作者与恢复流水线学会第三个分支时再并进来」。
于是现实是这样的：一道题干写着**「请抄写一个选项」**，读者要手打「核对新素材的具体条件」这九个字，
而「三选一 + 每个错项各自解释」的引擎早就写好躺在隔壁。

这正是记忆里那条「a wire schema can veto a shipped feature」的同一个形状，
只不过这次被否决的不是一个功能，是**整整一类互动**。

### 1.5 互动件的成本与用量是反着的

`learning-play/README.md` 自己量过，本次复核成立：

- 便宜的四种（`sort` / `contrast` / `weigh` / `connect`，渲染器合计 **795 行**）扛了 27 个落点里的 **21 个**；
- 贵的四种（合计 **3684 行**）扛了 **4 个**；
- 三种（`program` / `ai-brief` / `hunt`，合计 **1712 行**）**一次都没被用过**。

原因 README 说得很准：贵的四种要求「这节课恰好在讲一台有状态的机器」。
**这不是缺陷，这是这些玩法本身的教学内容。** 但它意味着一件事——
把十三种排成一张等长的表，会让人以为选择是均匀的，而实际的选择面是「四种 + 九种备用」。

## 2 把「多邻国那套」拆开

多邻国之所以让人想起来，是因为它同时做对了三件互相独立的事。**混在一起谈会做错决定。**

### 2.1 第一层：节奏（这层该抄）

多邻国一节 5–10 分钟，里面是 **12–15 道**快问快答，散文是零。
换算下来：**每 25–40 秒一次输入。**

University 现在：**每 2–4 分钟一次输入。**

差的是一个数量级。这一层和游戏化无关，和连胜无关——
**它只是把"讲解"这件事，改成用"一连串小题"来传输。**

### 2.2 第二层：元游戏（这层已经有了，边际收益有限）

连胜、宝石、排行榜、能量。这是把留存做成一个独立系统。
University 已经有 `QuestsScreen`、streak、counters——**这一层不是当前瓶颈。**

而且要说清楚：多邻国是**免费海量漏斗**，元游戏的边际收益极高。
University 是**付费、高意向、成人**。对这类用户，
「我今天是不是真的学会了一件事」比「我连胜第 47 天」更能防流失。
**不要把元游戏当成这次的答案。**

### 2.3 第三层：学科（这层不能抄）

**多邻国教的是「形式」，University 教的是「判断」。**

语言学习的原子单位是可以被上百次重复自动化的东西：词、语序、性数一致。
重复本身就是教学法，所以练习即学习。

「该不该在 agent 提交前叫停」没有这个性质。
**判断不能靠重复变成流利，它靠的是见过足够多、足够不同的情境，并且每次都被纠正。**

所以照抄多邻国的**粒度**是对的，照抄它的**重复模型**是错的：
University 的 7 个节拍必须是 **7 个不同的情境**，不能是同一个判断问 7 遍。

### 2.4 真正的对标不是多邻国，是 Brilliant

| | 多邻国 | **Brilliant** | University 现状 |
| --- | --- | --- | --- |
| 受众 | 免费海量 | 成人、付费 | 成人、付费 |
| 内容 | 语言形式 | 概念与推理 | **判断** |
| 一节 | 5–10 分钟 / 12–15 题 | 5–15 分钟，**整节就是一串题** | 5–10 分钟 / **2 次输入** |
| 顺序 | 练即学 | **先出题，后讲解**（pretest 在前） | 讲解在前，题在后 |
| 反馈 | 即时二值 | 即时 + **答错后的解释本身也是可交互的** | 即时（tier-1） |

Brilliant 的「先让你试，再告诉你怎么做」——**University 的「先猜一下」就是这个东西**，
只差一步没做：没让读者真的按下去。

结论：**要的是 Brilliant 的结构 + 多邻国的节奏感，不是多邻国的元游戏。**

## 3 建议的模式：三层，而不是「互动 vs 讲解」

「互动为主、讲解为辅」这个说法本身有歧义。我建议把它定义成下面这个具体形状：

| 层 | 名字 | 单次时长 | 每节数量 | 它负责什么 | 现状 |
| --- | --- | --- | ---: | --- | --- |
| **L1** | **节拍 beat** | 5–15 秒 | **6–9** | **承载讲解本身** | **不存在** |
| L2 | 关卡 play | 2–5 分钟 | 0–1（或每单元 1） | 综合应用、本节高潮 | 13 种，已成熟 |
| L3 | 卡片 + 练习 | — | 2–3 卡 + 1 练习 | 跨天留存、独立判分 | 已有，但形态该改 |

**「互动为主」= L1 成为课文的主干，散文降级为节拍之间的连接组织。**
不是删掉讲解，是**把讲解切成读者必须逐段"买票"才能通过的段落**。

### 目标数值

| 指标 | 现在 | 目标 |
| --- | ---: | ---: |
| 每节汉字 | 980 | 600–700 |
| 每节产出型输入 | 2 | 7–10 |
| 首次输入前的汉字 | 559 | **≤ 80** |
| 两次输入之间最长汉字 | ~450 | **≤ 120** |
| 阅读 : 操作 时间比 | ~85 : 15 | ~45 : 55 |

## 4 建议新增的 8 个微互动件

判断标准：**5–15 秒能做完、没有"玩法"需要先学、判题完全确定性（tier-1，零 AI 成本）、
能用本节课文已经给出的材料回答。**

### 第一批：零新判断，纯机械迁移（每节输入从 2 → 4）

**1. `predict` 预测** — 把 `## 先猜一下` 变成 2–3 选一的**锁定式**提交，锁定后才展开「答案」。
- 为什么最高杠杆：**100% 的课已经有这一段、已经写好了这道题**，内容一个字都不用新写。
- 心理学依据：hypercorrection effect——自信地答错再被纠正，比直接读到正确答案记得牢；
  以及好奇缺口（Zeigarnik）——现在课文把"把问题悬在心里"这件事外包给了读者，没有人会照做。

**2. `verdict` 判断** — 把 `## 自检` 变成「对 / 错 / 取决于」的即时判定。
- 同样 100% 已存在。注意：`自检` 现在规定「只提问，不给答案」，
  改成 `verdict` 后它会给答案——**这与"独立练习"的判分边界冲突，需要 Owner 明确**（见 §8）。

### 第二批：打开已经写好、但被封着的两样

**3. `choice` 选择题** — 把 968 道 `short-answer` 里题干本身就是二选一/三选一的那些，
   改成真正的选择题。
- 现在「请抄写一个选项」这种题，打字是纯摩擦，没有任何教学收益。
- 引擎和校验（含**每个错项必须有自己的解释**）已经写好，缺的是把它并进 `ExerciseSchema` 的 union，
  以及让 `apps/local` 的作者/恢复流水线认第三个分支。

**4. `cloze` 挖空卡** — 2109 张卡全是「正面问题 / 背面答案」的翻面卡。
- `cloze` 已在 schema 里。挖空是**产出**，翻面是**再认**——
  再认的记忆收益显著低于产出，而成本一样。
- 这也是多邻国词库拖拽的同一个机制。

### 第三批：真正的新形状（针对「判断」这门学科）

**5. `spot` 圈出** — 在一段 AI 回答 / 提示词 / 来源里，**点出有问题的那一句**。
- 这是 AI 素养课最缺的动作。现在课文教「要核对出处」，
  但读者从头到尾**没有做过一次核对**。`spot` 让"核对"变成一个手上动作。
- 适配面极广：所有"溯源"和"现象"变体。

**6. `order` 排序** — 把 3–5 个步骤拖成正确顺序。
- 例：「先出草稿 → 列出要提交的内容和接收对象 → 等我确认 → 才提交」。
- `program` 是网格走位，不是步骤排序，覆盖不到这个形状；而"步骤顺序"是 469 节课里到处都是的教法。

**7. `scale` 刻度** — 「你有多信这个回答？」拖一下，再揭示依据与判断标准。
- 教的是**校准**，这是 AI 素养的核心能力之一，目前一个组件都没覆盖。
- 注意：**必须只在课文里真有一个连续量的时候用**——
  这正是 repo 自己踩过的那个坑（`hunt` 被配在定性课上，0–10 刻度是为了配组件现编的）。

**8. `swap` 改一处** — 给一句指令 + 3 个候选词块，换掉让它出错的那一处。
- `ai-repair` 的微型版：943 行的引擎教的判断，用 15 秒也能练一次。

### 对应关系速查

| 课文在做的事 | 现在有的 | 建议的节拍 |
| --- | --- | --- |
| 提出一个悬念 | 散文 | `predict` |
| 划界 / 归类 | `sort`（关卡） | `sort` 的单格版，或 `verdict` |
| 对照两种做法 | `contrast`（关卡） | `choice`（两选一 + 各自解释） |
| 找出毛病在哪 | 无 | **`spot`** |
| 讲清先后顺序 | 无（`program` 不是） | **`order`** |
| 教"多大算多" | `tune` / `hunt`（关卡，要求有真数） | **`scale`** |
| 修一句话 | `ai-repair`（943 行） | **`swap`** |
| 记住一个判断 | `basic` 卡 | `cloze` 卡 |

## 5 现有 13 种怎么处置

- **便宜的四种**（`sort` / `contrast` / `weigh` / `connect`，795 行扛 21/27）→ **保留，作为 L2 主力。**
- **贵的四种**（3684 行扛 4 个）→ **保留，但降级为"单元收尾关"**，不再追求每节都配。
  它们的价值在于"这一单元学完之后综合跑一遍"，不在于每节点缀。
- **零使用的三种**（`program` / `ai-brief` / `hunt`，1712 行）→ README 说这个决定悬着。
  **我的建议：不退役，但把它们从"互动覆盖率"的分母里拿出来。**
  理由：在三层模型下，节拍的需求量是 ~535 × 7 ≈ 3700 次，关卡的需求量仍是 ~500 次。
  工程预算应该全部押在 L1，而不是再造第 14 个关卡引擎。

**关键一句：不要把新节拍做成第 14、15 种 `ActivityKind`。**（原因见下一节。）

## 6 挡在路上的三处结构性约束

这三处不解决，上面全部做不成。它们都在 schema 层，都不是"加个组件"能绕过去的。

### 6.1 `activities` 被硬性限制为最多 3 个

```ts
activities: z.array(LessonActivitySchema).max(3).default([])
```

注释写得很清楚，理由是：**「一节小课里放第二个游戏，读者的注意力会花在学玩法上，
而不是花在这个游戏讲的东西上。」**

**这个理由对 3 分钟的关卡引擎完全成立，对没有玩法要学的节拍完全不成立。**

所以**不要去改那个 3**。要新开一层——节拍是另一个 schema、另一个字段、另一套合同。

### 6.2 每个 activity 的必填合同太重

`LessonActivitySchema` 要求：`title` + `brief`（≤2000 字）+ `goal` + `takeaway` + `hint` + `source`（真实出处）+ `role` + `difficulty`。

**一个 5 秒的节拍扛不动这份合同。** 硬塞的结果一定是模型编出六段废话来填字段——
这正是 repo 自己记录过的失败模式（「玩法的必填字段这节课没有对应的真事，
那是为了配而配」）。

节拍的合同应该只有：**题干 / 选项（每项带解释）/ 正确答案 / 它锚在课文哪一段。**
出处继承所在段落的 evidence，不单独要求。

### 6.3 `ChoiceExerciseSchema` 被排除在 union 之外

已在 §1.4 说明。解开它需要动 `apps/local` 的作者与恢复流水线，
这是一次**真实的迁移工作**，不是改一行枚举。**但它是第二批里最值钱的一件。**

## 7 三个角度的账

### 7.1 心理学

| 机制 | 效应量 | 在这里意味着什么 |
| --- | --- | --- |
| 提取练习 vs 重读 | g ≈ 0.50（Rowland 2014，159 项研究）；g ≈ 0.61（Adesope 2017） | 把"读到答案"换成"先答再看答案"，收益是半个标准差量级 |
| 生成效应 | d ≈ 0.40（Bertsch，86 项研究） | 自己产出的内容比读到的内容记得牢 |
| 提取练习的**迁移** | d ≈ 0.40 | 关键：迁移只在"应用题和推理题"上出现，**在"学过但没考过的内容"上不出现** |

最后一行是这次最重要的约束：**练过的判断会迁移，没练过的不会。**
所以节拍不能只挑好出题的点，要挑这节课**真正想让人会做的那个判断**。

**一个必须点名的陷阱**：`:::detail` 每节 2.9 个，点开就看到答案。
**这是再认，不是提取。** 如果用"点击次数"来衡量互动，
把 detail 做多会让指标变好而让学习变差。
（记忆里那条 `name-the-gate-not-the-number` 在这里直接适用。）

### 7.2 游戏设计

**多邻国的核心循环是节奏游戏，不是解谜游戏。**
它的乐趣单位是"节拍"——一个 3 秒、几乎保证成功或立即纠正的微动作。
连续的节拍产生心流；心流靠的是**动作与反馈之间的间隔足够短**。

University 现在的循环是**解谜游戏**：一节课一个 3 分钟、认知负荷高的关卡。

问题不在于解谜不好，而在于：**1000 字散文 + 一个解谜，既不是节奏也不是解谜，
它是一本教科书加一道附录题。**「互动太少」是一个**节奏**投诉，不是**数量**投诉。

另一件游戏设计的事：**13 个重引擎 × 3 档难度，是一个很深的系统，但没有浅水区。**
多邻国前 10 题几乎白送。University 目前**没有任何一个"免费的节拍"**——
读者第一次被要求表态时，面对的就是一个要学规则的关卡。

### 7.3 商业

- **成本**：节拍全部确定性判题，在浏览器里跑完，**tier-2 AI 花费为零**。
  把互动提高 7 倍，AI 账单不变。这与 V5 里"每天 400 power units 免费额度"的漏斗设计不冲突。
- **已有证据**：便宜的四种（795 行）扛了 78% 的落点，贵的四种（3684 行）扛了 15%。
  **"便宜且贴合内容的组件赢"这件事，repo 自己已经量过一次了。** 节拍比它们还便宜。
- **迁移成本**：535 节课。但第一批（`predict` + `verdict`）**段落已经存在**，
  是可脚本化 + 模型批改的机械迁移；真正需要新判断的是第三批。
- **留存**：对付费成人产品，**不要把这件事卖成"更好玩"**。
  它同时提高感知节奏（防止中途弃读）和实测留存（提取练习的效应量）。
  两个都说，比只说一个诚实。

## 8 反对意见（必须一起读）

**1. 把判断降解成琐碎题。**
repo 已经踩过一次：`hunt` 被配在一节讲定性判断的课上，载荷里 0–10 的刻度是为了配组件现编的，
而**所有闸门全绿**。节拍更便宜 ⇒ 这个失败模式会更频繁、更难发现。
**防线**：每个节拍的干扰项必须是一个**真实误解**，并各自带解释——
`validateChoiceExercise` 已经强制这一条，是现成的、写好的防线。

**2.「真实来源」这个卖点是散文形状的。**
provenance / supports / limitations 天然是文字，这是 University 区别于一个答题 App 的地方。
**防线**：节拍不取代出处；很多时候节拍本身就是「这条来源到底支持哪一句」——
那反而让出处从装饰变成考点。

**3.「自检」改成判题会撞上完成合同。**
V5 明确「读完与答对是两盏灯」，且「演示型课件不能替代独立作答」。
`verdict` 化的自检**会不会被算作已答**，是一个必须由 Owner 明确的边界，不能由实现顺手决定。

**4. 535 节课的重写是真实成本。**
不要假装第一批是免费的——它仍然需要逐节复核"这个预测题的三个选项是不是三个真实误解"。

**5. 我没有证据说这更好玩。**
本文所有数字是**结构**数字。没有一个真人试学过节拍化的课。
README 自己写过同一句话：通关数和点击数**推不出**"觉得好玩、能举一反三、延迟后还记得"。

## 9 建议的落地顺序与闸门

| 阶段 | 做什么 | 每节输入 | 需要的决定 |
| --- | --- | ---: | --- |
| 0 | 定义 beat schema（独立于 `LessonActivitySchema`），一个渲染器 + 一条 e2e | 2 | 要不要做 |
| 1 | `predict` + `verdict`，在 **1 门 active 课**上全量迁移 | 4 | §8.3 的完成合同边界 |
| 2 | `choice` 并进 union；`cloze` 卡开用 | 5 | 流水线迁移预算 |
| 3 | `spot` / `order` / `scale` / `swap` 四个新形状 | 7–10 | 是否值得再投 4 个引擎 |
| 4 | 回头处理 `program` / `ai-brief` / `hunt` 的去留 | — | 由"接下来写哪些课"定 |

**先在一门课上做完整的一轮，不要 535 节一起改。**

### 闸门怎么设（以及怎么不设）

可以机械检查的：
- 每节 beats ≥ 6；
- 任意两次输入之间的汉字 ≤ 120；
- 首次输入之前的汉字 ≤ 80。

**但只设这三条一定会出事**——它们会被"把一道好题拆成三道废题"满足。
必须同时设的伴随闸门：
- 每个 beat 的每个干扰项都有非空解释（复用 `validateChoiceExercise`）；
- beat 的正确答案不得在其上方 200 字内以原文出现（防止"刚说完就问"）；
- **每门课仍然保留"一个人读一节"这一步**——
  repo 已经证明过，"这个游戏是不是关于这节课的"没有任何机械检查能看见。

## 10 需要 Owner 拍板的三件事

1. **「互动为主」是否按 §3 定义**——即 L1 节拍成为课文主干，而不是把关卡数量从 1 提到 5。
2. **`自检` 节拍化之后，和"独立练习"的判分边界怎么划**（§8.3）。这会碰 V5 的"两盏灯"。
3. **工程预算押 L1 还是继续补 L2**——三种零使用的关卡引擎（1712 行）是留是退，

## 11 做出样板之后被推翻的一条（2026-09-16）

上面 §4 列的 8 个微互动件里，有一个是错的：**`cloze` 挖空 / 拼句子那一类，不该进这个产品。**
这是做完可玩样板、Owner 指出来之后才看清的，记在这里，因为错法比结论有用。

### 判断一个互动件成不成立，只有一把尺子

> **玩家手上那个动作，和这节课要教的那个判断，必须是同一个动作。**

拼句子在语言学习里成立，因为**手在排词序，学的就是词序**——动作即目标。
搬到 AI 素养课上就散架了：手在拼图，而课要教的是「分辨哪一句要求能用」。
动作和目标脱钩，剩下的只有多邻国的外形。

样板第一版里，L1 和 L4 各有一拍是拼句子。两拍都通过了「每节 ≥6 拍」这类闸门，
读起来也像互动——**这正是 §8.1 那条反对意见成真的样子，而且是我自己踩的。**

### 换上去的那个东西，是这个产品独有的

多邻国没有、也不可能有的一件事：**AI 会回应你。**
所以 AI 学习有一种别的学科拿不到的原生互动：

> **你动一处输入，当场看见输出怎么变。**

它的形状不是拼词，是**象棋残局**：给你一个局面，走一步，看对手怎么应。

样板里叫 `lab`（组装台），两处落地：

| | L1「指令台」 | L4「图注台」 |
| --- | --- | --- |
| 玩家动的 | 四条要求的开关 | 六项图注信息的勾选 |
| 当场变的 | AI 的回复 | **读者看完以为这是什么** |
| 藏在里面的那一下 | 只勾「三项核对」时，它回「日期✓ 地点✓ 开始时间✓ 三项齐全」——**而玩家上一拍刚亲手核出开始时间没了** | 勾了标题+摄影者+日期（每一项都真），读者仍然以为这是**完整**照片——**因为你裁过** |
| 对应课文里哪一句 | `:::detail[它逐项打了勾，就真的检查过了吗？]` | 「两种身份必须让读者分得开」 |

左边那两格是关键：**原本折叠在 `:::detail` 里的一段散文，变成了玩家亲手触发的一个后果。**
它不再是「读到一个道理」，是「抓到 AI 在打勾糊弄我」。

### 重排后的组件清单

| 组件 | 手上的动作 | 教的判断 | 状态 |
| --- | --- | --- | --- |
| `lab` 组装台 | 改一处输入 | 同一个模型，要求不同，答案就不同 | **新增，最高优先** |
| `press` 按一下 | 亲手按出一个荒谬结果 | 合计算对了，表还是错的 | 成立 |
| `spot` 圈出 | 逐项核对，点出缺的那项 | 检查是一项一项过，不是整体感觉 | 成立 |
| `predict` 预测 | 在讲解之前先押一个 | 你押的那个标准本身是错的 | 成立 |
| `bucket` 分堆 | 归类 | 分界线在哪 | 成立 |
| `rows` 归位 | 给每行选回单位 | 它们从来不是同一种东西 | 成立 |
| `scale` 刻度 | 给自己的把握打分 | 把握和记录不换算 | 成立 |
| `cloze` / 拼句子 | 排词序 | —— | **退役：动作与目标脱钩** |

### 还该从别的学科偷的（Owner 提的那条线索）

多邻国不止有语言，它还有数学和音乐；棋类平台还有残局。这几个形状值得改造：

| 来源 | 原形状 | 改造成 AI 素养的什么 | 备注 |
| --- | --- | --- | --- |
| 棋类 残局 | 给一个局面，走一步，看应手 | **`lab` 的多回合版**：一段对话中局，你回一句，它答一句，三回合内拿到能核对的东西 | 已做单回合版 |
| 数学 数轴 | 把一个数放到刻度上 | 把一句话放到「事实／推论／猜测」的刻度上 | `scale` 的升级 |
| 数学 涂格子 | 给分数涂面积 | **在一段 AI 回答里涂出「有出处」和「没出处」的比例** | 见下方的约束 |
| 数学 天平 | 两边配平 | 证据天平：证据放两边，看结论压向哪边 | 未验证 |
| 音乐 听音配谱 | 声音↔记号配对 | 把 AI 的说法和原文逐条配对 | `spot` 的变体 |

**「在回答里点出没有出处的那一句」这个组件，这一轮故意没有做。**
它需要课文自己提供一段真实的、多条断言的 AI 回答；`ai-literacy` 的幻觉那一节
明确写了「我们不需要再编三个假题名」，硬凑就得伪造一段回答。
这正是本项目已经记录过的那个失败模式：
「玩法的必填字段这节课没有对应的真事……那是为了配而配。换一种，或者不配。」
所以它留在清单上等一节真有这种材料的课，不在这一轮硬塞。

### 样板在哪

`docs/reference/interaction-prototype/index.html`——四关二十拍，可直接打开玩。
内容是 `ai-literacy / understanding-ai` 单元「看懂回答，不被语气带走」的四节真实课文，
出处为真实公开记录（OpenAI sycophancy 回滚、OpenAI 幻觉研究、史密森尼开放数据、
Google Gemini 图像暂停、NASA《地出》）。它证明的是形态成立与规则跑得通，
**不证明真人觉得好玩**——那仍然需要真实试学。
