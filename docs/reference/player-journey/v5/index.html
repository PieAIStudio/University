裁决 B · 练习的 tier-2 是窄例外，不是「学习者文字自动出网」

01读完和答对，是两盏不同的灯

当前模型已经把这两个事实分开：readConfirmed 记录学习者确认读过， exercisesPassed 记录所有练习通过。问题在于交互还曾经把它们从一个事件一起写下去， 于是「跳到题目并猜对」看起来像完成了阅读。

决定 · 两个动作，最后才合成「完成」

学习者读到课文底部后，看到一个明确的「我读完了」动作。它只写 readConfirmed = true，不替任何练习判分。

练习提交只写对应的答案和判分记录。即使全部答对，也不能替读完动作盖章； 即使确认读完，也不能跳过练习。只有 readConfirmed 和 exercisesPassed 都为真，地图、结算和 XP 才把这节课当作完成。

2026-09-09 · 每一小节的教学闭环

每节围绕一个真实问题或任务，不强制制造反常。开场提供可观察的材料与必要词义； 每节必须有一道紧扣核心的“先猜一下”，读者能据开场作有理由的初步判断，不要求已经知道答案。 紧接着解释，不以答对预测作为继续阅读的条件。删除“答案”以下内容后，核心问题仍应未被揭晓。

五种变体按内容选择，中段面向读者讲清原因、差异、路径、取舍或术语边界。 自检／独立练习更换输入、条件或例子，检验能否自己应用，不要求换整个项目。 互动课件可用于开场观察、中段示范或独立应用；看过／操作过演示不能顶掉独立练习或自动完成课程。

正文顺序以“一句话”收尾；正文中的“自检”只提问，独立exercise仍由正文下方的练习区判分并反馈。 本轮不把exercise嵌入Markdown或移动阅读器控件，也不改“两盏灯”的完成合同。 可选“再想想”是正文跨课链接的唯一位置，放在中段之后、自检之前，最多三个链接。

无仓库课程使用已核实的官方资料、真实系统或可复现操作支撑白话讲解，明确事实、推论与示例； 文档规定不冒充本次运行结果。完整编写规范与机器／人工检查分工见 write-lesson。 本约定用于后续创作与修订，不表示已按此重写所有现有课文。

02「讲一遍」是复习卡，不是知识笔记

作者需要把真实、有证据的知识写进课程；学习者需要把刚学到的东西用自己的话说一遍。 两者都叫「笔记」会把内容生产和学习记录混成一件事，V5 把它们拆回各自该在的地方。

知识笔记讲一遍
谁写作者，通过 capture CLI学习者，在课后或复习时

决定 · 一句提示、一个输入框、一张会回来的卡

读完一节课或完成一个 explain 练习后，给学习者一个提示： 「请用自己的话，讲给一个完全不知道这件事的人听。」 提示来自该单元已有的第一人称能力句，不新增作者工作。

默认输入是文字。提交后答案成为一张 FSRS 卡；到期时再次问同一个问题， 把这次答案和之前的答案并排给学习者看，由学习者自己选「again / hard / good / easy」。 保存本身不是学习，回来再答才是这个功能存在的原因。

不做 · 选择题和 AI 判卷都不是默认答案

选择题把「生成一个解释」换成「认出一个选项」，少了这条路径真正要练的东西。 AI 判学习者的复述则会给免费层带来无法封顶的模型成本，也会把「我怎么理解」变成一个外部裁判的问题。 V5 先让学习者生成、重看、再生成，并且不替他假装判断。

决定 · 边界看载荷，不看「本机 / 在线」这个标签

「在线」不自动等于不允许，「本机」也不自动等于可以把任何数据塞进去。 判断顺序是：先问这段东西是谁选的、属于谁；再问实现它需要哪种传输。 产品选定的 word 是课程材料，所以浏览器的云端声音可以读它。

学习者的写作、声音和私有仓库文字属于学习者，默认留在本地。 这条许可只覆盖「读一个产品单词」，不覆盖「收集学习者的解释」。

TTS · 四档已经定了

packages/ui/src/language/speech.ts 现在把本机和在线英语声音收集后再做新奇音色过滤与排序， localService 只负责判断它属于哪一档，不再把在线声音一刀切掉。 设置存的是学习者的请求，不存某次运行的解析结果。

设置含义存什么拿不到时
自动每次按当前能力选最好的可用层级永远存 auto 这个请求每次重新尝试：高品质 → 在线 → 本机
本机只用本机英语声音存 local向下退无可退，显示没有可用本机语音；绝不静默改用在线
在线可以使用浏览器提供的云端英语声音存 online浏览器没有云端英语声音时，说明原因并按既定降级规则处理
高品质付费高品质声音存 premium 请求钱包和权益接入前置灰；付款后自动请求仍能重新解析到它

这里已经关掉的三个坑

第一，自动不是一次性答案。今天只有本机声音，明天登录后有高品质权益，或浏览器后来暴露了新的在线声音， 都应该在下一次使用时生效；把「自动」写成「本机」会把学习者困在过去的能力上。

第二，本机是明确选择。学习者手动选「本机」时，不能因为本机暂时没有声音就偷偷改走网络。

第三，高品质不是假装存在。钱包还没接好时把它显示为不可用，并解释是权益尚未接入； 不把一个没有兑现路径的付费承诺伪装成普通声音。

ASR · 仍然开放，而且正因为新规矩才开放

这不是「旧规矩还在」

浏览器实现 Web Speech API 的方式会把音频送到服务商：Chrome 和 Edge 的语音识别会把声音流向 Google 或 Microsoft。 Firefox 则根本没有实现这套能力。两件事都不能被一个「浏览器支持，所以打开」的判断抹平。

这个产品最常见的口述不是干净的单语句子，而是普通话夹着英文标识符；这是 ASR 最弱的场景。 学习者复述的主题还可能是 turing-pact 这样的真实私有仓库——他是在说自己的数据， 不是在朗读产品挑出来的一个词。

所以 ASR 不是被「语音不能出网」挡住，而是被新边界保留下来：学习者说的话需要单独、明确的选择加入。 TTS 放开之后，这个问题没有被顺带回答。

ASR 未来要先回答的五个问题

  1. 去哪处理：本机识别、哪一种在线服务，还是两者都给；不能把浏览器实现误说成本机。
  2. 什么时候同意：在第一次收音前说明会发送什么、发给谁、为了什么，且不能用 TTS 的同意代替。
  3. 保存什么：原始音频、转写文字、还是只在本机临时使用；保存与否、保留多久、怎么删除都要明说。
  4. 识别失败怎么办：Firefox 没有能力时给文字输入；中英混杂时不能把错误转写当成学习者说错。
  5. 学习者能否反悔：取消、拒绝和关闭后都不能留下一个已经上传却没有说明的录音。

怎么验

  • TTS 的载荷：点击「听发音」只给合成器一个产品选中的英文单词，不把复述框、读者标记或仓库文字拼进去。
  • TTS 的设置：四个值能持久化；自动持久化为请求而不是解析出的层级；高品质在钱包未就绪时不可用且有解释。
  • ASR 的门：当前没有任何「听发音」动作会打开麦克风；未来 ASR 进入产品前必须有单独的选择加入界面。
  • 浏览器差异：Firefox 走文字复述；不能用「没有按钮」掩盖能力不存在，也不能把 Chrome / Edge 的在线实现叫成本机。

05施工顺序与完成线

  1. 分离读完与答对。阅读器只在明确动作上写 readConfirmed，练习只写自己的 attempt 和 verdict。
  2. 落地「讲一遍」文字路径。使用单元现有能力句，保存到学习者文档，接入已有 FSRS，不新增模型调用。
  3. 保持 TTS 四档。所有调用经过共享 speech.ts 的声音选择；自动存请求，手动降级可解释，高品质等钱包。
  4. 单独设计 ASR 选择加入。先做载荷、目的地、处理位置、保存和删除的决定；决定前不接麦克风，不把「开放」写成已上线。
  5. 加入计量 tier-2。仍只通过 GradingPort；先过免费 tier-1，服务端验证 token 后按账号和 UTC 自然日读取并原子 reserve 每日免费额度，走 structured output 后 commit/refund；额度用完安静回到 tier-1 并说明明日恢复，钱包只有在学习者另选付费时才 reserve，任何情况下都不隐藏入口或把它禁用。
  6. 双模式逐屏对齐。本地与交付模式共享学习者面、课后提示、文字输入、复习卡和 TTS 设置；AI 来源、课文材料来源、以及能否触达课文背后的源码仓库，分别留在 GradingPort、ContentPort/ReaderPort、SourceAccessPort。能力缺席时照常显示入口并解释原因与未来支持路径。
  7. 按证据长度呈现。短仓库引文在正文中直接展开；长引文保留芯片、reference panel 和 full-source sheet。切分由共享策略常量决定，不能在两个模式各写一套。
  8. 把提醒放到价值兑现之后。结算页先说「明天有 N 张复习卡到期」，再显示一张普通的应用内预提示；只有学习者点击「好」才请求浏览器权限，点击「以后再说」不消耗机会。

06提醒要在明天的卡片之后出现

FSRS 已经排好了明天的工作，但提醒不是学习者打开首页时该付出的代价。 只有当结算页刚刚把「明天有几张卡」说清楚，提醒才有一个学习者能判断的价值。

决定 · 先用产品自己的卡问一次，再问浏览器

学习者完成一节课后，结算页必须先显示真实的明日卡数。若当前浏览器尚未开启提醒，紧接着显示普通应用内卡片： 「明天有 N 张复习卡回来。要我提醒你吗？每天最多一条，有卡才提醒，随时可以在设置里关掉。」 卡片只给「好」和「以后再说」；它不是系统权限弹窗。

点击「好」才执行 Notification.requestPermission()，并在同一个用户动作里注册 Service Worker、创建 Push 订阅、把订阅信息写进学习者文档。 点击「以后再说」只收起这一次卡片，不写浏览器权限，也不把学习者永久标成拒绝；下次又完成有明日卡的课程时还能再问。

不做 · 页面加载、首页、注册后都不问

首页打开、注册完成、刷新页面和普通设置加载都不会自动调用权限请求，也不会自动弹预提示。 浏览器已经返回 denied 后，结算页永远不再自动出现预提示；设置页保留入口，但只说明「浏览器已拒绝，请到浏览器的通知设置里改」——不反复调用一个已经被拒绝的请求。

学习者看到的状态控件怎么做必须说清楚什么
未开启设置里显示「打开复习提醒」；点击才进入权限流程每天最多一条，只在有到期卡片时提醒
浏览器已拒绝不再自动弹；设置里保留可见入口和人工处理提示浏览器已经拒绝，需要去浏览器通知设置里开启
已开启、已订阅设置里显示可关闭的开关「已订阅，但服务端还没接上，暂时不会真的收到提醒」
iPhone 普通 Safari 页面显示能力说明，不给按下去没反应的开关「在 iPhone 上需要先把它添加到主屏幕」
当前浏览器不支持显示能力说明，保留提醒位置说明可以继续用应用内复习，不假装已经能推送

平台事实 · iPhone 仍需要 Home Screen web app

Apple 当前开发者文档写明：iOS/iPadOS 16.4 及以后支持 Web Push，但适用对象是已经添加到主屏幕的 Home Screen web app；普通 Safari 页面不在这个能力范围内。 WebKit 的原始说明还要求权限请求来自直接用户操作。University 因此用能力检测判断「主屏幕 web app」，不把普通 Safari 页面渲染成一个不会工作的开关。 资料：Apple Developer · Sending web push notifications、WebKit · Web Push for Web Apps on iOS and iPadOS。

数据与边界 · 订阅是设备记录，仍进同一份学习者文档

一个学习者可能在手机和电脑上各有一个 Push 订阅，所以文档保存的是按 endpoint 区分的订阅记录，而不是一个会被新设备覆盖的单值。 每条记录带订阅 endpoint、加密所需的公钥材料、状态和更新时间；关闭提醒保留可合并的撤销记录。mergeProgress 对订阅按 endpoint 做并集、取较新的更新时间，旧设备的课程、卡片、答案、设置和订阅都不会因为一次上传被抹掉。

Service Worker 只处理 push 和 notificationclick，不接管 fetch、不改现有缓存，也不在首屏注册。当前没有 University 推送服务端；所以订阅成功后的诚实状态仍然是「已订阅，但服务端还没接上，暂时不会真的收到提醒」。

怎么验

  • 时机：首页、注册后、页面加载和设置加载都不调用权限请求；只有完成有明日卡的课程并点击预提示「好」，或在设置里主动点击打开，才进入流程。
  • 两次选择：「以后再说」不改变 Notification.permission；下一次价值兑现仍能看到预提示。
  • 拒绝：浏览器返回 denied 后结算页不再自动显示预提示；设置里仍显示「浏览器已拒绝」和人工开启说明。
  • iPhone：普通 Safari 页面显示「在 iPhone 上需要先把它添加到主屏幕」；主屏幕 web app 才显示可操作的订阅路径。
  • 文档：两个设备的订阅按 endpoint 合并；关闭一台设备不会因为另一台旧快照上传而复活；旧的 ProgressDocument 没有订阅字段时仍能正常读取。
  • 服务端缺口：没有 VAPID 私钥、定时函数和发送清理前，设置显示已订阅但不会伪造“提醒已送达”。
  • 首屏与离线：未同意前不注册 Service Worker；Service Worker 没有 fetch/cache handler，现有离线缓存和首屏请求数不因提醒增加。

静默登录只挂在两个真正会写入学习者文档的事件上：一是课程从未完成变为完成（读确认和全部练习通过都成立），二是第一张复习卡成功保存。 不是页面加载，不是打开课程，也不是出现登录页。调用不传 captchaToken；缺少后端、登录失败或网络失败都不报错、不弹窗，学习者继续使用本机进度。

决定 B · 邮箱占用时保住两边的文档

匿名身份绑定邮箱成功后，Supabase 保留同一个 user id，当前文档自然跟着走。若邮箱已被另一个账号占用，绑定失败只恢复匿名状态；学习者转而登录已有账号时，进度绑定器调用现有的 mergeProgress，把当前设备文档合入目标账号，而不是覆盖或丢弃其中一边。

合并不是简单的“最后一次上传获胜”：课程进度取较大值，卡片按 FSRS 的 reps、复习时间和到期时间选择较完整的一份，答题记录和批注按各自 id / 时间规则合并。 这轮没有另造 FSRS 冲突政策；如果产品以后要改排期语义，必须先单独设计并补验证。

  • 绿证据：apps/university/src/account/session.test.ts 验证合并后匿名侧和已有账号侧的复习卡、答题记录、阅读批注都仍存在。

决定 C · 匿名能同步基线，但不能购买

匿名会话可以把免费基线进度绑定到服务器；它不能读取或拥有正式账号的付费权益，不能读钱包、创建订单或查询订单。 会员页的购买控件照常渲染，不通过隐藏控件制造“没有这个能力”的错觉；点击后打开能力说明，说明购买前要绑定邮箱，并指向个人档案的绑定入口。 绑定成功之前不调用支付 transport，也不授予付费权益。

authoring 与 delivery 都经过同一个 PaymentPort、同一个 IdentityPort 和同一个账号进度绑定器；差异仍只留在既有的 AI 来源、课文材料来源和源码仓库可达性三个端口。

07主题由学习者选择，默认跟随系统

学习面不应该因为机器换了颜色就像换了一个产品。主题是学习者的账号偏好：第一次打开时跟随设备的浅色 / 深色设置， 也可以在设置里明确选择浅色或深色；两种模式显示同一组控件、同一套阅读面和同一条保存路径。

决定 A · 一个偏好字段，三种请求，不新增浏览器存储

AccountPreferences.theme 只保存学习者的请求：system、light 或 dark。 老账号没有这个字段时按 system 读取；选择会写回现有的学习者进度 / 账号文档，沿用同一套离线缓存、outbox、云端合并和逐字段时间戳。 不新增 localStorage key，也不另造一个只在设置页活着的主题状态。

决定 B · 应用只给 kit 一个当前主题，颜色仍归 SwimmerUIKit

共享主题控制器把请求解析成 data-game-ui-theme="light" 或 "night"，交给 SwimmerUIKit 的 :root 与 night 覆盖层。 color-scheme 也由 kit 随当前属性变成 light / dark，所以浏览器自己画的滚动条、表单控件和首屏过渡不会停在旧主题。 University 不复制第二套调色板；kit 缺角色时才回 kit 补角色。

「跟随系统」监听 prefers-color-scheme 的变化；明确选择浅色或深色时不被系统抢回去。 主题按钮在 authoring / delivery 都存在，因为这是学习者面，不是两个端口的答案。

决定 C · 3D 世界仍是场景，主题不把它涂成另一张地图

世界地图的海、天空、地形和悬浮在场景上的 HUD 玻璃属于 packages/world 的场景 / glass 边界，继续使用它们已有的 donor 与 kit 材料； 主题切换负责学习者能读的 2D chrome、路径、正文、代码和结算面。这样明亮主题下地图仍有稳定的景深与可读标签，正文也不会被强行塞进 canvas。 视觉验收若发现某个场景控件与当前主题冲突，先判断它是 kit 的主题角色还是场景固定材料，再决定是否向 kit 提案；不在 University 里临时加色。

    10匿名可以保存，但不能领免费的 AI

    §06A 定下「先保存价值，再问邮箱」，并且明确匿名不能购买付费权益。这一节把同一条边界补完： 匿名也不能领每天的免费 AI 批改额度。少的这一条不是吝啬，是因为不补上，这份额度就是免费的、可以无限重开的。

    先看现在会发生什么

    交付端的批改服务在验证 JWT 之后拿到了 is_anonymous，但从来没有用过它： funding: "free" 的请求不分匿名与否，一律进入按账号、按 UTC 自然日的免费额度。

    匿名会话的凭据只存在 localStorage 里（§06A 自己写明了这一点）。 所以清一次浏览器数据 = 一个新的匿名 user id = 一份新的当日额度， 而清浏览器数据是每台设备上都有的一个按钮。这不是被人钻空子才会发生的事，是默认路径。

    同一个动作还各留下一个不会自己消失的 Supabase Auth 用户，计入 MAU。 也就是说，这条路径同时漏两种钱：模型调用的钱，和身份的钱。

    裁决 · 免费额度绑在一个有邮箱的账号上

    每天的免费 AI 批改额度只发给已经绑定邮箱的账号。匿名会话请求 funding: "free" 时， 服务端不预留额度，返回一个具名的能力说明，而不是 401，也不是静默失败。

    匿名失去的只有这一件事。读全部课文、做全部练习、tier-1 确定性判题、 保存进度、生成复习卡、到期复习——一件都不减。学习本身没有被收走任何东西， 被收走的是「每天几次要花钱的模型调用」，而那正是唯一一件真的按次付现金的事。

    这条和 §06A 决定 C 是同一条原则的两半：匿名是一个存档位，不是一份权益。 能买不能买、能领不能领，都由「有没有一个能重新登录的身份」来分。

    学习者看到什么

    控件照常渲染，绝不隐藏。点下去打开能力说明： 「今天的免费 AI 批改要绑定邮箱才能领——因为它每次都要真的花钱， 而匿名身份换个浏览器就找不回来了。绑定之后这台设备上的进度会跟着你走。」 说明里带一个直接去个人档案绑定邮箱的入口。

    绑定成功之后，同一个 user id 继续用，当天的额度立刻可用——不需要重新学一遍， 也不需要退出重进。这一点必须是真的，否则这条边界就变成了惩罚。

    孤儿匿名用户 · 这一半在 SwimmerBackend

    即使额度关上了，放弃的设备仍会留下没有邮箱的 Auth 用户和进度行，Supabase 不会自己清。 保留期、清理任务、进度行级联和审计属于 SwimmerBackend 运维，登记在 Payment Backend Gap； University 不在自己仓库里偷偷补迁移或删除。

    怎么验

    • 匿名不预留：带 is_anonymous 的 JWT 请求 funding: "free" 时，配额的 reserve 一次都不被调用。
    • 不是错误：返回的是能力说明，不是 401、不是 500；控件仍在，仍可点击。
    • 绑定即生效：同一个 user id 绑定邮箱后再次请求，当天额度正常预留，不需要新会话。
    • 其余不减：匿名仍可读课文、答练习、走 tier-1 判题、保存进度与复习卡；这些路径不发出任何计量请求。
    • 钱包不受影响：这条只关免费额度；正式账号的钱包路径与 §05 一致。

    11听写整理：只修听错的字，不替你说话

    §03 决定 University 不做 ASR，因为手机和电脑的输入法自带听写，做得比我们好。 但那句话只解决了「怎么把声音变成字」，没有解决「变出来的字是错的」。 这一节处理剩下的那一半，并且给它划一条很窄的边界——窄到不会毁掉「讲一遍」本身。

    先说清楚这件事的风险在哪

    §02 明确拒绝了让 AI 判学习者的复述，理由是它「会把『我怎么理解』变成一个外部裁判的问题」。 一个会重写复述的 AI 有同样的毛病，而且更隐蔽： 复述卡存在的全部理由是到期回来时，把这次的答案和上次的并排看。 如果保存下来的是 AI 润色过的版本，明天你比对的就不是自己两次的理解， 是机器两次的措辞。那张卡就空了。

    所以这件事不能做成「润色」「优化」「帮你说得更好」。它只能是一件事： 把听写弄坏的地方修回来。名字就叫听写整理，不叫别的。

    裁决 A · 只允许三种改动，而且由类型强制，不是由提示词请求

    模型不返回整理后的段落。它返回一串「替换」，每一条是：原文里的一段、替换成什么、 以及一个来自封闭集合的原因——homophone（同音或识别错字）、 punctuation（断句）、filler（纯语气词）。客户端按这串替换去改原文。

    这样「不许重写」就是一条类型约束，不是一句祈使句：任何不能落在原文某一段上的输出都被拒绝， 模型没有地方可以塞进一个它自己想出来的句子。顺带三个好处： 差异高亮是免费的（你本来就知道改了哪几段）、输出很短所以便宜、 以及一次失败的整理只是「没有可改的」，不会变成一段陌生的话。

    不允许的：调整语序、合并或拆分句子、补充没说过的内容、把口语换成书面语、 把一个错误的理解改成正确的理解。最后一条尤其重要——理解错了是教材，不是错别字。

    裁决 B · 词典是这节课，不是这个人

    真正值钱的是术语：「组建」要变回「组件」，「瑞艾克特」要变回 React。 所以送给模型的上下文是这一节课自己的东西——本节的术语词条、 证据引文里出现的标识符、本单元的能力句。这些都已经在课程包里，不需要新写。

    不读个人资料，不读历史答案，不建口癖模型。它们会把一次窄的调用变成一份画像， 换来的边际收益却很小——听错的字绝大多数是术语，而术语在课文里。 这也避开一个更难看的结果：一个学过你说话方式的 AI，写出来的会越来越像你， 于是你更分不清哪句是自己想的。够用就是这里的正确答案。

    裁决 C · 两栏并排，默认选中你自己的原话

    整理完不直接替换。左边原话、右边整理稿、改动的地方标出来，学习者选一个保存。 默认选中的是原话。这和复习卡的四档自评是同一个姿势：产品给材料，判断权在学习者。

    存进复习卡的是学习者最终选中的那一份，并且记下它是不是整理过的。 到期回来并排看历史答案时，这个标记要能看见——否则你会拿一份整理稿去和一份原话比。

    裁决 D · 不做成单独的收费点

    它是一次真实的模型调用，所以它计量：走已有的 tier-2 通道、 吃同一份每日免费额度、用完之后同样安静回退并说明明天恢复、 另选钱包才单独扣费。这条路径一行新的计费代码都不需要。

    但它不单独定价。理由有两条。第一，它修的是输入法造成的损坏； 为「把你自己的话修回来」单独开一个价，是给摩擦标价， 而这多半会是一个学习者遇到的第一个付费时刻——那是最差的一个第一印象。 第二，一个功能一个计费面，正是端口纪律要防的那种增生： 它已经在被订阅变现了，因为常用它的人会先用完免费额度。 它是收费点，只是不是新的那一个。

    边界 · 出网的时机和 §05 裁决 B 一致

    学习者写的字默认留在本地。听写整理是一次明确提交：只有按下那个控件， 这一段文字和本节课的术语表才会发给交付端的计量服务；不按就一个字节都不出去。 控件在文本框里有内容之后才出现，永远不自动运行，也永远不自动套用结果。 匿名会话按 §10 处理——先绑定邮箱。

    暂时不做 · 练习答案上的同一个控件

    口述练习答案有一模一样的问题，同一个控件显然也该出现在那里。但那里的文字是要被判分的， 「修听错的字」和「把答案往对的方向挪一点」之间只隔着一个模型的判断力。 这是一个关于判分公平的决定，不是一个关于输入法的决定，所以它单独定，不在本节里顺手扩大。

    08一座岛是一条主线，形状可以弯

    05B/05C 已经把课程岛从「一关一座浮岛」改成一块地面，把关卡放回地上；这次只再补一条几何与语义的边界： 课程岛内部是一条连续的语义主线，视觉上不必是一条直线。 弯道服务于地形和构图，不能偷偷变成另一套课程结构。

    决定 A · 先固定主线，再选择视觉形状

    课程蓝图先给出教学顺序和节点之间的 next 关系；没有真实课程分支的课程，起点到终点只有一条连续链。 因此允许 arc（弧线）、horseshoe（马蹄）、loop-around-hill（绕丘环线）、 switchback（回头弯）和 serpentine（蛇形）等视觉形状，形状只改变节点的屏幕位置，不改变先后顺序。

    只要课程数据没有声明真实分支，就禁止画出 Y 型语义分叉：不能因为一条回头弯在远处看起来像两条路， 就让学习者猜「下一步选左边还是右边」。曲线可以靠近、绕山和折返，但在课程投影里不能自交，也不能近到让两段路误读成交叉口； 节点仍按唯一的连续索引前进，不得产生第二个可选的 next。

    决定 B · 岛内可铺地面路，岛与岛之间仍不架桥

    课程投影可以在相邻关卡节点之间铺一条低矮、贴着自然地面的路或小径，让「从这一关到下一关」有连续的脚下语汇。 路的高度取同一套地形函数，不能变成悬空栈道、石阶或一串把节点重新分组的家具；它也不拥有独立的课程关系数据。

    世界地图是另一种尺度：一座岛是一个可选的 course，岛与岛之间依然没有桥、木板、栈道、浮线或任何可被读成「走过去」的连接。 先修关系和可进入状态由数据与节点状态表达，不能用跨岛桥偷偷恢复 05C 已拆掉的语义。

    决定 C · 自然地势可以起伏，unit 只是标签

    岛面可以有连续、缓慢的自然高低差：山丘、凹地和坡面是自然底盘的一部分，服务于视线、阴影和路线构图。 但 unit 仍只是岛面上的分组标签，不是可以进入的地方，也不对应一级台阶、平台抬升或单元边界的地形断层。 单元换页时，语义换了章节，脚下不应凭空变成楼梯。

    关卡节点、贴地路和装饰都要采样同一连续地形；若坡度让节点不可点、标签不可读或道路像悬桥，先改路线和构图， 不用加一层「单元台阶」来掩盖问题。

    决定 D · unit 不切开场景，小节节点共享视觉家族

    单元之间不通过地形、空间分区或不同环境主题来区隔。自然底盘从入口到终点保持连续， 两个主题只负责整座岛的身份与构图，不得被安排成「这一段是一个 unit、换一块环境就是下一个 unit」。 unit 的边界只由 DOM 标签和学习语义表达，不在世界里另画一道门。

    同一 unit 的小节节点组成一个可辨认的视觉家族：共享颜色与非颜色符号 / 环形纹样；需要状态动画时，同组使用同一套克制的运动词汇， 但不能让所有节点持续跳动。颜色不能是唯一线索。即使把颜色去掉，学习者也能靠符号、环纹、状态和 DOM 标签认出它们属于同一组； 这套家族只整理信息，不增加分支、不抬高地面，也不改变课程仍是一条路线的语义。

    决定 E · 一个纯数据 blueprint，编译 course / world 两种投影

    每座岛只有一份可序列化的 IslandBlueprint：课程与节点 ID、唯一顺序、语义锚点、路线形状、自然地形参数、稳定 seed、轮廓和主题槽位都在这里。 编译器接收同一份蓝图与 course 或 world 投影档位；不能为两个模式各写一份坐标表、地形函数或节点顺序。

    course 投影保留可点击的关卡节点、贴地路、单元 DOM 标签和细节装饰；world 投影只保留岛的轮廓、色彩 / 尺度、少量地标和当前进度这类身份线索。 世界远景不渲染 lesson 节点、单元标题、可读课文或细碎主题道具；需要文字时仍由 DOM 覆盖层承担，而不是把字烘进模型。

    决定 F · 每座岛的艺术预算是自然底盘 + 最多两个强调主题族

    自然底盘负责浮岛轮廓、地形起伏和岩层，不占强调主题槽；树与灌木统一使用已登记的 elemental-serenity 画意叶片投影， 岩石则保留通过同机位对比的安静 Kenney 小石头。这样自然元素共享同一套渐变、法线分段和阴影语汇，建筑才使用 Kenney。 在它之上最多放两个强调主题族，并统一尺度、材质和色彩管线。 第一座岛 foundations-before-zero 的垂直切片固定为：程序化自然地形 + elemental-serenity 树 / 灌木 + 保留的 Kenney 岩石 + Fantasy Town 一个物理强调包。 这次切片故意只用一个强调包；后续星港岛再使用 Space + Modular Space 两个物理包，不能用斜线把多个包伪装成一个预算槽。

    Kenney 素材逐项走现有的授权登记、导入和 provenance 清单；不把别的项目的渲染代码或一整套资产目录抄进 University。 头像、DOM UI 和天空 / 云海不借机成为第三个强调主题；如果一个物件无法归入自然底盘或这两个强调主题，就删掉、重配色或把它留到另一座岛。

    「最多两个」限制的是一座岛，不是整个产品。University 可以登记并逐步使用完整的合规 Kenney 包目录：一组岛复用一份经过审美审核的双主题配方， 下一组岛换另一份配方；全局覆盖账本记录哪些包已经获得舞台。目标是让所有适合产品语义的包都能在某座岛上出现，不是强迫每个重复款、过重款或语义不合的 GLB 都上场。 配方与覆盖是数据，渲染器不得用 if (courseId) 写成一串首岛特例。

    决定 G · 云是可替换的软雕塑模块，不是天气系统

    云层作为环境里的独立可替换模块，目标是截图式的可爱、圆润和有厚度的软雕塑感；它不属于课程蓝图，也不拥有路线或进度语义。 优先用实例化的低模云瓣、共享材质和远景 LOD 控制数量与层次，不采用昂贵的 ray-marched 真体积云。 换一套云模块不应改动 course / world 投影、节点顺序或主题预算。

    云只做构图和纵深，不得遮住节点命中区、道路、头像、导航栏或任何 DOM 信息；需要让位时先减密度、换 LOD 或调整云的屏幕占位。 这是后续同一垂直切片的独立验收项，不扩展成风、雨、昼夜或天气系统，也不以「有一朵云」代替可测的遮挡和性能合同。

    决定 J · 2026-09-06 · 连续地形的路、光影和道具必须服从同一个地面

    决定 L · 2026-09-06 · 小节是可辨认的学习路标，景物按用途成组

    12分级与跳级：不发等级称号，只决定从哪儿开始

    课很多，小节更多。让每个人都从第一节爬起，会把有基础的人赶走；而把课全部敞开随便点， 又等于没有次序。这一条决定学习者怎么被安排到合适的起点，以及他变强之后怎么自己往前跳。

    决定 A · 判断落在「从哪一节开始」，不落在一个称号上

    学习者回答几个关于自己经历的问题，结果**不是**「初级 / 中级 / 高级」。称号对学习没有用， 而且贴上去就很难撕：一个被标成「初级」的人，会在每一次卡住时把它当成对自己的解释。 判断只表现为两件具体的事——你从这一节开始，以及这几个单元已经点亮。

    题目问的是做过什么，不是懂不懂。「你以前把一个项目改过并重新跑起来吗」可以回答； 「你理解组件吗」不能——后者量的是自信，不是能力。

    决定 B · 不另建题库，跳级的题就是课自己的练习

    每节课已经带一道练习。跳级用的就是它们，随机抽这个单元里的三道。 这不是省事：另建一套题库，意味着课改了而题没改时，学习者会因为一道过期的题被挡在外面， 而没有任何检查会发现——两边本来就该长得不一样。 题跟着课走，课一改题自动跟着改。

    手写的分流表不再扩张。目前 CourseRouteQuiz 只覆盖一门课， 其余课程直接不问；一张要为每门课手写三个落点的表，走不到几十门课。

    决定 C · 前置只灰，不锁

    前置没满足的课显示为未点亮，并说明它假定你已经会了什么。但它仍然点得进去—— 点了先给一句「这节假定你已经做过 X，要不要先测一下」，然后由学习者决定。

    锁死会把有基础的人挡在门外，而那正是这一整条要解决的问题。灰是信息，锁是权力； 这里我们只给信息。

    决定 D · 跳级随时能发起，不是一次性的入门测验

    每个单元入口都有一个「我会了」。抽三道，全对就把整个单元标记为已掌握； 错一道，只打开错的那一节，其余仍然可跳。人的能力是一路长的， 只在进门时测一次，等于假定他一年后还是进门那天的样子。

    决定 E · 跳过的单元算「证明过」，不算「学过」——复习卡不进队列

    跳级解锁后面的课，但不把被跳过那些课的记忆卡片放进复习队列。 卡片是给读过课文的人用的：一张三周后弹出来、而正文从没读过的卡片， 只会制造一次挫败，并且教会学习者忽略复习提醒。

    所以跳级改变的是「你可以去哪」，不是「你已经记住了什么」。 学习者随时可以回头正式读那一节，那时卡片才开始排期。

    决定 G · 自述只负责挑出「要不要测这几个」，解锁永远靠做对题

    开场的几个问题和单元入口的「我会了」不是两套东西，是同一个机制的两个入口： 自述缩小范围，测试决定解锁。自述本身从不把任何一节标成已掌握。

    因为自报家门不是能力证明。一个高估自己的人会被自己的答案推到接不住的地方， 然后把接不住理解成「我不适合学这个」——那正是这套东西要防的结果。 自述的产出只有一句话：「看起来你可以跳过这三个单元，要不要各测三道？」 题从这些单元自己的练习里抽，做对了才真的跳过去。

    决定 F · 次序写在课的字段里，不写在课的介绍文字里

    prerequisiteCourseIds 是唯一的次序真相。写在 audience 那句「已经把这个项目跑起来的人」里的次序，机器读不到，因此既灰不了也测不了—— browser-ai 的四个系列此前正是这个状态：介绍文字里有清楚的顺序，字段全是空的。
