产品挑的词可以，
学习者说的话不行

V4 定下了地图、双模式和共享阅读器；当前执行记录又把「讲一遍」分成作者知识笔记与学习者复述卡。V5 只把其中一条还会被误读的边界钉牢： 语音输出已经定了，语音输入仍然开放。这不是重画世界地图，也不是给两个模式再加一个差异。

承接 V4：V4 没有被本文推翻的地图、组件、商业和双模式决定继续有效。 本稿新增 读完与答对分开、学习者复述进 FSRS、TTS 与 ASR 的边界。读法 先看裁决，再看为什么，最后看怎么验。

The V5 boundary

决定权在载荷，不在传输方式。

那条「什么都不出网」的笼统规矩已经没有了。产品自己挑的一个英文单词是产品材料， 可以交给浏览器的在线声音读出来；学习者自己写的、自己说的、以及私有仓库里的文字是学习者的数据， 默认留在本地。所以不是「语音不能出网」，而是「产品挑的词可以，学习者说的话不行」。

00这一版到底改什么

V4 的大部分决定已经是产品骨架，不需要因为语音再开一套架构。V5 只处理一条用户会实际遇到的路径： 读一节课、答练习、用自己的话复述，以及想不想把这段话说出来。

继续沿用 V4V5 新增的裁决
一个 apps/university，两个模式；学习面一套实现读完与答对是两个事实，不能由一个事件代替另一个
ContentPort / ReaderPort 只换材料从哪来，不复制阅读器「讲一遍」是学习者自己的复述卡，不是作者的知识笔记
可读文字在 DOM，3D 只负责世界、路径和反馈TTS 四档已定；学习者口述的 ASR 仍是开放决定
课程内容不设付费墙；AI 按既定成本层级走端口打开 TTS 不等于同意上传学习者的声音

裁决 A · 先把复述做成文字卡，TTS 做窄，ASR 不顺手打开

实现后，学习者先用文字完成「讲一遍」，并让它进入已有的 FSRS 复习队列。 读单词的 TTS 按四档工作，其中在线声音可以读产品挑的单词。 学习者口述复述的语音输入不在这次实现里；它保持开放，直到明确的选择加入设计完成。

V4 已统一的世界词汇也继续有效：星球 / 课程系列 / 岛 / 单元 / 关。 本稿只把它作为学习者复述卡的定位层级，不重新定义地图；完整解释见 V4 §05D。

01读完和答对，是两盏不同的灯

当前模型已经把这两个事实分开：readConfirmed 记录学习者确认读过， exercisesPassed 记录所有练习通过。问题在于交互还曾经把它们从一个事件一起写下去， 于是「跳到题目并猜对」看起来像完成了阅读。

决定 · 两个动作，最后才合成「完成」

学习者读到课文底部后，看到一个明确的「我读完了」动作。它只写 readConfirmed = true，不替任何练习判分。

练习提交只写对应的答案和判分记录。即使全部答对，也不能替读完动作盖章； 即使确认读完，也不能跳过练习。只有 readConfirmed 和 exercisesPassed 都为真，地图、结算和 XP 才把这节课当作完成。

线框 · 一节课的事实顺序
课文底部
  [ 我读完了 ]  ──只写 readConfirmed

练习区
  [ 提交答案 ]  ──只写该 exercise 的 attempt / passed

结算
  readConfirmed && exercisesPassed
  └─ 两盏灯都亮，才显示「完成」和下一关

怎么验

  • 先答后读：所有练习答对后，课程仍显示未完成，直到明确点击「我读完了」。
  • 先读后答：点击「我读完了」后，课程仍显示未完成，直到所有练习通过。
  • 跨设备：两个事实都写进同一个云端学习者文档；本地缓存只是离线缓存和 outbox。
  • 版本：确认动作带着当前 contentRevision，不会把旧课文的确认误套到新版本。

02「讲一遍」是复习卡，不是知识笔记

作者需要把真实、有证据的知识写进课程；学习者需要把刚学到的东西用自己的话说一遍。 两者都叫「笔记」会把内容生产和学习记录混成一件事，V5 把它们拆回各自该在的地方。

知识笔记讲一遍
谁写作者，通过 capture CLI学习者，在课后或复习时
依据需要证据引用，按版本锁定来自现有的单元能力句，不要求作者另写提示
放哪作者端的内容发布管线共享云端学习者文档；离线时进本机 outbox
是否进课程包会，经过发布门不会；它不是课程内容
是否调用模型作者工作流另说零模型调用，免费层也成立

决定 · 一句提示、一个输入框、一张会回来的卡

读完一节课或完成一个 explain 练习后，给学习者一个提示： 「请用自己的话，讲给一个完全不知道这件事的人听。」 提示来自该单元已有的第一人称能力句，不新增作者工作。

默认输入是文字。提交后答案成为一张 FSRS 卡；到期时再次问同一个问题， 把这次答案和之前的答案并排给学习者看，由学习者自己选「again / hard / good / easy」。 保存本身不是学习，回来再答才是这个功能存在的原因。

不做 · 选择题和 AI 判卷都不是默认答案

选择题把「生成一个解释」换成「认出一个选项」，少了这条路径真正要练的东西。 AI 判学习者的复述则会给免费层带来无法封顶的模型成本，也会把「我怎么理解」变成一个外部裁判的问题。 V5 先让学习者生成、重看、再生成，并且不替他假装判断。

线框 · 先文字，语音输入不偷偷出现
讲一遍
  请用自己的话，讲给一个完全不知道这件事的人听。

  [ 在这里写你的复述……                         ]
  [ 保存为复习卡 ]

  语音输入：还在设计
  （不会因为你打开了「听发音」就自动启用。）

怎么验

  • 一次写入：提交后生成一张可定位到课程系列 / 岛 / 关 / 版本的复习卡，不生成课程包文件。
  • 真的会回来：到期卡出现在同一套复习队列，能看到自己的历史答案并完成四档自评。
  • 成本封顶：从写入、再次提问到自评，默认路径的模型调用次数为 0。
  • 两模式同形：本地模式和交付模式共用这套输入、卡片和复习表面，只通过既有端口取材料与判分。

03语音分成输出和输入，不能用一个开关代替

「语音」不是一个整体功能。一个动作是产品读出它自己挑的单词，另一个动作是学习者把自己的理解说出来。 前者已经定案，后者仍开放；把两个动作放进同一个「允许语音」开关，会让学习者在不知情时交出另一种数据。

动作载荷是谁的现在状态网络与默认行为
TTS · 听发音产品选中的一个英文单词已定可以使用本机或浏览器云声音；只读产品单词，不代表收集学习者内容
ASR · 口述复述学习者自己的声音、句子，以及可能提到的私有仓库开放默认不启用；必须另做明确的选择加入，不能从 TTS 设置推导同意

决定 · 边界看载荷，不看「本机 / 在线」这个标签

「在线」不自动等于不允许，「本机」也不自动等于可以把任何数据塞进去。 判断顺序是：先问这段东西是谁选的、属于谁；再问实现它需要哪种传输。 产品选定的 word 是课程材料，所以浏览器的云端声音可以读它。

学习者的写作、声音和私有仓库文字属于学习者，默认留在本地。 这条许可只覆盖「读一个产品单词」，不覆盖「收集学习者的解释」。

TTS · 四档已经定了

packages/ui/src/language/speech.ts 现在把本机和在线英语声音收集后再做新奇音色过滤与排序， localService 只负责判断它属于哪一档，不再把在线声音一刀切掉。 设置存的是学习者的请求，不存某次运行的解析结果。

设置含义存什么拿不到时
自动每次按当前能力选最好的可用层级永远存 auto 这个请求每次重新尝试：高品质 → 在线 → 本机
本机只用本机英语声音存 local向下退无可退，显示没有可用本机语音；绝不静默改用在线
在线可以使用浏览器提供的云端英语声音存 online浏览器没有云端英语声音时，说明原因并按既定降级规则处理
高品质付费高品质声音存 premium 请求钱包和权益接入前置灰；付款后自动请求仍能重新解析到它

这里已经关掉的三个坑

第一，自动不是一次性答案。今天只有本机声音，明天登录后有高品质权益，或浏览器后来暴露了新的在线声音， 都应该在下一次使用时生效；把「自动」写成「本机」会把学习者困在过去的能力上。

第二，本机是明确选择。学习者手动选「本机」时，不能因为本机暂时没有声音就偷偷改走网络。

第三，高品质不是假装存在。钱包还没接好时把它显示为不可用，并解释是权益尚未接入； 不把一个没有兑现路径的付费承诺伪装成普通声音。

ASR · 仍然开放，而且正因为新规矩才开放

这不是「旧规矩还在」

浏览器实现 Web Speech API 的方式会把音频送到服务商：Chrome 和 Edge 的语音识别会把声音流向 Google 或 Microsoft。 Firefox 则根本没有实现这套能力。两件事都不能被一个「浏览器支持，所以打开」的判断抹平。

这个产品最常见的口述不是干净的单语句子，而是普通话夹着英文标识符；这是 ASR 最弱的场景。 学习者复述的主题还可能是 turing-pact 这样的真实私有仓库——他是在说自己的数据， 不是在朗读产品挑出来的一个词。

所以 ASR 不是被「语音不能出网」挡住，而是被新边界保留下来：学习者说的话需要单独、明确的选择加入。 TTS 放开之后，这个问题没有被顺带回答。

ASR 未来要先回答的五个问题

  1. 去哪处理：本机识别、哪一种在线服务，还是两者都给；不能把浏览器实现误说成本机。
  2. 什么时候同意：在第一次收音前说明会发送什么、发给谁、为了什么，且不能用 TTS 的同意代替。
  3. 保存什么：原始音频、转写文字、还是只在本机临时使用；保存与否、保留多久、怎么删除都要明说。
  4. 识别失败怎么办：Firefox 没有能力时给文字输入；中英混杂时不能把错误转写当成学习者说错。
  5. 学习者能否反悔：取消、拒绝和关闭后都不能留下一个已经上传却没有说明的录音。

怎么验

  • TTS 的载荷：点击「听发音」只给合成器一个产品选中的英文单词，不把复述框、读者标记或仓库文字拼进去。
  • TTS 的设置：四个值能持久化；自动持久化为请求而不是解析出的层级；高品质在钱包未就绪时不可用且有解释。
  • ASR 的门：当前没有任何「听发音」动作会打开麦克风；未来 ASR 进入产品前必须有单独的选择加入界面。
  • 浏览器差异：Firefox 走文字复述；不能用「没有按钮」掩盖能力不存在，也不能把 Chrome / Edge 的在线实现叫成本机。

04已关的和还开着的

把开放问题写出来不是把产品做成半成品，而是避免一个已经定的 TTS 选择替另一个高风险决定背书。

问题状态当前正确说法
TTS 能否使用在线声音已关可以；产品挑选的英文单词是产品材料，边界由载荷决定
语音质量设置已关自动 / 本机 / 在线 / 高品质；自动存请求，高品质等钱包
学习者口述复述是否默认开启开放不默认开启；它涉及学习者自己的数据，需要明确选择加入
ASR 的处理位置与服务商开放本机、在线或两者的取舍尚未定，不从浏览器 API 的名字猜答案
录音 / 转写的保存与删除开放在隐私和数据生命周期说清楚前，不把它写进学习者功能承诺

不会再打开的旧问题

「自动到底选本机还是在线」「高品质是否要等钱包」「TTS 能不能读产品单词」已经由代码与设置契约回答。 后续如果发现浏览器声音质量不好，修排序、降级说明或品牌 kit；不要借机把学习者口述也接上同一条路径。

05施工顺序与完成线

先把两个事实和一张文字复述卡做成一套，再决定是否值得为 ASR 支付隐私和识别失败的复杂度。 TTS 的四档设置已经有共享实现，本节描述它必须守住的产品行为。

  1. 分离读完与答对。阅读器只在明确动作上写 readConfirmed，练习只写自己的 attempt 和 verdict。
  2. 落地「讲一遍」文字路径。使用单元现有能力句，保存到学习者文档，接入已有 FSRS，不新增模型调用。
  3. 保持 TTS 四档。所有调用经过共享 speech.ts 的声音选择；自动存请求，手动降级可解释，高品质等钱包。
  4. 单独设计 ASR 选择加入。先做载荷、目的地、处理位置、保存和删除的决定；决定前不接麦克风，不把「开放」写成已上线。
  5. 双模式逐屏对齐。本地与交付模式共享课后提示、文字输入、复习卡和 TTS 设置；唯一的 AI 来源差异仍留在既有端口。

完成线

检查必须看到什么
读完 / 答对任意顺序都不能互相冒充；两个事实都存在且能跨设备合并
讲一遍文字复述生成 FSRS 卡，到期回来，显示历史答案，默认零模型调用
TTS四档设置真实可见；自动仍是 auto 请求；在线 TTS 只收到产品单词
ASR当前不默认收音；未来若打开，必须另有选择加入和数据生命周期说明
两模式同一棵组件树、同一份学习者数据、同一套可见行为；不因为「本机」两个字复制一份功能
