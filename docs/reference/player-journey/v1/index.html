University · 用户旅程 v1

2026-08-18 · 由 PGS 控制平面起草 · 22 幕 · 六个阶段 · 这一版是用来被推翻的

这份文件先回答一件事：University 到底是什么，以及它凭什么和 UniversityLocal 一致。 答案不是「两个应用互相同步功能」，而是一条流水线的两半。UniversityLocal 是作者工作台， University 是学生播放器。只有一个生产者，所以「课程一致」不是同步问题，是供货问题。

UniversityLocal（已存在）

AI 宿主带着一个人读真实仓库，产出课文、卡片、习题、证据。单人、本地、永不联网。

→

course-recovery 导出包

已经存在的格式，按内容哈希寻址，自带整棵课程树，不含任何学习者状态。这就是内容契约，不用再发明一个。

→

University（本仓库）

导入 → 评审 → 投放。3D 地图与关卡负责动机，2D 课堂负责学习，在线模型负责判分与辅导。

方向是单向的：University 去拉，UniversityLocal 永远不知道它存在。这不是偏好——UniversityLocal 自己的 router 写死了「永久本地、不得为任何后端准备同步通道」，那条约束不归 University 来打破。

这一版和图灵密约那份旅程的区别

图灵密约的 v2 用「已上线 / 只有机器验过 / 不够好 / 没有」标每一幕，因为那个产品已经有代码了。 University 今天一行产品代码都没有，全标「没有」等于没有信息。

所以这一版换了一根轴：每一幕标它的来源——是 UniversityLocal 已经做好、只需搬过来的， 是搬一半的，是 University 全新的，还是外部件（品牌套件 / 后端）给的。 这根轴直接回答你最关心的问题：「一致」的代价具体分布在哪里。 按它排序，你会看到一件反直觉的事——这个产品最贵的部分不是 3D。

图例

G1 · 让第一节课能上完 G2 · 让第二天会回来 G3 · 让它变成身份
直接移植 · UniversityLocal 已有 移植一半 · 引擎在，交付侧要重做 全新 · University 独有 外部件 · SwimmerUIKit / AIKit / Backend

「直接移植」不等于零成本。它的意思是逻辑已经被验证过，代价在抽包和接线，不在重新想清楚。 真正贵的是「全新」，因为它同时要想清楚和做出来。

镜头墙

默认按学习者真实经历的顺序排。用下面的按钮换一个看法。

快乐地图：他在哪一秒真的拿到了东西

柱子高度是快乐强度，颜色是快乐的种类。零高度的不是「做得差」，是纯支出——学习者付出了时间，什么都没拿到。

这张图说了三件事，都不是"多做点 3D"

一、唯一抄不走的快乐是「懂了」，而它发生在 2D 课文里。 深绿色（懂了）的两个峰在第 7 幕「读课文」和第 10 幕「判分讲错在哪」。别的学习产品也有进度条、也有连击、也能做 3D 地图； 只有这个产品能让人指着一段正在赚钱的商业产品源码说「我看懂它为什么这么写」。 3D 的作用是把人送到那一刻，并在那一刻之后给它一个仪式。 如果 3D 的预算挤压了课文与判分的质量，那是拆了护城河去修外墙。

二、两段最长的零回报都在「要东西」的时候。 第 13 幕注册和第 18 幕付费都是纯支出。它们的位置比它们的措辞重要得多： 两者都必须排在学习者已经拿到东西之后。V1 把注册放在第一次结算之后，把付费放在第一次真正卡住的时候—— 不是因为好听，是因为那是他手里第一次有值得保护的东西。

三、第二天回来的理由不是 streak 数字，是那张卡。 连击是包装，间隔重复才是引擎——而引擎 UniversityLocal 已经有了（FSRS + 卡片 + 到期选择）。 公开数据里 Duolingo 把连击称作最有效的留存杠杆，但真正让人第二天有事可做的是「今天有 12 张到期」。 先接引擎，再做包装；反过来做，会得到一个很好看的空壳。

两条曲线：信心该涨，负荷该只在该高的地方高

信心（他觉得自己能行）必须整体向上。认知负荷允许在读课文和判分时高——那是学习本身。 但在导航期（选课、进地图、找关卡）负荷必须低。

这条曲线是 3D 的验收标准，也是它唯一可能变成负债的地方。 研究里反复出现同一个结论：游戏化能提高动机与成绩，但不是所有游戏化元素都免费——某些装饰元素会抬高认知负荷。 如果 3D 地图让「我下一节课在哪」变成一道需要思考的题，它就是净负债，无论多好看。 所以第 3、5 幕的验收不是「好看吗」，是「不看教程能在 8 秒内找到下一节课吗」。

首次五分钟预算

从点开链接到第一次结算。总预算 300 秒。红色是超支。

合计 333 秒，超支 33 秒，而且超支全部来自注册。 这不是让注册更快的问题，是注册不该在这五分钟里。V1 的处理：第一节课完全免注册， 结算屏给出成果之后才请求注册，并且把注册说成「保存你刚拿到的东西」而不是「创建账号」。

坏掉的时候，他还知道下一步吗

任何一幕坏掉时，学习者看到的东西必须能让他自己走出去。「重试」不是出路，出路必须换一条路。

坏在哪他看到什么出路（不是重试）
3D 地图加载失败 / 弱 GPU地图转不出来或帧率崩自动降级到 2D 列表视图，课程结构完全一致。3D 是导航的一种表现，不是唯一表现。
在线模型判分超时提交后卡住确定性判分本来就不需要模型，先出结果；只有开放题降级为「先记下来，稍后给你讲」并把卡片照常入库。
免费额度用尽辅导按钮变灰明确说出剩余能做什么（读课文、做确定性题、复习全部可用），而不是把整个产品锁上。
离线 / 通勤断网什么都点不动已导入课程与到期卡片本地可用，判分排队。复习是最该离线可用的那一部分。
课程被作者重新导出进度看起来消失了未决。UniversityLocal 的规则是新修订让课程回到未完成——那对一个自学的人是对的，对付费学习者大概率是敌意的。见待决项 D3。
课程包校验失败课程打不开课程不上架，学习者根本看不到它。校验发生在投放之前，不是学习者面前。

成本：这决定了它能不能收费

AI 学习产品最常见的死法不是没人用，是用得越多亏得越多。 公开的行业口径里，AI 产品的毛利通常被压到 60–70%（传统 SaaS 是 80–90%），因为你实质上在转售算力。 所以判分必须分层，而且最便宜的那层要覆盖绝大多数交互。

层用在哪成本为什么现在就能做
1 确定性短答、选择、卡片正反面零边际成本导出包里的习题自带 expectedAnswer，卡片自带 front/back。这是白捡的。
2 小模型 + 结构化输出需要语义容错的自由作答极低经 SwimmerAIKit，输出受 schema 约束，不走对话。
3 开放辅导「我还是不懂，给我讲讲」可观且随使用增长这就是付费墙的位置。免费层不得提供不计量的大模型对话。

验收写死在契约里：一节所有习题都可确定性判分的课，学习者从头走到尾应触发零次大模型调用。 这一条能不能过，决定了免费层是获客还是失血。

缺口总账（按「离第二天有多近」排）

这不是偏好排序，是按「什么最先杀死第二次打开」排的施工单。

#缺口来源为什么排这里
1课程包导入 + 校验 + 评审闸门全新没有它，一节课都投放不出去。它是所有其他幕的前置，且评审闸门因为「上架真实商业源码」的决定而变成硬需求。
22D 课文阅读器（代码块、证据跳转、选中标记）可移植「懂了」发生在这里。它是护城河，而且 UniversityLocal 已经验证过，是性价比最高的一块。
3确定性判分 + 卡片入库一半它同时决定第一节课的手感和第二天的理由，还顺手压住了成本。一块砖砌三面墙。
4到期复习与召回可移植第二天回来的唯一实质理由。引擎现成。
5世界地图与关卡链（含 2D 降级）全新它决定「愿不愿意开始」，但排在 2–4 之后，因为一个漂亮地图通往一节糟糕的课，只会让人更快离开。
6账号与结算（SwimmerBackend）外部件在第一次结算之后才需要。提前做会把它推到旅程前面去，那正是预算超支的原因。
7分层判分的第 2、3 层与计量全新付费墙。但在有人愿意回来之前，付费墙无人可拦。
8连击、角色成长、装扮全新包装层。它放大已有的快乐，不创造快乐。放在最后不是因为不重要，是因为它没有可放大的东西时等于零。

把这张表和你的直觉对一下：3D 排第 5，不是第 1。 我不掩饰这和「先把 3D 弄进来」的起点是有出入的。理由是上面那张快乐地图—— 3D 的作用是运输和仪式，它放大「懂了」，但不生产「懂了」。垂直切片应该是 一门课，从导入到第二天复习整条打通，地图那一层可以先是最朴素的 3D，甚至先是 2D 降级视图。

公开待决项

这些没有在 V1 里替你决定，因为现在决定就是猜。它们是 V2 该回答的。

D1 · 地图上要不要一个能走动的小人？

「3D 小人选地图」是这个想法的起点，但它有具体价格：可操控角色要装 ecctrl + Rapier 物理，donor 目录当前对所有产品的标注是「先不要装，等有试玩证据」。

A 要走动 → 装物理，手感要调，移动端要测
B 不走动 → 点击关卡节点，镜头飞过去，零物理依赖
C 折中 → 小人只在着陆与结算时出现，不接受操控

D2 · UniversityLocal 的 study 在地图上是什么？

那边的组织方式是「一个源仓库 = 一个 study，下面若干课程」。学习者不关心仓库。一门课 = 一块大陆，那大陆之上是什么？

A 星系 = 一个真实产品（读《图灵密约》）
B 星系 = 一个主题（读界面 / 读 AI 契约），跨仓库
C 干脆没有上层，课程平铺

D3 · 课程更新后，学习者的进度怎么办？

UniversityLocal 的规则：内容修订让课程回到未完成。对一个自学的人这是对的（内容变了就该重看），对付费学习者大概率是敌意的。

A 进度按课程保留，只标注「有更新」
B 按小节比对，只有变过的小节回到未完成
C 沿用上游规则

D4 · 免费额度的单位是什么？

「每天 N 次辅导」学习者能算清但对你成本不封顶；「每月 N token」对你安全但没人看得懂。

A 按「解释次数」计，内部换算 token
B 按课程数（前 N 节免费，全课程订阅）
C 混合：读与确定性判分永久免费，辅导按次

D5 · 私有源码的展示边界是什么？

已决定把「读真实商业产品源码」当卖点。那么评审闸门要有可执行的标准，而不是每次凭感觉：哪些目录永不出现、密钥形态之外还有哪些红线、竞品能从课程里复原多少。

这一条不是待选项，是必须写出来的清单。没有清单，闸门就是摆设。

D6 · 首发语言

现有课程内容是中文的。i18n 是已登记能力，但双语从第一天做会让每一幕的文案成本翻倍。

A 中文优先，结构上留好 i18n
B 一开始就双语
C 英文优先（内容要重做）

这一版明确不做

  • 联机与多人。不装 SwimmerGameServerKit。测验和本地复习不构成权威多人需求。
  • 让学习者上传自己的仓库生成课程。那是 UniversityLocal 的工作，把它搬进交付侧会同时毁掉成本模型和内容质量。
  • 在 WebGL 里做文本与输入。中文输入法、可选中复制的代码、无障碍、手机键盘在画布里全部退化，而且违反已注册的 Web3D 基线规则 7。
  • 写实画风与大世界。这是学习产品。地图存在的目的是让人知道自己在哪、下一步去哪。
  • 排行榜。在「懂了」还没做扎实之前，排行榜只会奖励刷题速度——那正好是学习的反面。
  • 把课程内容在本仓库里改一个字。内容的修改在 UniversityLocal 里做，重新导出。
