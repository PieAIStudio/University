University · 用户旅程 V2

2026-08-18 · 在本仓库内撰写 · 28 幕 · 六个阶段 · V1 是从外面写的投影，V2 是量过 52 门真课之后写的

V1 和 V2 最大的区别不是结论变了，是 V2 有数据。 V1 起草时没有人打开过导出包。V2 把 52 门课、146 单元、560 节课全部统计了一遍， 再回头看 V1 的每一条论断——有几条站不住，而且站不住的恰好是最贵的那几条。

这些数字由 pnpm journey 从 UniversityLocal 的导出包里现算，本页直接读它。 没有一个数字是手写的；哪天内容变了，重新跑一次这一页就跟着变。

先看界面

3D 的部分是能点的灰模，不是静态图。原因很实在：镜头怎么飞、层级怎么下钻、 八秒内找不找得到下一节课——这三件事在图上一个都看不出来， 而它们正是「做完之后还要不停地调」的来源。

灰模和线框都要 pnpm dev 打开（file:// 下浏览器会拦掉数据读取）。 用到真课文、真题、真卡片的那几张，还需要先跑一次带 --sample 的拉取命令。 每张界面怎么建、验收是什么，写在建造说明书里。

V1 里错的，逐条对账

只列被数据推翻的，不列见仁见智的。

① 成本模型的地基是错的 —— 这条最贵

V1 说
导出包自带 expectedAnswer，所以确定性判分零成本，且覆盖绝大多数交互。
实测
673 道 short-answer 确实全都带 expectedAnswer，但那是中文自然语言答案， 中位数 9 字、p90 24 字。真实样例：「因为共享上下文、顺序和控制信号，需要保持 per-channel 单个 in-flight batch」。字符串比对对这种答案召回率接近零。 更关键的是 UniversityLocal 自己就没有确定性判分——判分走 host-exercise-grade.ts，由 AI 编程宿主给出 passed。 expectedAnswer 是给判分者看的参考答案，不是匹配键。
所以
SPEC-0001 验收第 7 条（全确定性的课触发零次大模型调用）用今天的内容一节都过不了。 缺口总账把判分标成「移植一半」乐观了一整档。

修法不在运行时，在导入时。导入按包哈希发生一次，成本按课程摊销而不是按学习者摊销： 在导入流水线里用一次模型把每道题编译成机器可判的东西——可接受答案集合、关键词要点、 或用同单元其他答案生成干扰项变成点选题——产物连同包哈希固化，人工评审顺手一起审。 这样第一层才真是零边际成本，而且不需要改 UniversityLocal 一个字。

② 首次五分钟预算按错的尺度估了

V1 说
「读课文」120 秒，全程 333 秒，超支 33 秒且全部来自注册。
实测
课文均值 2363 字符、最长 4903，全库 964 段代码围栏（692 段 TypeScript）。 阅读器线框用一节真课渲染出来是 2606 字 + 3 段代码， 按中文技术阅读 300 字/分钟算是 ≈9 分钟。
所以
真实首课是十分钟量级，不是五分钟。这不是措辞问题——V1 那张预算表是拿假数据估的， 它把这个产品的核心动作按「Duolingo 一句话一题」的尺度估了。 要么承认首课十分钟并据此重排注册位置，要么在导入侧引入「首课特供短课」的概念。

③ 「一门课 = 一块大陆」和真实体量不匹配

V1 说
一门课 = 一块大陆，镜头从星图推近。
实测
52 门课，体量从 1 节到 41 节，中位 12。四个 study 的拓扑完全不同： buzz 完全平铺（0 条先修关系），supaluv 是一条 7 环的链， university-local 是链加末端三叉，turing-pact 是深 14 层的树—— 九级主干，然后一次炸出九条支线，再收窄。
所以
52 块大陆不是星图，是列表套了 3D 皮。内容里唯一真实存在的拓扑是先修 DAG， 其他层级只是文件夹。地图按树排，并且容忍不整齐——岛的大小由课时数决定， 41 节就是大岛，1 节就是礁石。要求内容先变整齐再做地图，就永远做不了地图。

④ 朗读不是「两边都还没有」

V1 说
朗读两边都没有，所以它是共享包价值的第一个真实检验。
实测
UniversityLocal 已有 src/language/speech.ts（Web Speech，选音策略写得很细， 明确不走网络）加 WordPopover 与 LessonWordList。
所以
论证塌了。共享包的第一个真实检验应换成内容键 + 进度推进规则 + FSRS 调度 （exerciseContentKey / lessonContentKey / reviewContentKey / advanceLessonProgress）—— 纯函数、两边都要、各写一份必然漂移。

⑤ 评审闸门的泄露面被低估了一档

V1 说
导入包携带源码路径、精确 commit 与行号，所以要有人工评审闸门。
实测
不止指针。逐字源码嵌在课文正文里——964 段围栏，含 SQL 建表语句， 1597 条证据锚点。另外一个包 6.8 MB，其中 6.1 MB 是四张内联成 base64 的截图， 单张最大 2.86 MB。
所以
闸门要做成导入时可执行的检查 + 对包哈希的一次人工签署，不是每次凭感觉。 而且它在缺口总账里应该有独立一行，不能并进「导入」里。 截图那条另说：写课技能今天才开始建议用截图，第一张就 2.86 MB， 560 节课每节两张就是 3 GB——现在管很便宜，以后管很贵。

⑥ 「读真实商业产品源码」只覆盖一部分课

V1 说
把「读一个正在赚钱的产品的源码」当卖点，一句话说清差异。
实测
turing-pact 的 31 门里有 9 门 foundations-*（139 节，深度 0–8 的整条主干）， 它们是拿 TuringPact 源码当教具的通识工程课：什么是 App、代码是什么、 怎么读一行代码、什么是异步。那不是「读商业产品」，那是「从零学工程」。
所以
两类课的人群、定价、评审风险都不同，V1 把它们当一种东西。首发排课应分开： foundations 系列免费获客，产品剖析课订阅。这也顺手回答了 D4。

V1 漏掉的幕

下面镜头墙里带 V2 新增 的六幕，V1 一幕都没有。它们不是锦上添花，缺了会直接出事。

镜头墙

默认按学习者真实经历的顺序排。

快乐地图

柱高是快乐强度，颜色是快乐的种类。零高度不是「做得差」，是纯支出。

V1 的三条结论我保留两条，改一条。 保留：唯一抄不走的快乐是「懂了」，而它发生在 2D 课文里；两段最长的零回报都在「要东西」的时候。 改的是第三条——V1 说第二天回来的理由是那张卡。对，但不完整： 第二天回来的前提是第一天读完了，而按实测，第一天要读九分钟、看三段真源码。 所以真正的第一风险不是「第二天忘了回来」，是第一天没读完就走了。 V2 因此把「答错之后」和「判错申诉」补成独立的幕：那是第一天最容易断掉的地方。

首次一节课的真实预算

从点开链接到第一次结算。V1 的总预算是 300 秒；下面是按实测重估的。

合计约 11 分钟。这不是把 V1 的预算调大一点，是换了一个量级。 结论也跟着变：五分钟内不可能完成一节课，所以别把注册往五分钟里塞—— 注册仍然排在第一次结算之后，但理由从「预算超支」变成了「他刚花了十一分钟， 现在手里第一次有值得保护的东西」。

坏掉的时候，他还知道下一步吗

「重试」不是出路，出路必须换一条路。加粗的两行是 V2 新增。

坏在哪他看到什么出路
3D 地图加载失败 / 弱 GPU地图转不出来或帧率崩自动降级到 2D 列表视图，结构完全一致。灰模里那个开关就是它。
判分判错了（他认为自己对）明明答对却被判错V2 新增。一键「我觉得我对了」→ 升到下一层判分一次，这次不计费。分层判分必然产生这种故障，而且比模型超时高频得多。这条直接决定第一层能不能激进使用。
在线模型判分超时提交后卡住确定性判分本来不需要模型，先出结果；开放题降级为「先记下来，稍后给你讲」，卡片照常入库。
免费额度用尽辅导按钮变灰说清剩下能做什么（读课文、做确定性题、复习全部可用），而不是锁上整个产品。
离线 / 通勤断网什么都点不动已导入课程与到期卡片本地可用，判分排队。复习是最该离线可用的那一部分。
课程被作者重新导出进度看起来消失了按内容键逐节比对，只有变过的小节标「有更新」，进度不清空。见 D3。
已上架课程因 IP 事故被撤下正在学的课不见了V2 新增。已购学习者保留只读访问与全部到期卡片，不再计入新销售；如果必须彻底下架，按未学完比例退款。上架方向 V1 设计了，撤架方向没有——而后者是「上架私有源码」这个决定的对偶风险。
课程包校验失败课程打不开课程不上架，学习者根本看不到。校验发生在投放之前。
6.8 MB 的课程包在手机上点开课程转圈很久导入时把素材抽成独立文件按需加载；课文先到，图后到。自包含是运输格式，不是运行时格式。

成本：分三层，但第一层要先造出来

层用在哪成本V2 的修正
0 导入时编译 把 673 道自然语言答案编译成机器可判的答案键 按包哈希一次，可摊销 V2 新增的一层。没有它，下面第 1 层是空的。它同时是评审闸门的天然工位。
1 确定性比对编译出来的答案键零边际成本V1 以为它现成，实际要先有第 0 层。
2 小模型 + 结构化输出答案键判不了、但语义明显对的作答极低经 SwimmerAIKit，输出受 schema 约束，不走对话。申诉走这一层，且不计费。
3 开放辅导「我还是不懂，给我讲讲」可观且随使用增长付费墙的位置。免费层不得提供不计量的大模型对话。

缺口总账

按「什么最先杀死第二次打开」排。和 V1 相比动了四个地方，理由写在最后一列。

#缺口来源相对 V1
1课程包导入 + 校验全新不变。没有它一节课都投放不出去。
2评审闸门（可执行清单 + 对包哈希签署）全新独立成行。V1 把它并进第 1 行，但正文里嵌着逐字私有源码，它是硬门不是附属品。
32D 课文阅读器（代码块、证据锚点、选中标记）可移植不变。护城河，且上游已验证。
42D 导航（课程 / 单元 / 节，先修可见）全新提前。V1 把它藏在第 5 行的括号里当「3D 的降级」。实际上垂直切片就需要它，先做它，3D 后面覆盖上去，「结构一致」才是自然成立而不是事后补。
5答案键编译 + 确定性判分 + 卡片入库全新从「一半」改成「全新」。见上面对账①。它是免费层经济模型的承重墙。
6到期复习与召回可移植不变。第二天回来的唯一实质理由，引擎现成。
73D 地基（单 renderer / 色彩管线 / DPR clamp / 音频解锁 / 一层 grade）全新拆出来单独一行。这五条必须在第一次 <Canvas> 一次付清并撤销 portfolio 例外。混在「做地图」里做，是三件事挤一次改动。灰模已经按这五条写了，可以直接抄。
8世界地图与关卡链全新仍在第 8 位。它决定「愿不愿意开始」，但漂亮地图通往糟糕的课只会让人更快离开。
9账号与结算（SwimmerBackend）外部件不变。第一次结算之后才需要。
10分层判分第 2、3 层与计量全新不变。在有人愿意回来之前，付费墙无人可拦。
11分级、面板与动态调整全新新增。上游已有一个写死在组件里的雏形，见 D7。
12连击、角色成长、装扮全新不变。包装层，没有可放大的东西时等于零。

3D 从第 5 变成第 7 和第 8，但这不是降级，是拆分。 地基那一行完全可以很早做——场景可以是空的。真正该等的是地图内容。

待决项：V1 的六张，加 V2 的三张

这一版明确不做

  • 联机与多人。不装 SwimmerGameServerKit。
  • 让学习者上传自己的仓库生成课程。那是 UniversityLocal 的工作。
  • 在 WebGL 里做文本与输入。违反已登记的 Web3D 基线规则 7，而且中文输入法、可复制的代码、无障碍、手机键盘在画布里全部退化。
  • 可操控的 3D 小人。见 D1。它要 Rapier 物理，donor 目录对本产品的标注就是「先不要装」。
  • 写实画风与大世界。地图存在的目的是让人知道自己在哪、下一步去哪。
  • 排行榜。在「懂了」还没做扎实之前，排行榜只奖励刷题速度。
  • 把课程内容在本仓库里改一个字。内容的修改在 UniversityLocal 里做，重新导出。
  • 为了让地图好看而先重构课程划分。地图容忍不整齐；内容规范化是内容自己的排期。
