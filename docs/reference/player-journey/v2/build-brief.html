建造说明书

给执行者（人或子代理）的六张界面规格 · 每张都能独立完成 · 完成标准写在每张里

这份文件的存在，本身就是对「怎么才不会不停地调」那个问题的回答。 一张精致的图交给执行者，得到的是像素级复刻加无穷的返工； 一句可测的验收 + 真数据边界 + 状态清单交给执行者，一次做对的概率高得多。 所以下面每一张都只有这三样，没有配色、没有间距、没有动效曲线。

所有界面共同遵守的六条

1 · 骨架照抄现成的。 新页面直接复制 screens/reader.html 的外壳：crumb → h1 → sub → .accept → 内容 → .scope → .notes，样式一律来自 ../lib/journey.css，不新增全局样式，页内 <style> 只放这一页独有的东西。
2 · 颜色来自 SwimmerUIKit，不自己发明。 产品界面部分 import "@pieai/swimmer-ui-kit/styles.css"， 用 --game-ui-* 变量。唯一允许自定义的是阅读字号与行高， 并且必须像 reader.html 那样写明「这是 kit 缺的、将来属于 university-kit」。
3 · 真数据，不许 Lorem。 结构数据读 ../data/taxonomy.json；需要课文、题目、答案时读 ../data/sample-lesson.json（未生成时给出生成命令，不要伪造内容）。 读不到就显示怎么生成，不要静默降级成假数据。
4 · 桌面 + 375px 手机并排。 用 .frames / .frame / .frame.phone。 页面本身永不横向滚动；宽内容（代码、表格）在自己的容器里横滚。
5 · 四种状态必须画出来，不是写在注释里。 空 / 加载 / 错误 / 受限（额度用尽或未解锁）。做成可切换的 chip， 像世界地图那个 2D 降级开关一样能点。
6 · 画布里不许有文字和输入框。 已登记的 Web3D 基线规则 7。中文输入法、可选中复制的代码、无障碍、 手机键盘在 WebGL 里全部退化。

六张界面

① 答题 · 判错 · 申诉

screens/answer.html · 对应第 10、11、12、13 幕

验收
答错一次之后，屏幕上必须出现一条指回课文原句的线索，而不是重复题面。 并且从判错到发起申诉不超过一次点击。
真数据
用 sample-lesson.json 里那道真题：due-column-name， 题面「card_state 里表示「下次该什么时候问」的列名是什么？」， 参考答案 due_at。 注意全库只有两种题型：short-answer 673 道、explain 32 道， 没有选择题——所以「答对扣血」的节奏要靠导入时编译出来的选项， 这一屏要把「编译出的四选一」和「自由作答」两种形态都画出来。
必须有
  • 三层判分的可见差别：确定性（立刻）／小模型（转一下）／导师（付费）
  • 答错第一次 → 线索卡：引用课文原句 + 那段源码的位置
  • 答错第二次 → 才出现导师入口
  • 「我觉得我对了」申诉按钮，旁边写明不计额度
不许
把答错做成打叉、扣血音效、红色闪烁。错是学习的正常一步，不是惩罚。

② 结算与卡片掉落

screens/settlement.html · 对应第 14、15、16 幕

验收
屏幕上必须出现「明天 N 张」这个具体数字， 而且它要比连击数字更显眼。没有它，连击只是一个数字。
真数据
卡片用 sample-lesson.json 的 2 张真卡（front/back）。 全库 1236 张卡全部是 basic 类型，没有 cloze，掉落展示不要画出不存在的卡型。
必须有
  • 掉落的是卡片不是金币；卡片正面可翻
  • 「明天 N 张到期」+ 连击第 1 天
  • 注册请求：措辞是「保存你刚拿到的东西」，不是「创建账号」
  • 注册可跳过，跳过后本次成果仍然保留到本地
不许
在注册之前索取任何信息；把注册做成必经闸门。

③ 复习关

screens/review.html · 对应第 17、18 幕

验收
断网状态下这一屏完全可用（把离线做成能点的状态，不是写在注释里）。 通勤是它最大的使用场景。
真数据
从 taxonomy.json 里跨 study 抽到期卡片—— 到期卡片来自全部 study，不只是当前主攻的那一个， 这是上游 LearningFocusSchema 的既有规则，照搬。
必须有
  • 先回想再看答案：答案在点击之前不可见
  • 四档反馈（忘了 / 困难 / 一般 / 简单）对应 FSRS 评分
  • 每张卡能跳回它来自的那一节课
  • 手机形态是主形态，桌面是次要的——和其它屏相反
不许
把复习做成一个列表页。它是回到地图上已通关的区域。

④ 导师对话与付费墙

screens/tutor.html · 对应第 20、21、22 幕

验收
额度用尽时，学习者仍能完整走完一节课—— 这一屏要能切到「额度耗尽」状态并证明只有辅导按钮变灰。
真数据
对话内容围绕 sample-lesson.json 那节课的真实概念，不要编造别的课。
必须有
  • 入口只有两个：答错两次、主动点「我不懂」。入口越窄成本越可控
  • 每次对话显示消耗了几次额度，剩余多少
  • 付费页出现在刚被讲通一次之后，并且不打断当前这次解释
  • 额度耗尽状态下：读课文、确定性判分、复习全部照常
不许
做成无限对话框；把付费页做成弹窗遮挡正在读的解释。

⑤ 2D 降级导航

screens/nav-2d.html · 缺口总账第 4 行

验收
和 3D 世界地图结构完全一致：同样的 study → course → unit → lesson， 同样的先修关系，同样的解锁状态。把两边并排放，任何一项对不上都算不通过。
真数据
全部 52 门课、146 单元、560 节。这一屏必须一次性承受完整体量， 这是它相对灰模的价值：灰模可以只画一个 study，列表不行。
必须有
  • 层级可折叠；深度 14 层的链要能读懂
  • buzz 那 5 门没有先后的课要如实显示为平铺
  • 键盘可完整操作（这是它存在的第二个理由：无障碍）
  • 它是先于 3D 存在的，不是 3D 的降级——垂直切片就用它
不许
为了好看而隐藏层级或重排顺序。它的唯一职责是诚实。

⑥ 分级问卷与面板

screens/placement.html · 对应第 3、26 幕

验收
面板上必须同时出现「你当初说 X」和「我们看到的是 Y」两行， 并且改起点的按钮写的是「手动覆盖」的意思，不是「重新测一次」。
真数据
题面照抄上游 CourseRouteQuiz.tsx 里那三道真题， 入口点用 foundations-* 那条九门课的真实链。
必须有
  • 作用范围是整个系列课（foundations 那九门），不是单门课
  • 答完即永久保存；再次进入不重复询问
  • 面板可查、可覆盖；覆盖后记录「这是你手动改的」
  • 推荐起点但不锁其他课
  • 难度旋钮只能动三样：起点、跳过粒度、复习强度。不能动题目难度——题目是导入的固定内容
不许
做成两个并列的真相源。真实表现一旦存在就优先于自评，面板要如实说出这一点。

交给子代理时，额外的三条

一次只给一张。 六张一起发出去，回来的是六种风格。一张做完、验过、合并，再发下一张。
报告不算证据。 「已完成、全部通过」这句话本身不构成完成。合并前必须由主控在浏览器里 打开、截图、跑一遍验收句。这一条不是不信任，是这个项目已经两次被 「报告说完成了但实际没有」绊住：一次是 41 节课的重写躺在工作区没提交， 一次是导出包停在前一天而所有门禁都是绿的。
先给一张试水。 换新执行者的第一张一定是最小的那张，用来校准风格和精度， 而不是把最难的那张交出去赌一把。
