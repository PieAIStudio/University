验收

进来 3 秒内说出「这门课还剩几节」和「下一关是哪一个」，不用滚动、不用点开任何东西。

这一页负责：一门课的路径形状、单元怎么分段、进度怎么一眼看出、极端体量会不会崩。 不负责：课文长什么样（那是阅读器那一页）、颜色、材质、过场动画。

为什么是蛇形

  • 单元里 93/146 恰好 4 节，所以一段就是四步，节奏是内容自带的，不是设计出来的。
  • 一条直路放 41 节 = 一条看不到头的走廊。折返之后，41 节和 12 节用同一个形状，都能一眼看完。
  • 单元之间抬一级台阶。台阶是「这一段结束了」的物理信号，不需要文案说。
  • 只有 1 节的课（founder-engineer）也照样成立：一块台阶、一个关卡。它看起来太小——那是内容的问题，地图如实显示，不替它遮掩。

「还剩几节」为什么是最大的那个数字

  • 学习者在这一屏只问两个问题：还剩多少、下一步点哪。别的都是次要的。
  • V1 的结算屏验收要求出现「明天 N 张」，同一个道理：进度要给具体的数，不是一条百分比的进度条。
