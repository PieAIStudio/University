答题 · 判错 · 申诉 · 线框

2D · 第 10–13 幕 · 用一道真题驱动 · 可以真的答错两次走完整条路 · 需要 pnpm dev 打开

验收

答错一次之后，屏幕上必须出现一条指回课文原句的线索，而不是重复题面； 从判错到发起申诉不超过一次点击。

这一页负责：三层判分的可见差别、答错第一次给什么、答错第二次才给什么、申诉入口在哪、额度耗尽时哪些还能用。 不负责：血条动画、音效、最终配色、导师对话本身（那是另一屏）。

为什么要画两种题型

  • 全库只有 short-answer 673 道 + explain 32 道，一道选择题都没有。
  • 「答对扣血」的战斗节奏需要快速判定，而快速判定需要选项。
  • 选项从哪来？导入时编译（待决 D8）——用同单元其他题的答案当干扰项，按包哈希生成一次，人工评审时一并审。所以左边那一屏是「编译产物」，右边是「原始形态」。
  • 这不是把内容改了。原题、原答案、原证据一个字没动，只是多了一层机器可判的外壳。

三层判分为什么要让学习者看见

  • 成本是产品的一部分，不是藏起来的实现细节。看得见，学习者才理解为什么「讲给我听」是要付费的。
  • 第 1 层立刻出结果，第 2 层转一下，第 3 层要额度——这三种手感差别本身就在教用户成本结构。
  • 申诉走第 2 层且不计额度。因为误判是分层判分必然产生的故障，让学习者为系统的误差付钱是错的。

状态

  • 加载：题面骨架先到，不闪空白。
  • 额度耗尽：只有导师按钮变灰，答题与申诉照常——这是验收第 22 幕的地方。
  • 读不到题：给出生成命令，不伪造题目。
  • 离线：确定性判分本地完成，第 2 层排队。
