## 执行约定

- `[x]` 只用于有对应证据的完成项；`[ ]` 后注明待做、进行中或待验收。
  “代码已写”与“验收通过”分开记录。
- 稳定编号不重排；新发现接在所属块末尾。一个任务完成时补充文件、验证结果、
  下一步或遗留疑问，使用文末回执表，不在另一处维护重复任务列表。
- 执行安排与文件所有权以最新回执和实际进程为准，不把历史的桌面/Web 交接当成当前派工。需要委派时沿用用户偏好的 Gemini/Grok CLI 有界子任务，根代理负责视觉、架构判断和最终验收；模型不可用时报告事实，不让登录阻断独立可做的工作。
- 每个执行器限定文件所有权；后续任务不得在前一执行器仍写文件时抢占。
  CLI 帮助与模型 ID 以实际安装版本为准；不靠猜测切换模型。
- `SCRATCH/` 与 `/tmp/` 是本机证据/进程材料，不是跨机器保存的承诺。
  检查摘要、验收结论与提交 ID 必须回写本文件或相应 ADR。
