# 3D 世界交付清单

本文件是当前 3D 工作的唯一任务清单。用户要求在额度中断后能直接接续，
并明确授权重构程序化算法、改善小节标记、统一模型尺度与摆放逻辑。
课程编写由另一条工作线负责；本计划只读取既有课程与进度合同。

先交付一座好看、能操作、成本可控的连续课程岛，再扩展到系列岛群和全局世界。
**A–G 与 H01–H04 是首岛交付工作；其余是后续升级队列，不全部阻塞首发。**
产品行为以 [V5 决定 I–L](../../reference/player-journey/v5/index.html) 为准；
技术选择与预算以 [ADR-0008](../../adr/ADR-0008-one-locked-technique-per-island-element.md)
为准；数据来源遵循 [ADR-0009](../../adr/ADR-0009-the-procedural-map-is-one-pipeline.md)。
本计划记录执行状态，不复制资产登记表或另立渲染规范。

## 执行约定

- `[x]` 只用于有对应证据的完成项；`[ ]` 后注明待做、进行中或待验收。
  “代码已写”与“验收通过”分开记录。
- 稳定编号不重排；新发现接在所属块末尾。一个任务完成时补充文件、验证结果、
  下一步或遗留疑问，使用文末回执表，不在另一处维护重复任务列表。
- 主代理负责判断和验收；编码、查资产、批量检查优先交给外部 Grok/Gemini。
  Claude 可用时指定用户允许的 Opus 5。不要创建 Codex 自身模型的子代理。
- 每个执行器限定文件所有权；后续任务不得在前一执行器仍写文件时抢占。
  CLI 帮助与模型 ID 以实际安装版本为准；不靠猜测切换模型。
- `SCRATCH/` 与 `/tmp/` 是本机证据/进程材料，不是跨机器保存的承诺。
  检查摘要、验收结论与提交 ID 必须回写本文件或相应 ADR。
