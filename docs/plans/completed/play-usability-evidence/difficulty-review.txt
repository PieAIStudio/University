## 结论与共享合同

采用 `ActivityFamily`，一个情境保留同一学习目标、同一 kind、三份明确的活动载荷；十个玩法仍只有十个引擎。不要把难度作为引擎入口的统一乘数，也不要让引擎按档位猜业务规则。主代理提出的 `ActivityBase.difficulty` 适合用于身份与展示；规则仍来自该载荷的具体字段。

```ts
type ActivityDifficulty = "starter" | "practice" | "challenge";
type ActivityOf<K extends ActivityKind> = Extract<LearningActivitySpec, { kind: K }>;
type ActivityFamily<K extends ActivityKind> = {
  readonly id: string; // 情境身份，不是某一档的定义身份
  readonly kind: K;
  readonly levels: {
    readonly [D in ActivityDifficulty]: ActivityOf<K> & { readonly difficulty: D };
  };
};
// 若收集异构 Family，使用映射后的判别联合，防止 K 被推成两个 kind 的联合。
type AnyActivityFamily = {
  [K in ActivityKind]: ActivityFamily<K>
}[ActivityKind];
```

可以用小工厂复用翻译、来源、节点和共同表达式，但输出应是三份可直接审查的完整载荷；不同规则要显式写出。Family 不必进入每个游戏组件。宿主选择 `family.levels[occurrence.difficulty]` 后，仍给 `LearningActivity` 一份载荷。

课程每次出现记录 `{ occurrenceId, familyId, difficulty }`，再绑定精确载荷 `id`。同一课允许“简单接线→困难调参→中等接线”，同一种也能再次出现。不要把 `seriesIndex`、课号、播放列表位置、第二个情境或语言映射成难度。已有二十情境可作为二十个 Family 的中档基线，再逐个编写较小任务和新增约束；不需要发明六十个故事。

这些仍是实验组件数据。未来 AI 配课只能经现有 authoring CLI、课程校验和发布合同导入，不能因加入 Family 就变成第二套课节 JSON 生产口。

## 十类最小有效分档

以下简单／中等／困难是作者预设的相对任务复杂度，不是经真人测量的能力等级。中档保留现有玩法价值；若调整现有完成合同，要明确记录，不能悄悄沿用旧的“完成”含义。

| 类型 | 简单：一个有意义的小任务 | 中等：现有核心体验 | 困难：增加什么判断／约束 | 最小实现方式 |
| --- | --- | --- | --- | --- |
| `connect` | 3 节点、2 条关系、单一路径；所有必要边由玩家建立并实际运行 | 当前 6 节点、5 边、成功和失败两个结果 | 加恢复／重试关系与对应路径，需要区别顺序、分支和回路；不能仅加一条原路径上的冗余边 | 纯 nodes/edges/probes；不必新增 initialConnections。若使用给定边，至少留一条真实决策，结果分开给定边和玩家边 |
| `tune` | 真正只留下一个变量，另一参数替换成模型常量；仍有上下相冲突的目标及可见结果 | 当前两变量同时调节，寻找满足各指标的配置 | 图片增加独立的最低宽度条件；批处理增加“少一个工作者时仍有最低产出”的第二运行条件。同一配置要兼顾正常与降级状态 | 现有有限表达式足够；不需要新引擎。不要把第二个可调参数仅藏起来 |
| `hunt` | 玩家找到一条真实反例 | 反例加一侧正常对照，说明问题不是所有输入都错；这是比当前首反例即结束更强的中档合同 | 故障边界下、边界上、边界上方都实际试过，结果中包含反例；证明边界位置 | 新增声明式对照要求和聚合判定，复用 evaluateHunt；UI 不可在首反例时提前锁定 |
| `dispatch` | 少量请求中包含第一次生产和一次真实复用，预算宽松 | 当前多通道、多个缓存键、实时请求与总预算 | 混合同名不同版本的缓存键、必须获取新结果的请求及复用，玩家判断“看似相同”是否真的可用；预算逼出选择 | 纯 cards/cacheKey/allowedLaneIds/budget；新版须有新 key，要求 fresh 的请求不带可复用 key |
| `program` | 小网格、1 次转向、宽松指令数，亲自写出可执行路径 | 当前障碍、检查点、重复次数与有限指令 | 新检查点不在原解上，必须改路线；预算促使压缩重复动作，所有合法解都通过 | 纯网格载荷。delivery 可加 (4,4)，maxCommands=7，见下方静态 witness |
| `ai-brief` | 题目明确给定 access/roster，玩家只澄清 confirmation；仍实际提交及检查名单；无客户变更 | 当前三个约定与一项后续变更，保留两轮真实试用 | 后续同时改两个相互影响的约定，并保持第三条；例如访问权限改变后，重新验证登录、报名与名单 | `initialChoices` 是最小扩展；给定约定公开显示并与玩家决策分开。followUp 已能表达两项变更，无需第三套流程 |
| `ai-context` | 1 个事实槽、1 位顾客、2 份冲突来源；找权威材料、重新生成并实测 | 当前 3 槽、5 文档、16 格容量，处理缺口和冲突 | 同样 3 槽改为 8 格：必须摘段并为反馈选等价权威来源，不能整篇装入；不是比谁省得更极端 | 纯 documents/slots/visitors/capacity；现有 3+3+2 格解可用，见下方说明 |
| `ai-agent` | source→draft 的读取／写作两步；手动授予必要文件能力并保留原件 | 当前有用写入混杂源文件破坏、材料越权指令、后续预览 | 必需动作涉及多个不同保留项，且预览依赖真实生成产物；玩家需审查具体目标并保留有用部分，不是只接受／拒绝整步 | 纯 files/tools/actions/goals。避免只增加等价写入步骤；不得把保留文件同时列为必须改写的目标，也不强迫先犯错再恢复 |
| `ai-eval` | 正常请求 + 1 类异常，亲手冻结并运行，发现一条未加检查的失败，修正后整组回归 | 当前四类条件、同题多次观察、产品检查与全组复跑 | 新增交叉条件用例，如同时缺信息且超范围，要求依据业务优先级选择预期；仍须保留正常任务能力 | 新增 requiredExpectations、requiredInputPatterns；不能删掉正常请求，不能直接替玩家生成全部验收题 |
| `ai-repair` | 2 个候选修改，较小产品场景；仍亲手复现、双版同路径验证、从空现场手工回归旧功能 | 当前 3 个候选与已有改约／持久化回归 | 预约可要求“保留 A，把 B 改成 C”，容量 2 让保留项成为真约束；偏好可要求多轮改选各自经过 reload 验证 | offeredPatches 可缩小简单选择；困难须补相应回归合同。仅将 minimumDistinctRegressionChoices 从 2 改成 3 是更多重复，不足以证明多了保留／持久化约束 |

具体静态依据：

- **Tune 图片现有 size 与 time 的目标等价。** `time = size × 0.008`，`time ≤ 1.2` 就是 `size ≤ 150`。不能用“3 个指标”证明三项独立约束。图片困难可增加宽度下限；批处理降级吞吐可用 `product(batch, max(0, sum(workers, -1)), 2)`，同一有限表达式树已支持。
- **Program delivery 困难示意解：** 新增检查点 `(4,4)`，`F2 R1 F4 R1 F2 R2 F4`。从 `(0,4,north)` 经过原两个检查点及新点，到 `(4,0)`；原五指令解漏掉新点。此为静态推演，未执行引擎，主代理应运行 witness 后采用。
- **Context 8 格可行包：** `brief-offering` 3 + `policy-limit` 3 + `summary-feedback` 2。反馈的权威文档已有 brief 和 summary 两个候选；选两份等价事实也可，但超过容量不能完成。该档必须同步更新 goal、hint、容量说明。

## 必要扩展及关键陷阱

1. **Brief 给定条件。** `BRIEF_AXES` 目前固定三项且全部必须已选。若加 `initialChoices`，题面必须明确是客户已定的约定；至少留一个待决定轴。结果保存 providedChoices 与 learnerChoices，最终真实产品行为仍按完整目标验收。给定初值不等于玩家学会了这些轴。
2. **Hunt 聚合证据。** 现有 `HuntGame` 的首个 counterexample 会立即锁定并发送成功。加入对照后，当前观察和整组完成必须分开。`threshold` 故障边界是 activity.boundary；`clamp` 当前错误是没做下限约束，故障边界是 **0**，不是上限 100。应由核心 helper 定义边界，不能由视图自行猜。无效输入与同值重复不补覆盖。
3. **Eval 覆盖。** requiredExpectations 默认保留四类；每档至少要求 fulfilled 与一个异常，否则“全拒绝”可能被当作好产品。hard 的输入模式应作为可解释要求显示，不能成为隐藏答案。若简单档从三次试跑降至两次，要重写明确的响应序列；商品示例的失败在第三次，直接 slice(0,2) 会删掉唯一盲点，导致不可完成或任务失去含义。
4. **Repair 约束。** 当前回归模型写死至少两种选择；预约必须取消后改选且最终只剩一单，偏好只要求末尾 reload。要求同时保留另一单需明确调整该回归条件，不能只把容量或选项数改大；要求每次改选持久化需逐次 reload 的真实轨迹。保留 authentic replay、当前实现验证与全手工来源检查；预设的 reproduceSteps 只作提示。

Connect 的给定边不是必需扩展；Context、Agent、Dispatch、Program、Tune 不必因难度新添策略开关。先用显式小任务和新约束，确实无法表达时才加领域字段。

## 重置、结果与课程身份

- **定义身份：** 同一载荷 id 必须永远指同一活动定义与难度；三档用不同 id，规则／完成合同修订后换 id。不必同时发明第二个版本系统，可以延续 README 的修订 id 约定。Family id 仅用于归类。
- **出现身份：** 课程中的每次出现有 occurrenceId；同一活动重复出现也不能互相覆盖。当前 Lab 的 playlist 按 kind 去重，只适合目前一次出现一种的示范，不能原样作为自由混课证据存储。
- **一轮身份：** 渲染 key 至少由 `occurrenceId + activity.id + round` 组成；重试新建一轮，三档切换新建一轮，取消未完成播放和延迟回调。报告结果至少有 activityId、difficulty、occurrenceId（或宿主绑定的等价上下文）及本轮身份。未完成切换不得假造完成或沿用另一档证据。
- **提示身份：** guided 不属于难度也不属于定义 id；随时开关不清空本轮，不改变要求、不补证据，不触发结果。提示使用情况继续单独记录。
- **宿主负责：** 每轮只发送一次 completed 或 skipped，结果追加到对应出现；完成小游戏继续只是本轮学习证据，不自动发 XP 或宣称课程完成。

## 给未来 AI 作者的最少规则

先写本次学习者需要亲自作出的决定，再选 kind，再决定每次出现的 difficulty。三档共享教学目标，但各自要写清：题目已给什么、玩家仍须决定什么、失败怎样显现、提交保留什么。困难档用一句话说明新增了哪项独立判断或约束；若只能写“更多／更快／更窄／更少提示”，应重写设计。

作者必须给每档一个私有可行 witness 和一个关键失败反例，走现有引擎核对。witness 属于维护验证，不进入学习者初始答案；初始状态不能已经完成。重复使用共同素材可以，不能以模板预填、点击继续、自动授权、自动重放或直接写 passed 代替玩家证据。对已有场景裁剪时，引用、访客、目标产物、预览依赖及 UI 文案必须一起一致。

## 可测试不变量与拒绝的捷径

- Family 三档齐全、kind 一致、载荷 id 各异且难度字段与槽位匹配；所有指向节点、文件、段落、工具、用例的 id 存在；非空必要任务和可行 witness 均成立。
- 每档分别有真实通过及接近但不足的失败：反例缺对照、评测全拒绝／漏交叉条件、返工原问题已修但旧功能坏、Agent 保留项被改、Context 当前版本未实测等，不依赖界面隐藏来阻止作弊式完成。
- 同一输入与历史下，guided 开／关给同一规则结果；切提示保留状态，切载荷／出现重置且旧回调失效。两次相同 kind 的不同 occurrence 均可保留独立结果。
- 预置条件可公开给定，但结果不能声称是玩家生成；无效或重复操作不能凑齐不同覆盖。简单档也必须有至少一次真实决定及其可观察验证。
- 拒绝三十套组件、按难度复制 evaluator、通用 difficulty multiplier、把第三次重复点击称为新判断、把 timer／隐藏说明等同于 hard、按课号自动升档、复用旧 id／旧证据、降低真实性门槛来让简单档快速变绿。

审查证据来自 `packages/core/src/learning-play/{types,connect,tune,hunt,dispatch,program,ai-brief,ai-context,ai-agent,ai-eval,ai-repair}.ts`、六份 UI 示例工厂、`LearningActivity.tsx`、`LearningPlayLab.tsx`、`HuntGame.tsx`、组件 README 与当前易玩度计划。仅本文件有写入；未构建、测试或浏览器验证。此评审不捕获为已验证项目 learning。

主代理收尾同步：已采用 Family、独立难度／出现身份、简单接线不预连、Brief 给定约定、复杂返工保留项与跨重开验证等建议。Hunt 当前实施选择为“简单较窄搜索区间／中等原区间／困难三侧证据”，不同于上表建议增加中档对照；这能缩小简单档的输入搜索空间，但不能据此宣称中档多学会一种判断。调参 batch 当前采用更紧产出要求而非降级情境，也应如实描述为约束收紧。后续独立体验复核再检查这些较弱的档位差异是否足够，静态评审不把它们认定为经过学习有效性验证。
