# 用 AI 做产品的五种玩法

用户保留前轮五种玩法，并要求新增至少五种以普通人指挥 AI 做产品为中心的互动。
沿用 `University-play` / `codex/learning-play-lab`，本轮基线 `f14383d`。
具体任务板在 `SCRATCH/ai-play-lab/tasks.md`。既有玩法保留；课程发布仍走既有 CLI。

## 学习者要练的判断

学习目标不是记代码，而是把意图说清、让 AI 看见必要事实、决定工具能做什么、
亲自检验产品是否按约定工作，以及带证据进行小步返工。界面继承现有 SwimmerUIKit
实验台；每个玩法都要有可操作对象，不能只给 AI 术语配一组选择按钮。

| 玩法 | 核心操作 | 可见后果与通关证据 |
| --- | --- | --- |
| 原型对焦台 | 消除模糊需求里的关键假设，构造一份可以验收的任务单 | 两种可能解释逐渐收敛；用户在真正可点的小产品里验证所需行为 |
| 上下文装箱 | 检查来源、选材料或摘片段，在本轮容量内整理必要事实 | 缺失/冲突影响工作结果；留下可追溯的上下文包，不以“越短越好”评分 |
| Agent 驾驶舱 | 配置工具范围，检查下一步动作，放行、限制或退回 | 行动改变沙盒中的名单、草稿或预览；拒绝一切不能完成任务 |
| AI 试车场 | 自己构造测试情境与可观察验收要求，冻结用例，再试方案 | 挑出单次漂亮输出掩盖的盲区，保留回归用例；没有隐藏的“最佳模型”答案 |
| 返工时光机 | 在小产品里复现失败，附证据提出局部修改，检查旧功能，必要时回退 | 修改前后行为真正变化；删掉按钮或错误路径不能算修好 |

每种有两个产品情境；可独立使用，也可作为一次产品迭代的五个环节。
成功后给出可以带到真实项目的任务单、上下文包、授权说明、回归清单或修改单。

## 已推翻的方案

- “提示词拼图得分”：关键词覆盖率既不代表表达正确，也不预测模型质量，淘汰。
- “看三条 AI 回答选最佳”：本质仍是选择题，改成先构造并冻结测试再运行比较。
- “游戏里把 AI 一律挡住”：这会教会无效监督，授权玩法必须有实际任务产物。
- “用分数条代演产品变化”：原型与返工必须有可点、可重放的小产品。
- 不按网页/CLI 外观固定判断工具能力；按本回合实际提供的能力与权限判断。

## 方法与诚实边界

本轮采用明确标注的教学沙盒与预设 AI 案例，确定性规则可复核；不伪装正在调用模型，
不把脚本结果解释成某个真实模型的成功率，不收集真实用户资料，也不执行外部动作。
开放文本不做关键词判分；实际模型调用继续由既有端口和 SwimmerAIKit 管理。

Anthropic 的上下文工程实践支持按任务筛选信息、保留必要上下文和来源、随工作进展调整材料；
“最小”不等于越短越好，因此装箱玩法容许多个充分的材料组合。
来源：[Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)。

Anthropic 的评测实践区分任务、一次运行、评分方式和最终结果，提醒随机性、多次运行、
确定性检查与真实目标对齐。本轮据此让测试先于方案选择，并保留实际输入和行为证据。
来源：[Demystifying evals](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)。

Microsoft 的人机交互指南强调能力边界、有效纠正与用户控制；这里把它们落实到工具权限、
可撤销的检查点和就地修正，而不是增加一层强制确认。
来源：[Guidelines for Human-AI Interaction](https://www.microsoft.com/en-us/research/publication/guidelines-for-human-ai-interaction/)。

沿用前轮 IES、PhET 的操作—观察—解释设计依据。这些材料用于提出可检验的设计假设，
不是对本组件的学习效果证明。真人试学应看无提示操作、能解释一次失败、换情境迁移。

## 十个情境与迁移

| 玩法 | 两个情境 | 本轮可以带走的工作单 |
| --- | --- | --- |
| 原型对焦台 | 社区散步报名 / 会员活动报名 | 行为约定及实际提交、登录与名单验收 |
| 上下文装箱 | 咖啡预订页 / 手作工坊报名页 | 来源明确的材料包与事实制作单 |
| Agent 驾驶舱 | 活动邀请草稿 / 食谱与采购清单 | 工具与文件范围、执行记录及保留的原始资料 |
| AI 试车场 | 体验课预约助手 / 文具店助手 | 正常、缺信息、不可用、越界四类回归与产品检查 |
| 返工时光机 | 重复预约 / 重开丢失偏好 | 原始失败、局部修改、重放、旧功能回归与检查点 |

五种主操作分别是试用产品、整理证据、控制行动、构造试验和回放修改。
悬念来自可见后果：两份都能跑的原型为什么不同，哪段材料造成冲突，
放宽编辑范围会改坏什么，同一个方案为什么会在相同问题上给出不同结果，修好一个问题为何又破坏旧功能。
这是对探索乐趣的设计假设；不以选项数量、动效数量或脚本通过率替代真人体验结论。

## 本轮推翻与修正

| 证据 | 改变 | 守住的行为 |
| --- | --- | --- |
| 研究审查发现“看答案选方案”仍是选择题 | Eval 先让玩家造输入、定要求、冻结用例 | 改用例必须重跑；不同方案可配不同边界通过 |
| 原型只对齐条款仍可能没有实际试用 | 验收绑定当前约定下的真实操作记录 | 改动条款清空旧观察；会员名单也检查登录入口 |
| 装箱编辑后仍显示旧制作单 | 显式标记旧结果待重跑，保留实验历史 | 14 格整份材料与 8 格摘录都可形成充分证据 |
| Agent 原始资料遭破坏后容易忘记权限仍过宽 | 检查点恢复文件、保留当前授权和审计；按工具能力与文件交集执行 | 全拒绝不能交付；读取器不能冒充编辑器 |
| 独立审查 IR-001：回看 Eval 记录清掉已通过的验收 | 回看使用缓存；同一候选不作废当前验收 | 更换候选、用例或边界仍须重跑 |
| 独立审查 IR-002：偏好重开后误报未提交 | 区分保存回执、重开载入与新选择待提交 | 原始版本的丢保存故障仍能实际复现 |
| 真实浏览器的长页反馈、切关位置与开关名称 | Brief 反馈滚入可见区；Next 显式回到活动起点；使用 kit 支持的 label | 手机和桌面回归包含反馈可见、标题可见与可访问命名 |
| 单轮设计 detector 的厚侧线与圆角漂移 | 反馈和对象改用细边线/浅底；收敛到现有圆角尺度 | 保留材料页、容量格、食物与时间轴的对象几何 |

没有增加模型调用、课程生产者、运行时脚本解释器或独立品牌控件。
共享核心及 UI 的单一实现同时服务 authoring 与 delivery。

## 用户追加的游戏性迭代

2026-09-08 用户再次强调必须具有游戏性，分别从玩家和设计者角度反复审视。
功能检查通过后，重新做一次不读答案的真实浏览器首玩；发现原型后半段偏填表、
装箱可以照开场配方直接过关、混合 Agent 步骤缺少就地调整入口、评测日志割裂、
返工候选名称提前泄露优劣。它们进入下一轮机制修改，不能以测试通过宣布结束。

已经实现并经对应 Chrome 路径验证的行为：原型增加同步探测与客户中途变更；装箱从有问题的材料包接手并让顾客实际验收；
Agent 把混合步骤拆成可控制的文件目标；评测匿名逐次试探并保留已发现的回归；
返工让同样操作同时作用于两个版本，玩家可回到分叉前继续试探。
即时设计、风险、循环与验证约定见 `SCRATCH/ai-play-lab/gameplay-design-iterations.md`。
这是现有品牌与教学沙盒内的机制迭代，不新增真实模型调用或课程发布渠道。


## 最终机制与选择理由

这轮先做功能版，再由不读答案的 AI 玩家真实首玩，随后分别从玩家和设计者角度推翻薄弱环节，改过核心操作，再用相同路径核对。没有用添加分数或倒计时来充当游戏性。

| 玩法 | 最终新增的可玩动作 | 适合放进课程的时机 |
| --- | --- | --- |
| 原型对焦台 | 同一操作试两份成品；首次收货后接客户变更，只改相关规则，重新试用 | 开始让 AI 做页面前，学会把愿望变成可观察行为 |
| 上下文装箱 | 接手有问题的材料包，招呼三位顾客，用实际错误追到来源，修好后再次试营业 | 给 AI 读需求、文档或项目资料前 |
| Agent 驾驶舱 | 看见即将读写的文件和拟改内容，在文件旁改权限，推进到判断点；可以犯错再恢复 | 从“让 AI 回答”转为“让 AI 动手”时 |
| AI 试车场 | 给匿名方案出题，一次揭示一份响应，发现同题反差；收藏失败并建立整组验收 | AI 的一次漂亮输出让人准备收货时 |
| 返工时光机 | 两版同时接受动作；拖动或逐步查看历史、跳到首次不同、从中途接新操作 | 准备让 AI 修 bug 或改已工作的产品时 |

玩家角度的复核将 Context、Agent、Eval 原列薄弱点判为有可见改善；Brief 与 Repair 保留部分结构化解题路径。这个判断没有被改写成全绿：Brief 的需求事实仍通过询问获得，Repair 仍展示修改范围，熟悉业务的人可能在试用前判断风险。我保留这两点，因为明确约定和读懂修改范围本身就是学习动作；没有用隐藏必要信息来强迫猜答案。两关仍须操作实际产品才能验收，不能靠选对说明通关。原型适合作为低门槛入口，评测与返工更适合让学习者主动探索后果。

设计者在机制改动后另外发现并修正两个具体问题：纯手工回归中途分支丢失核对入口（GD-001），以及切换候选沿用前一份方案的通过提示（GD-002）。维护的 Q 用例分别覆盖手工回退后继续验收、未测方案不借用旧成功提示，并保留旧候选自己的有效记录。
