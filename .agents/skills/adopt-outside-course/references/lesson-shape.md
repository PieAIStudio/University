# 一节课装什么

六个小节的顺序是固定的，因为它就是一个人学会一件事的顺序：
知道要学什么 → 先拿到答案 → 用熟悉的东西接住它 → 看它真的跑起来 → 自己试 → 记住该记的。

## 六个小节

### `## 学习目标`

一句话，动词开头，写**读者读完能做到什么**，不是"了解"什么。

- 好：「读完你能自己写出一个按钮的三种状态，并说出每种什么时候出现。」
- 坏：「了解按钮的交互状态。」——"了解"没法验证，也没法自检。

**只有一个动词。**出现"并且"「同时」就该拆成两节。

### `## 先给结论`

**答案放最前面。**不要铺垫，不要"我们先来看看历史"。

初学者读教程最常见的挫败是读了三段还不知道这段要说什么。
先给结论之后再展开，读者是带着答案在验证；先铺垫再给结论，读者是在雾里走。

三到五句，说清楚这一节的那件事是什么。

### `## 一个类比`

硬性小节。写法和判据见 [rewriting.md](rewriting.md) 的「类比怎么写才算数」。

一段就够。**类比失效的地方也要写出来**，否则读者会一路用错。

### `## 工作示例`

一个**具体的、能看见的**例子，从头走到尾。

通用课没有代码仓库，所以这里不是 `[[evidence:]]` 锚点，而是：
一段可以照做的操作、一段可以复制的代码或文字、一个自己写出来的对话、一张自己画的图。

**例子必须是自己造的。**不要把参考的那门课里的例子搬过来——
连图带例子一起搬，就不再是"照着提纲重讲"，那是复制。

**必须是完整的一次**，不是片段。初学者卡住最常见的原因是例子只给了中间三步。

### `## 自检`

两部分，都要有：

1. **做对了会看到什么**——一句具体的、能对照的描述
2. **最常见的两种做错了会看到什么**——以及各自怎么回去

第 2 部分是外部课程最缺的，也是初学者最需要的。
只写正确路径的教程，等于假设读者不会出错。

### `## 重点`

三到五条，每条一行。这些会变成记忆卡片的来源。

**每一条都要能脱离课文单独成立。**写「见上文那个例子」的条目，
半年后在复习队列里弹出来时是一句废话。

## 卡片

- **一节课最多 4 张。**超过就是把复习队列冲垮，门禁会拒。
- **有卡片就必须有练习。**没有练习，卡片永远进不了复习队列——门禁也会拒。
- **正面是问题，背面是答案。**背面必须自己站得住：
  禁止出现「见上文」「见前文」「如上所述」「参见上面」。
- 卡片考的是**这一节最值得记住的事实**，不是最容易出题的细节。
  「按钮的三种状态是什么」是好卡片；「transition 的默认时长是多少毫秒」不是——
  那是查得到的东西，不该占用一个人的长期记忆。
- **每张卡片自己也要带 evidence。**门禁会查。
  理由是对的：卡片会脱离课文单独弹出来，一个人在复习队列里看到一条断言，
  应该能顺着它查到出处。**课文有出处不代表卡片有**——它们是分开读的。

## 练习

- `kind` 用 `short-answer`，让人用自己的话写。
- `expectedAnswer` **要短**。判分是做归一化比对的，
  一句三十字的标准答案会把答对的人判错。
- 题目问的应该是**理解**，不是记忆——记忆交给卡片。
  「为什么按钮要有 hover 状态」比「hover 的中文叫什么」好。

## proposal 的形状

```json
{
  "unit": {
    "id": "kebab-case",
    "title": "……",
    "objective": "读完这一单元你能……"
  },
  "lessons": [
    {
      "id": "kebab-case",
      "title": "……",
      "content": "## 学习目标\n……\n\n## 先给结论\n……",
      "evidence": [
        {
          "kind": "fact",
          "note": "读者能看到的一句话，说明这条出处证明了什么",
          "sourceUrl": "https://developer.mozilla.org/zh-CN/docs/Web/CSS/…",
          "sourceTitle": "MDN · ……",
          "sourceAuthority": "mdn"
        }
      ],
      "cards": [
        { "id": "kebab-case", "front": "……", "back": "……（自己站得住）" }
      ],
      "exercises": [
        {
          "id": "kebab-case",
          "title": "……",
          "kind": "short-answer",
          "prompt": "……",
          "expectedAnswer": "短",
          "evidence": [{ "kind": "fact", "note": "……", "sourceUrl": "…" }]
        }
      ]
    }
  ]
}
```

所有 id 必须是 kebab-case（小写字母、数字、连字符），标签也是。
一个 camelCase 的标签会在最后写盘那一步被拒——那时整门课都已经生成完了。

## 门禁会拒的事（先自己看一遍，比被拒了再回来快）

- 六个小节缺任何一个
- 出现：众所周知 / 显而易见 / 简单来说 / 不言而喻
- 卡片背面出现：见上文 / 见前文 / 如上所述 / 参见上面
- 卡片多于 4 张
- 有卡片但没有练习
- 任何 id 或标签不是 kebab-case
- id 重复
- 任何一条 evidence 缺 `note`
- 通用课的 evidence 缺 `sourceUrl` 或 `sourceAuthority`（由 `check-adoption.mjs` 管）
- **evidence 指向了被参考的那门课**（`check-adoption.mjs` 直接拒，没有例外）


## 出处只能指向权威原始资料

`sourceUrl` 指向 MDN、RFC、官方文档、规范。**不指向我们参考的那门课，一次都不行。**

`sourceAuthority` 是个短标签，用来在界面上显示出处的份量：
`mdn` / `rfc` / `w3c` / `official-docs` / `spec`。
不在这个清单里的，先想清楚它凭什么算权威。

**为什么这条比看起来重要：**
一个说法找不到权威出处，通常不是因为没人写过，
而是因为它其实是某个人的经验或习惯。经验可以讲，但要讲成「很多人这么做」，
不能讲成「事实就是这样」。**这条规矩因此顺带挡住了课文里最常见的一类错误。**
