# 纳入别人的课

## 这个技能存在的理由

别人的课有三样东西值得拿：**结构**（讲什么、按什么顺序）、**例子**（他挑的案例
往往比现编的好）、**图**（他画的示意图是他想清楚的证据）。

**正文也要读，而且要反复读。** 这一条曾经写反过：技能最初禁止把正文存盘，
理由是「存下来早晚被复制进课文」。那条规矩防住了抄袭，也顺手防住了改写——
把一件事重新讲一遍，本来就得反复看原文。**授权已经拿到了，本来就该读。**

要保证的不是「没读过」，而是**读完之后写出来的是自己的话**。
那是能量的，`scripts/check-verbatim.mjs` 就是量它的。

> **这不是搬运，也不是翻译，是把同一件事对一个零基础的人重讲一遍。**
> 四章进来出去可能是七章，因为原来一章塞了三件事而初学者接不住。

原课通常有两个毛病，改写就是在治这两个：**一是 AI 味儿太重**——句子对，但没有人
这么说话；**二是默认读者已经懂了**——跳过的那一步正好是初学者卡住的地方。

## 一条不能破的规矩

**通用课引用的出处，必须是权威原始资料，绝不能是我们参考的那门课。**

讲 CSS 就引 MDN，讲 HTTP 就引 RFC 或 MDN，讲 React 就引 React 官方文档，
讲 Git 就引 Git 官方手册。**引用参考的那门课会出严重问题，一次都不许。**

这条不只是合规，它还是个质量闸：
**如果一个说法你找不到权威出处，那这个说法本身就可疑，不该写进课里。**

## 先判断：这门课能不能纳入

三个问题，任何一个答不上来就先停下问人，不要开始改写。

1. **授权拿到了吗？** 口头同意在免费阶段够用，一旦收费就不够。要一份能存进仓库的东西——
   聊天截图、邮件、或原站的开放授权声明。**没有就不要开始。**
2. **背后有没有可运行的仓库？** 有 → 这是**实战学习**，走正常的授课流程，不是这个技能。
   没有 → 这是**通用课**，继续往下。
3. **原课到底教会了什么？** 说不出来就说明结构没想清楚，那就没有值得留的东西，
   纳入它只是把一份糊涂话换个地方糊涂。

判断标准和两类课的分野在 [general-course.md](references/general-course.md)。

## 流程

### 1 把提纲和正文都抓下来

```bash
node scripts/fetch-outline.mjs <url> --out outline/<source>.md --body-out source/<source>.md
```

`--body-out` 那份是**原料**，不是内容。它应当被 gitignore，文件头会自己写明这件事。

**很多值得纳入的站是前端渲染的**，直接 fetch 只拿到一个空壳。VibeHub 就是：
一门课的页面 fetch 下来正文是六个字「正在载入路线」，照那个抽出来的提纲
是一份披着大纲外衣的导航菜单。加 `--render` 走真实浏览器：

```bash
node scripts/fetch-outline.mjs <url> --out outline/x.md --body-out source/x.md --render
```

课程索引页只有各章简介，**每一章的正文在它自己的页面上**，逐个抓。

抓不动就自己看着网页敲进去。**不要为某一个网站写抓取器**——下一个来源一定是另一种形态。

### 2 拆成节

对着提纲，每一章写下两件事：

- 这一章想让读者**会做什么**（一句话，动词开头）
- 为了会做这件事，读者**必须先懂哪几件事**（列出来，每件一行）

然后按"必须先懂的事"拆成节。**一节只教一件事。**
一章讲了四件事就拆成四节——由读者接得住多少决定，不由原来的章节数决定。

### 2.5 给每个说法找权威出处

**这一步在动笔之前做，不是写完之后补。**

把每一节要讲的事实列出来，逐条找权威原始资料：

| 领域 | 去哪找 |
| --- | --- |
| HTML / CSS / JS / Web API | MDN Web Docs |
| HTTP / URI / 邮件等协议 | RFC，或 MDN 的对应条目 |
| 框架、库、工具 | 它自己的官方文档 |
| Git | Git 官方 Book / 手册 |
| 无障碍 | WAI-ARIA / WCAG |

**找不到的那一条，先别写。**它要么是别人的个人经验（那就不该当事实讲），
要么是你记错了。这一步会让课变慢，也正是它让课可信。

### 3 改写

先读唯一的[写课合同](../../../apps/local/.agents/skills/write-lesson/SKILL.md)，
再按其变体、检查清单与卡片／练习引用编写。这里不维护另一套章节模板。
无仓库只改变证据来源，不改变教学合同；对应规则在写课技能的
[无仓库证据附录](../../../apps/local/.agents/skills/write-lesson/references/evidence-and-failures.md#without-a-repository)。

每节必须提供一道有开场依据的预测题；具体任务可以作为开场，不用捏造反常。
类比仅在确实帮助理解时使用，先直白解释，再明确区隔类比并说明边界。
白话改写方法见 [rewriting.md](references/rewriting.md)；它不另行规定课文形状。

## 提案的信封

新建整门课时，JSON顶层必须是：

```json
{ "schemaVersion": 1, "proposalId": "<和文件名同一个 kebab id>", "course": { ... } }
```

只写 `{ "course": ... }` 的提案**落不了盘**——`course create` 的
`CourseCreationProposalSchema` 要这三个字段。第一份 VibeHub 提案就少了信封，
是落盘那天才发现的。

为已有课程追加单元／课时则沿用`unit`＋`lessons`的提案形状；
`assets/sample-proposal.json`是这种追加提案，不是整门课的创建信封。

**不要写 `targetSnapshotId`。** 通用课没有被研究的仓库，所以没有快照可指。
那个字段现在是可选的，留空就是「这门课不研究任何代码」的正式说法。

## 3.5 组件：他的搬过来，我们的加上去

原课里的图、示意图、对照表，往往是他把事情想清楚的地方——**那些要留**。
留的方式有两种，先看能不能重画：

| 情况 | 怎么办 |
| --- | --- |
| 流程图、结构图、对照表 | **自己重画**，用 Mermaid，`kind: "diagram"` |
| 截图、照片、他自己的插画 | 授权范围内直接用，`kind: "authorized-external"`，注明来源 |
| 纯装饰、和内容无关的配图 | 不要 |

重画优先，理由不是版权而是质量：**重画一遍会逼你确认自己真的看懂了那张图**，
看不懂的地方画不出来，而那正是初学者会卡住的地方。

然后加我们自己的，这是原课**没有**的部分，也是这门课凭什么比原课好的地方：

- **练习与记忆卡片**（`exercises` / `cards`）——数量、类型和内容以写课技能的
  [卡片／练习合同](../../../apps/local/.agents/skills/write-lesson/references/cards-and-exercises.md)为准；
  卡片自己也要带evidence。独立练习换输入、条件或例子，不能只复述正文答案。
- **词条**——第一次出现的术语要能点开。
- **AI 讲解入口**——卡住的地方留一个能问的口子。

这些是结构化数据，不把卡片或exercise答案塞进Markdown的`## 自检`。
正文以“一句话”结束，独立练习由下面的练习区判分并反馈。
互动课件可用于观察、示范或独立应用；演示不能顶掉练习，试玩完成不能顶掉课程完成。

### 4 出 proposal

产出一份 JSON，交给已有的落盘流程，**不要自己写课程文件**：

```bash
# 先干跑，看形状对不对
pnpm --filter @pieai/university-local exec node .university-local-build/server/cli.js \
  course add-lessons --study <studyId> --input proposal.json --dry-run
```

课程文件的目录结构、哈希、修订号都由那条流程负责。绕过它自己写文件，
会得到一份 University 读不出来的课，而且错在哪儿要很久才发现。

### 5 过门禁

```bash
node .agents/skills/adopt-outside-course/scripts/check-adoption.mjs proposal.json --verify-urls
node .agents/skills/adopt-outside-course/scripts/check-verbatim.mjs proposal.json --against source/
node apps/local/scripts/check-proposal-shape.mjs proposal.json
```

第一个检查通用课特有的规矩（出处与标记），不定义第二套课文骨架。
`--verify-urls` 会**真的去请求每一条引用**——编一个看起来完全合理的 MDN 链接
是 AI 写课的标志性错误，静态检查看不出来，人工评审也几乎发现不了。

第二个量**还剩多少是原话**。两个数：最长逐字段（抄一整句会在这里露馅），
和 12 字滑窗覆盖率（把句子拆开重排、换几个连接词，最长段会变短但覆盖率不会）。
专有名词和 API 名本来就该一样，所以阈值不是零。

第三个是仓库原有的门禁。**三个都绿了才算完。**

### 6 自己读一遍

门禁只能证明形状对。找一节你**最不熟**的课，从头读到尾，问自己一个问题：

> 如果我完全没接触过这个领域，换一个输入、条件或例子，我还能用出这一节教的东西吗？

答不上"能"，就回第 3 步。**这一步不能跳，也不能交给检查脚本。**

## 两类课的分野

通用课**没有代码仓库**，所以拿不到代码证据。但"每句话都有出处"这条规矩不能松——
**只是出处的种类变了**。

| | 实战学习 | 通用课 |
| --- | --- | --- |
| 出处 | commit + 文件 + 行号 | **权威原始资料**（MDN / RFC / 官方文档） |
| 绝不能引用 | — | **我们参考的那门课** |
| 「跑一下这个版本」 | 有 | 没有 |
| 课程卡 / 关卡卡 / 课文页的标记 | 无（默认） | **三处都要标** |

三处都标，是因为只标一处，人就会在另外两处被骗到。
产品的承诺是「每段解释旁边都是真实代码」——**只要有一个人点开一节课、期待证据、发现没有，
这条承诺对全部课同时失效。**

## 边界

**这个技能不做：**

- 翻译（原文是中文的照样要重写，问题不在语言）
- 摘要（缩短不是目标，读懂才是；改写后变长很正常）
- 实战学习课（有仓库的走正常授课流程，那条路要挂代码证据）
- 落盘（交给 `course add-lessons`）
- 谈授权（这是人的事）
- 把外部课程的句子、图、例子复制进来（一句都不行）

**近邻但不是这个技能：**

- 「帮我读懂这篇教程」→ 直接回答，不要建课
- 「把我们的课导出成 Markdown」→ 反方向，另一件事
- 「给这门课加几张卡片」→ `course add-lessons`，不需要纳入流程

## 产出契约

一次成功的纳入交付三样：

1. `outline/<source>.md` —— 只有章节标题和顺序，**没有正文**
2. `proposal.json` —— 两个门禁都绿，每条 evidence 指向权威原始资料
3. `SOURCES.md` —— 这门课引用了哪些权威资料，按节列出

**`SOURCES.md` 里不出现我们参考的那门课。**课文是我们自己写的，
引用的是 MDN 和官方文档——这就是这门课的全部来历，也是唯一该被记录的来历。
