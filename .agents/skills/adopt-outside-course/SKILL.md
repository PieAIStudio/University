# 纳入别人的课

## 这个技能存在的理由

别人的课只有**一样**东西值得拿：**结构**——讲什么、按什么顺序讲，那是他想清楚的。

其余的全部自己来。句子自己写，例子自己找，**引用自己去找权威原始出处**。

> **这不是搬运，是照着一份提纲重新讲一遍。**
> 外部课程在这里的角色是「目录」，不是「原文」。
> 四章进来出去可能是七章，因为原来一章塞了三件事而初学者接不住。

## 一条不能破的规矩

**通用课引用的出处，必须是权威原始资料，绝不能是我们参考的那门课。**

讲 CSS 就引 MDN，讲 HTTP 就引 RFC 或 MDN，讲 React 就引 React 官方文档，
讲 Git 就引 Git 官方手册。**引用参考的那门课会出严重问题，一次都不许。**

这条不只是合规，它还是个质量闸：
**如果一个说法你找不到权威出处，那这个说法本身就可疑，不该写进课里。**

## 先判断：这门课能不能纳入

三个问题，任何一个答不上来就先停下问人，不要开始改写。

1. **授权拿到了吗？** 口头同意在免费阶段够用，一旦收费就不够。要一份能存进仓库的东西——
   聊天截图、邮件、或原站的开放授权声明。**没有就不要开始。**
2. **背后有没有可运行的仓库？** 有 → 这是**实战学习**，走正常的授课流程，不是这个技能。
   没有 → 这是**通用课**，继续往下。
3. **原课到底教会了什么？** 说不出来就说明结构没想清楚，那就没有值得留的东西，
   纳入它只是把一份糊涂话换个地方糊涂。

判断标准和两类课的分野在 [general-course.md](references/general-course.md)。

## 流程

### 1 只抄提纲

```bash
node scripts/fetch-outline.mjs <url> --out outline/<source>.md
```

**只留三样：章节标题、每章想解决的问题、章节顺序。**

原文正文读一遍就够，**不要存进仓库**。存下来它就会在某一天被当成素材复制进课文里，
而那正是不能发生的事。脚本默认只抽标题和小标题；正文只在终端打印，不落盘。

抓不动就自己看着网页把提纲敲进 `outline/`。来源是什么形态无所谓——
**不要为某一个网站写抓取器**，下一个来源一定是另一种形态。

### 2 拆成节

对着提纲，每一章写下两件事：

- 这一章想让读者**会做什么**（一句话，动词开头）
- 为了会做这件事，读者**必须先懂哪几件事**（列出来，每件一行）

然后按"必须先懂的事"拆成节。**一节只教一件事。**
一章讲了四件事就拆成四节——由读者接得住多少决定，不由原来的章节数决定。

### 2.5 给每个说法找权威出处

**这一步在动笔之前做，不是写完之后补。**

把每一节要讲的事实列出来，逐条找权威原始资料：

| 领域 | 去哪找 |
| --- | --- |
| HTML / CSS / JS / Web API | MDN Web Docs |
| HTTP / URI / 邮件等协议 | RFC，或 MDN 的对应条目 |
| 框架、库、工具 | 它自己的官方文档 |
| Git | Git 官方 Book / 手册 |
| 无障碍 | WAI-ARIA / WCAG |

**找不到的那一条，先别写。**它要么是别人的个人经验（那就不该当事实讲），
要么是你记错了。这一步会让课变慢，也正是它让课可信。

### 3 改写

每节课的正文必须是这六个小节，顺序固定，一个都不能少：

```
## 学习目标
## 先给结论
## 一个类比
## 工作示例
## 自检
## 重点
```

`## 一个类比` 是硬性的，不是可选的。这一条正是"给零基础的人写"在结构上的样子——
一个没有类比的解释，只对已经懂的人成立。

怎么写出真的好懂的句子，见 [rewriting.md](references/rewriting.md)。
六个小节各自该装什么、卡片和练习怎么配，见 [lesson-shape.md](references/lesson-shape.md)。

### 4 出 proposal

产出一份 JSON，交给已有的落盘流程，**不要自己写课程文件**：

```bash
# 先干跑，看形状对不对
pnpm --filter @pieai/university-local exec node .university-local-build/server/cli.js \
  course add-lessons --study <studyId> --input proposal.json --dry-run
```

课程文件的目录结构、哈希、修订号都由那条流程负责。绕过它自己写文件，
会得到一份 University 读不出来的课，而且错在哪儿要很久才发现。

### 5 过门禁

```bash
node .agents/skills/adopt-outside-course/scripts/check-adoption.mjs proposal.json
node apps/local/scripts/check-proposal-shape.mjs proposal.json
```

第一个检查通用课特有的规矩（出处、标记、类比是否真的是类比）。
第二个是仓库原有的门禁。**两个都绿了才算完。**

### 6 自己读一遍

门禁只能证明形状对。找一节你**最不熟**的课，从头读到尾，问自己一个问题：

> 如果我完全没接触过这个领域，读完这一节，我能做到「学习目标」里写的那件事吗？

答不上"能"，就回第 3 步。**这一步不能跳，也不能交给检查脚本。**

## 两类课的分野

通用课**没有代码仓库**，所以拿不到代码证据。但"每句话都有出处"这条规矩不能松——
**只是出处的种类变了**。

| | 实战学习 | 通用课 |
| --- | --- | --- |
| 出处 | commit + 文件 + 行号 | **权威原始资料**（MDN / RFC / 官方文档） |
| 绝不能引用 | — | **我们参考的那门课** |
| 「跑一下这个版本」 | 有 | 没有 |
| 课程卡 / 关卡卡 / 课文页的标记 | 无（默认） | **三处都要标** |

三处都标，是因为只标一处，人就会在另外两处被骗到。
产品的承诺是「每段解释旁边都是真实代码」——**只要有一个人点开一节课、期待证据、发现没有，
这条承诺对全部课同时失效。**

## 边界

**这个技能不做：**

- 翻译（原文是中文的照样要重写，问题不在语言）
- 摘要（缩短不是目标，读懂才是；改写后变长很正常）
- 实战学习课（有仓库的走正常授课流程，那条路要挂代码证据）
- 落盘（交给 `course add-lessons`）
- 谈授权（这是人的事）
- 把外部课程的句子、图、例子复制进来（一句都不行）

**近邻但不是这个技能：**

- 「帮我读懂这篇教程」→ 直接回答，不要建课
- 「把我们的课导出成 Markdown」→ 反方向，另一件事
- 「给这门课加几张卡片」→ `course add-lessons`，不需要纳入流程

## 产出契约

一次成功的纳入交付三样：

1. `outline/<source>.md` —— 只有章节标题和顺序，**没有正文**
2. `proposal.json` —— 两个门禁都绿，每条 evidence 指向权威原始资料
3. `SOURCES.md` —— 这门课引用了哪些权威资料，按节列出

**`SOURCES.md` 里不出现我们参考的那门课。**课文是我们自己写的，
引用的是 MDN 和官方文档——这就是这门课的全部来历，也是唯一该被记录的来历。
