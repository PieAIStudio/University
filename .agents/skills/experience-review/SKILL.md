# 体验审查

## 这个技能存在的理由

2026-08-31 那一轮之前，问题是这样被发现的：**菲哥自己撞上 → 告诉 AI → AI 修。**
这非常耗他的脑力，而且漏掉的比发现的多——那一晚一次审查就挖出 19 条，
其中 4 条是挡路级，包括**线上四天没人能登录**（因此也收不到钱），
以及**产品的核心卖点在线上是 100% 报错**。

所以要的不是更多 UX 原则，是**一台自己会跑、而且结论会死掉的机器**。

## 两条不许违反的规则

### 一 · 按成本分层，和批改分层是同一个形状

这个仓库已经有「确定性优先 → 结构化小模型 → 开放模型」的批改分层。
体验审查用同一个形状，**不是巧合，是为了让它对这个代码库是本地口音**：

```
第 0 层  探针    机器判定   每次 push 都跑   零模型成本
第 1 层  差分    只看变了的 探针事实变了才升级
第 2 层  评审    模型判断   只跑差分         一个评审一个镜头
第 3 层  台账    结论会死   每条有状态，重复的不再报
```

**不要在第 0 层能判的事情上花模型。** 对话框有没有出口、控件有没有被盖住、
点了有没有回应——这些全部机器可判定，所以每次 push 都能跑，
而不是「想起来的时候跑一次」。

### 二 · 一条发现只有写出「哪个测试守着它」，才允许标成已修

```bash
node scripts/experience-ledger.mjs check
```

这条闸门在 `pnpm verify` 里。没有守卫就标已修，会直接失败。

**这是让这件事复利而不是西西弗斯的唯一一条规则。** 没有它，
三周后同一条会被重新发现，而你会开始不看报告。

## 怎么跑一轮

### 先读台账，不要从零开始

```bash
node scripts/experience-ledger.mjs list open
```

已经 `accepted` 的欠账**默认不再出现**。已经 `fixed` 的有测试守着。
你要找的是**新的**。

### 第 0 层：探针

跑 `e2e/`。它们断言的是跨屏不变量，不是某一屏长什么样。
新加的不变量必须是**机器可判定**的，并且必须攻击测试过：
制造缺陷 → 确认变红 → 还原 → 确认变绿。**没见过红的断言不算断言。**

### 第 2 层：评审，一个评审一个镜头

2026-08-31 实测：两个模型独立走同一个线上站，
**前 5 条重要发现 5 条全部重合，剩下 11 条一条都不重合。**

结论：**同一个镜头派两个评审是浪费。** 头部会收敛，价值全在长尾，
而长尾取决于**镜头**不取决于模型。所以按镜头分工，不按模型分工：

| 镜头 | 问什么 | 谁合适 |
| --- | --- | --- |
| 掏钱的人 | 信任在哪一刻建立、在哪一刻崩掉；哪里看起来「廉价」 | 推理强的模型 |
| 看不懂的人 | 我在哪里停下来超过三秒；哪一刻我怀疑「是不是坏了」 | 口语化的模型 |
| 用不了的人 | 键盘、读屏、慢网、弱设备、reduced motion | axe + 手动 |

每个评审必须交出可复现的证据。格式见 `.scratch/uxrace/SCHEMA.md`，
三条硬规则：**没有截图的视觉判断不算数；不许写泛泛的建议；不许猜代码。**

### 第 3 层：合并进台账

台账的键是 **屏幕 + 元素 + 类别**，**不是描述**。

同一个缺陷会被不同评审说成不同的样子——那一晚一个评审说
「档案页先说登录没开放，过一会儿又画出登录表」（症状），
另一个说「包里缺 publishable key」（原因）。**按文字去重会把它们分成两条。**

```bash
node scripts/experience-ledger.mjs diff <本轮结果.json>   # 只看台账没见过的
```

## 已经踩过的坑，不要再踩

- **不要做 600 条超级 checklist。** 它会产出 150 条「可以考虑增加微交互」，
  最后还是人一条条判断，等于没解决。
- **不要建 11 条路径 × 21 个状态 × 2 视口的矩阵。** 462 格跑一次四小时，
  于是只会被跑一次。真正有用的是便宜到不会跳过的那种检查。
- **不要把 State Matrix 写成散文文档。** 会漂移的东西不该是文档，该是测试——
  状态就写在测试的表里，没有漂移的余地。
- **「卡顿」不等于「感知性能」。** 真掉帧要用帧时间量。
  走查和截图永远发现不了它。
- **但不要在隐藏的浏览器面板里量帧时间。** `requestAnimationFrame` 在不可见的
  标签页里会被节流甚至暂停，于是你会读到一个 13 秒的「掉帧」，而那是面板不是产品。
  2026-08-31 试过一次，数字全废。帧时间必须在 e2e 里、用真实可见的浏览器量。
  这和「截图会骗人」是同一条：**视觉证据和时间证据的采集条件不一样，不能共用一次运行。**
- **探针要钉结构，不要钉文案。** 会员页的 CTA 探针写成
  `getByRole("button", { name: "购买" })`，付费文案一改就有五条探针变红——
  而那次改动是对的。会因为正常改文案而变红的断言，会训练你不看报告，
  正是台账要防的那件事。改成 `.plan-card button.liquid-cta__button` 之后，
  它守的是「付费卡上有行动号召」，不是「上面写着两个特定的字」。
- **绿的子集不是闸门。** `pnpm verify` 全绿的时候，
  浏览器 e2e 抓到过 main 上的真实缺陷。学习者可见的改动，两个都要跑。

## 边界

这套东西能替人找：漏状态、遮挡、死路、静默失败、文案歧义、
已知 UX 原则违反、无障碍、回归。

它**证明不了**「真实学生觉得这个产品好用」。它只能说：
按证据，这里高度可能有问题。最终验证仍然是真实用户行为。
