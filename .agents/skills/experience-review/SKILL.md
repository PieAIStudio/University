# 体验审查

## 这个技能存在的理由

2026-08-31 那一轮之前，问题是这样被发现的：**菲哥自己撞上 → 告诉 AI → AI 修。**
这非常耗他的脑力，而且漏掉的比发现的多——那一晚一次审查就挖出 19 条，
其中 4 条是挡路级，包括**线上四天没人能登录**（因此也收不到钱），
以及**产品的核心卖点在线上是 100% 报错**。

所以要的不是更多 UX 原则，是**一台自己会跑、而且结论会死掉的机器**。

## 两条不许违反的规则

### 一 · 按成本分层，和批改分层是同一个形状

这个仓库已经有「确定性优先 → 结构化小模型 → 开放模型」的批改分层。
体验审查用同一个形状，**不是巧合，是为了让它对这个代码库是本地口音**：

```
第 0 层  探针    机器判定   每次 push 都跑   零模型成本
第 1 层  差分    只看变了的 探针事实变了才升级
第 2 层  评审    模型判断   只跑差分         一个评审一个镜头
第 3 层  台账    结论会死   每条有状态，重复的不再报
```

**不要在第 0 层能判的事情上花模型。** 对话框有没有出口、控件有没有被盖住、
点了有没有回应——这些全部机器可判定，所以每次 push 都能跑，
而不是「想起来的时候跑一次」。

### 二 · 一条发现只有写出「哪个测试守着它」，才允许标成已修

```bash
node scripts/experience-ledger.mjs check
```

这条闸门在 `pnpm verify` 里。没有守卫就标已修，会直接失败。

**这是让这件事复利而不是西西弗斯的唯一一条规则。** 没有它，
三周后同一条会被重新发现，而你会开始不看报告。

## 怎么跑一轮

### 先读台账，不要从零开始

```bash
node scripts/experience-ledger.mjs list open
```

已经 `accepted` 的欠账**默认不再出现**。已经 `fixed` 的有测试守着。
你要找的是**新的**。

### 第 0 层：探针

跑 `e2e/`。它们断言的是跨屏不变量，不是某一屏长什么样。
新加的不变量必须是**机器可判定**的，并且必须攻击测试过：
制造缺陷 → 确认变红 → 还原 → 确认变绿。**没见过红的断言不算断言。**

### 第 2 层：评审，一个评审一个镜头

2026-08-31 实测：两个模型独立走同一个线上站，
**前 5 条重要发现 5 条全部重合，剩下 11 条一条都不重合。**

结论：**同一个镜头派两个评审是浪费。** 头部会收敛，价值全在长尾，
而长尾取决于**镜头**不取决于模型。所以按镜头分工，不按模型分工：

| 镜头 | 问什么 | 谁合适 |
| --- | --- | --- |
| 掏钱的人 | 信任在哪一刻建立、在哪一刻崩掉；哪里看起来「廉价」 | 推理强的模型 |
| 看不懂的人 | 我在哪里停下来超过三秒；哪一刻我怀疑「是不是坏了」 | 口语化的模型 |
| 用不了的人 | 键盘、读屏、慢网、弱设备、reduced motion | axe + 手动 |

每个评审必须交出可复现的证据。格式见 `references/evidence-schema.md`，
三条硬规则：**没有截图的视觉判断不算数；不许写泛泛的建议；不许猜代码。**

### 第 3 层：合并进台账

台账的键是 **屏幕 + 元素 + 类别**，**不是描述**。

同一个缺陷会被不同评审说成不同的样子——那一晚一个评审说
「档案页先说登录没开放，过一会儿又画出登录表」（症状），
另一个说「包里缺 publishable key」（原因）。**按文字去重会把它们分成两条。**

```bash
node scripts/experience-ledger.mjs diff <本轮结果.json>   # 只看台账没见过的
```

# 这台机器会怎么死

三种死法。每一种都真的发生过，而且**每一种在发生的当时都长得像「一切正常」**——
这正是它们危险的原因。审查这台机器本身，比多跑一轮审查更值钱。

## 死法一 · 闸门瞎了

闸门还在跑，还是绿的，但它已经看不见它要守的那个东西了。
绿色从「没问题」变成「没在看」，而这两件事在终端里长得一模一样。

**一个闸门写完，先问一句：什么东西坏掉会让它变红？**
如果答不出一件真的会发生的事，它就是装饰。这和上面那条
「没见过红的断言不算断言」是同一条规矩，只是用在闸门自己身上。

已经见过四种瞎法：

- **等一个永远不会出现的东西。** 3D 观感判官的 ready 条件要求场景里存在一个
  只有带海的场景才会挂载的物件；课程岛不带海，于是判官每次都超时。
  仓库唯一的画面质量闸门，**恰好在被投诉的那个场景上是瞎的**，
  而它表现出来的样子只是「这个测试有点慢有点flaky」。
  **超时不是flaky，超时是一个没说出口的失败。**

- **悄悄跳过。** 导出新鲜度检查会跳过本地没有源的学科。工作树里一个软链接
  嵌错了一层，把一个学科藏了起来，于是它跳过那个学科，然后自信地打印
  「3 份导出与课程一致」——而唯一真正过期的就是被跳过的那一个。
  **跳过必须和失败一样大声。** 现在它会说清楚哪几个没检查、因此新鲜度没有被证明。

- **两边一起缩。** 货架检查拿构建的产物和构建的输入比对，两边同源，
  所以上游丢了东西的时候两边一起变小，它永远是绿的。一次重写导出把
  **28 门已经发给顾客的课**从目录里拿掉，全仓所有闸门没有一条变红。
  **一个闸门必须至少有一边是不会跟着一起动的。** 这里那一边是
  「产品已经承诺过的东西」，记在 `apps/university/published-catalog.json`。

- **只查了「可见」的前两层。** 一个元素可以同时 `visibility: visible`、
  `opacity: 1`、`textContent` 一字不少，而人根本看不到它：生产站上地图操作提示
  首次拖动后 `opacity` 归零，`toBeVisible()` 和 `getByText()` 全都照过。
  同一天另一条：会员页 CTA 的五点命中测试全过，因为浮动按钮只压住它的左端，
  中心点仍判给按钮本身——但人一眼就看见两个控件叠在一起。
  三层要分别断言：**在不在 DOM（谓词）→ 点不点得到（命中测试）→
  看不看得见（计算样式 + 截图）。** 只查前两层的探针，
  会在最像「已经修好」的时候放行。

还有一种更粗的：**绿的子集不是闸门。** `pnpm verify` 全绿的时候，
浏览器 e2e 抓到过 main 上的真实缺陷。学习者可见的改动，两个都要跑。

## 死法二 · 证据是假的

结论没错，推理没错，**但那个数字或那张图根本不是产品的**。

**采集条件是证据的一部分。** 记不下采集条件的证据，等于没有证据。
至少要记：哪个 URL（**带完整 query**）、哪个视口、标签页在不在前台、
有没有开调试开关。

- **调试开关会改变画面。** 一张显示场景「发平」的截图，URL 里带着 `post=off`——
  那是个只在开发模式生效的参数，它同时关掉了色彩分级和环境光遮蔽。
  生产永远是开着的。**照着这张图去修光照，修的是一个不存在的产品。**
  拿到任何截图，先看 URL。

- **隐藏的、零尺寸的面板会给出废数据。** 后台标签页里 `requestAnimationFrame`
  会被节流甚至暂停，于是你会读到一个十几秒的「掉帧」；`innerWidth` 是 0 的时候
  DOM 几何全量成 0，于是你会读到一条「面包屑塌成 0 宽」的假缺陷——
  把标签页拉到前台给足尺寸再量，它是好的。WebGL 更狠，直接拍成全黑。
  **量任何几何或时间之前，先确认标签页可见且有真实尺寸。**

- **视觉证据和时间证据不能共用一次运行。** 截图要的是稳定帧，
  帧时间要的是真实浏览器在动。「卡顿」不等于「感知性能」，
  真掉帧要用帧时间量，走查和截图永远发现不了它。

## 死法三 · 报告没人看了

闸门是好的，证据是真的，但人已经学会了忽略它。这是最难救的一种，
因为它没有任何技术症状。

- **探针要钉结构，不要钉身份，也不要钉文案。** 会员页 CTA 探针写成
  `getByRole("button", { name: "购买" })`，付费文案一改就有五条探针变红——
  而那次改动是对的。改成 `.plan-card button.liquid-cta__button` 之后，
  它守的是「付费卡上有行动号召」，不是「上面写着两个特定的字」。
  **同一条错误还有一个更贵的版本：钉在一门具体的课上。** e2e 夹具把课程 id
  写死成某一门课，那门课后来被作者合法地退役，于是 15 条探针一起变红，
  **没有一条是在报它自己要守的那件事**。夹具要问产品「你现在有哪些课」，
  而不是替产品记住它应该有哪一门。

- **一条红的检查配上一个现成的解释，是最危险的组合。** 新鲜度检查红了，
  报的是「这个学科没有活跃课程」。而我笔记里正好存着一条
  「课程工作会让每个工作树的新鲜度变红」——于是我用自己的笔记解释掉了它，
  合并了，四小时后才发现那正是 28 门课消失的第一声警报。
  **当你能不调查就解释掉一个红，那恰恰是必须调查它的时刻**，
  尤其当解释来自你自己的记忆。记忆记的是当时为真的事，不是现在为真的事。

- **菲哥自己找到的问题必须入台账，并记下 `foundBy`。** 这台机器存在的理由
  就是让他不再当发现者；他真的发现了东西的时候不入账，那条就没有状态、
  不要求守卫、可以被我一句「应该是窗口尺寸」搪塞过去然后忘掉——
  底部提示那条正是这么消失的。记 `foundBy` 还有第二个用处：
  **机器漏了多少，是可以被数出来的。**

## 方法上的死路，别再走

- **不要做 600 条超级 checklist。** 它会产出 150 条「可以考虑增加微交互」，
  最后还是人一条条判断，等于没解决。
- **不要建 11 条路径 × 21 个状态 × 2 视口的矩阵。** 462 格跑一次四小时，
  于是只会被跑一次。真正有用的是便宜到不会跳过的那种检查。
- **不要把 State Matrix 写成散文文档。** 会漂移的东西不该是文档，该是测试——
  状态就写在测试的表里，没有漂移的余地。

## 边界

这套东西能替人找：漏状态、遮挡、死路、静默失败、文案歧义、
已知 UX 原则违反、无障碍、回归。

它**证明不了**「真实学生觉得这个产品好用」。它只能说：
按证据，这里高度可能有问题。最终验证仍然是真实用户行为。
