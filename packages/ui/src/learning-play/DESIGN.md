# Design System: University Learning Play

## Overview

**Creative North Star: "可操作的实验台"**

这是 University 的品牌扩展组件：让学习者选择一种玩法，改变可观察的对象，看见原因与结果，再修正或总结。「编程原理」与「用 AI 做产品」两个合集各有五种玩法，每种两个情境，共十种玩法、二十个情境，每个情境有入门、进阶、挑战三份任务配置。接线、图片细节、数轴、缓存、机器人路线，与双原型、材料和顾客、工具和文件、测试响应、产品版本各有自己的操作形状，共享同一套活动外壳与结果反馈。

本文件记录 2026-09-08 已实现并追加玩法迭代的模块。它不改全站品牌；颜色、字族和基础控件由 SwimmerUIKit 提供，frontmatter 中的变量保持绑定，主题值仍以 kit 为准。断点、动效与焦点等扩展说明收在本文件，不另建全局 sidecar。API 与配课边界见 [README](README.md)，学习者行为合同见 journey v5 的[编程玩法](../../../../docs/reference/player-journey/v5/index.html#learning-play)与 [AI 产品玩法](../../../../docs/reference/player-journey/v5/index.html#ai-product-play)。

AI 合集开场明确标为预设教学沙盒。学习者实际操作产品与材料，看到确定性的状态变化；候选产品、计划、响应与修改版本来自预设案例。未知行为通过试用揭示，任务的奖励是修好的行为和能带走的证据，不以模型质量分或通关次数代替判断。

**Key Characteristics:**

- 首先呈现本轮目标和可操作物，线索由学习者主动展开。
- 反馈留下路径、读数、输入、文件或产品状态；错误指向可以修改的原因。
- 对照共享同一操作或输入；当前规则、材料和版本决定哪些证据仍然有效。
- 完成与跳过分开呈现，结果可以交给宿主组合下一段活动。

## Colors

暖中性色承载阅读和操作，橙色吸引动作注意，青色呈现关系与系统状态；明暗主题使用同一组语义变量。

- **Primary：暖橙。** 当前玩法、当前顾客或候选、主要运行按钮、正在传播的信号和机器人沿用主色；文字按上下文使用 kit 的 accent ink / contrast 配对。双版本出现差异时，可用主色边线与文字共同指出变化。
- **Secondary：青色。** 静态连接、工作场地的浅底、已装入材料、检查点和达到目标的指标使用副色。目标区、刻度、来源与文字同时说明状态。
- **Neutral：暖纸色与深棕层次。** 面板、正文、次要文字及边线继承 panel / text / border 系列；局部浅底由现有颜色混合得到。
- **语义反馈。** 成功、可修正问题和碰撞分别使用 kit 的 success、warning、danger 系列，并配文字、图标或边框，颜色不单独承担含义。

## Typography

页面标题、活动标题和关键读数形成主要层级，说明与状态文字紧随操作物。字族继承 frontmatter 的三种绑定；坐标、指令序号、精确输入、文件路径和材料日期使用等宽字体，变化中的读数、响应次数和时间线步数使用等宽数字。文件正文与可复制工作单使用正文字族，保留换行并允许长文本折行。

活动标题为粗体（800），字号随视口变化（20–26px）；桌面活动说明为正文（14px、1.8 行高），手机说明缩为（12px）。AI 工作区标题承接活动标题与操作物，产品名称、当前行动、顾客回答和预约单数量等关键对象可放大；材料正文、候选响应和操作后果采用正文密度，来源与版本标签退到次要层级。参数与指标读数放大，单位维持次要层级。具体实现以 [共享样式](learning-play.css) 与各玩法样式为准；现有紧凑注释的小字号只描述当前布局，不作为新增课程正文的字号规范。

## Layout

试玩宿主居中限宽（1080px），先选择合集，再显示该合集的五个横排玩法入口，情境与难度组成同一行，活动标题后直接进入当前步骤；目标背景、扩展工具和记录按需展开。两个合集入口可换行，当前合集、玩法与情境都有文字标识。单玩与连玩使用同一活动；连玩切换后将新活动开头滚入视口，再聚焦而不二次滚动。

页面底部留出空间（96px），避免手机壳导航遮住尾部内容。内嵌活动拥有容器宽度上下文；玩法按所在课文栏的实际宽度重排，即使浏览器很宽也不强留多列。AI 工作区在现有间距节奏内以区域分组，长材料、路径和状态可折行，按钮可换行，主要操作保持可点击高度（至少 44px）。

**首次进入。** 默认选择入门任务，并显示当前步骤提示。一个页面只突出当前有意义的动作；背景/目标、材料全集、工具箱、完整用例及历史按需展开，不另做遮罩导览或独立教程。五个玩法入口在手机仍同时可见。首个可用动作与固定底栏、反馈浮钮之间留出空间；统计首动作时按真实可操作按钮或滑块，不按 DOM 中出现的第一个按钮。

**难度和帮助。** 入门/进阶/挑战选择的是显式任务载荷。跟随提示/自由探索只改呈现，不影响判定、不清空当前证据。换难度或课节位置则明确开始新一轮。难度具体变化归 README 和载荷定义，不由 CSS、是否计时或提示多少推断；不得把入门提供的事实当作玩家自己推理出的事实。

**运行可见规则。** 指令启动与结果到达时检查棋盘至反馈的可见范围，必要时立即滚到棋盘标题并聚焦；手机预留底部导航空间，桌面已经可见时不额外移动。停止保留指令并返回编辑；碰撞后的“修改第几条指令”滚到对应次数输入框并聚焦。删除指令后焦点转到相邻输入，空列表则转到编辑区标题。

**反馈就近规则。** 原型的客户变更回到新委托，查看原型回到产品标题；验收反馈滚入视口。上下文的顾客回答就近可见，追查来源到对应材料，重生成回到顾客台。Agent 优先让本步实际结果与停止/决定控件共同可见，放不下时保住控件，调整范围可直达相关文件或工具。评测新响应与整组复跑结果聚焦各自标题，编辑或删除用例回到题目区；返工应用版本、开始手工检查、载入操作带或恢复检查点回到当前产品。已有内容在视口内时不作无关滚动。

响应式规则以 [原型及外壳](ai-play.css)、[材料与工具工作区](ai-workflow.css)、[顾客台](ai-context-play.css)、[Agent 文件及执行区](ai-agent-play.css)、[评测与返工](ai-quality.css)的最终层叠为准，不能只读取早期样式中的断点。

## Elevation & Depth

外壳使用 `GamePanel`，按钮、输入和开关保留 kit 的材质、边缘与交互反馈。玩法内部主要用浅色层次和细边线划分对象、仪表与记录；接线节点和玩法入口取消额外阴影，避免多个可操作物堆叠成浮层。AI 工作区依靠产品边框、文件表头、来源分隔与记录底色建立层级；运行成功、受阻与文件损坏改变局部语义状态，不另造一层完成弹窗。棋盘的障碍通过纹理和顶边厚度区别于可走区域。

## Shapes

场地采用柔和矩形，反馈和指令行使用较小圆角，图标容器与节点略更饱满。基础卡片和面板沿用 kit 的 radius card / panel；模块内重复的反馈与棋盘圆角见 frontmatter。双原型、顾客台、文件目标和双版产品沿用同一圆角层级；文件段落、响应单和操作带通过边线分段。圆形用于连接端口、检查点、探针与顾客序号等位置标记。玩法图标与连线使用 SVG；标题、规则、文件、产品状态、坐标说明和结果仍是 DOM 文字。

## Components

基础控件直接使用 `GameButton`、`GamePanel`、`GameField`、`GameInput`、`GameSlider` 与 `GameToggle`。模块负责玩法特有的排列、对象、规则与状态，不复制品牌控件实现。当前玩法使用 primary，其余入口使用 secondary；辅助操作使用 ghost。hover 与按下反馈保留 kit 行为，键盘焦点使用清楚的品牌 focus ring（3px）。

### 当前一步的提示

`PlayGuide` 放在实际操作物旁，由当前状态派生一句目标和必要的一句解释。原型先比较，再逐项问清约定；装箱沿顾客错误打开来源；Agent 首先明确读取范围，再出现真实文件写入决定；评测提供条件与预期都可见的首题，正常题允许确认当前条件；返工按真实操作进度切换产品、改法和记录区。接线、调参、反例、调度与指令也给当前动作提示。

反例的首次按钮执行原测试，并在结果超出视口时带到真实对照及“再换一个输入”入口。调度的三个处理入口同时可见，尚无可用副本时引导模式不让缓存按钮抢走首个可执行动作。材料重生成的粘附工具条避开手机底部导航；高级工具展开后仍使用原控件，不复制一套移动版。

### 反馈与证据状态

局部状态和外壳结果使用文字状态区；空态说明下一步可做的动作，受阻状态说明缺少的材料、权限、试用或验收。完成后保留本轮证据、总结、尝试与提示记录，提供重试和宿主指定的下一步。提示、重新开始与跳过在进行中可达，失败不扣课程进度。完成与跳过分别呈现，每轮只交付一次结果；组件不发 XP、不结算课程。

**当前证据规则。** 记录可以保留，但只有与当前被验收对象一致的证据才能完成本轮。界面必须分清“计划如此”“实际发生”“此前记录”和“需要重试”。

- **原型：** 改约定清空当前试用状态；客户变更保留首轮验收，开始新一轮实际试用。两份产品看起来一致或选齐条款，都不能代替产品操作；首轮通过只是关内阶段。
- **上下文：** 材料包变化后，旧输出仍可查看并标为待更新，顾客试用暂停到重新生成。已验证人数对应当前材料；旧访问记录不冒充新材料的回答。材料的“格”是教学容量，充分的完整包和摘录包都成立，没有额外节省奖励。
- **Agent：** 文件目标区先展示现有内容、尚未执行的计划与可达范围；实际执行区另列本步读取、改动和受阻的文件。授权来自工具能力与文件范围的交集，材料文字不扩大权限。检查点恢复沙盒文件和步骤，保留当前授权及审计痕迹。
- **评测：** 每次响应保留题目、预期、候选和次序。回看旧题或切换候选保留对应观察；新增独立用例保留其他发现，修改或删除只让对应题观察失效。用例集合或产品检查变化后，原整组验收失效，须在当前边界下重跑。候选用中性名称，先前失败不会被后来一次通过覆盖。
- **返工：** 封存的原始失败独立于最近四条探索操作带；游标只决定正在查看哪一步。拖到末尾不等于手工检验，带着回放前缀接操作也不等于从空现场回归。原问题按封存路径复查，旧功能从空现场亲手走完；应用版本、恢复操作带或检查点后，当前版本重新验收。

AI 完成结果可展开并复制文本工作单；复制失败提示直接选中文字，重试复制仍可用。工作单沿用案例中的约定、材料、范围或回归证据，并标明使用前需要换成真实项目事实。研究、答案路线和载荷字段归 [README](README.md) 与计划，本设计文件不另立评分标准。

### 时间、停止与可达性

连续运动用于信号传播与程序执行。接线逐节点推进（240ms）；程序按轨迹长度控制步进（100–420ms）。指标、图片细节和结果出现采用短过渡。`prefers-reduced-motion` 下关闭动画与过渡，接线和程序直接显示同一结果及完整文字轨迹。

调度的 60 秒挑战由学习者主动开启，可暂停、切到后台自动暂停、超时后继续不限时练习。AI 五种玩法没有倒计时惩罚。Agent 自动推进在材料内指令、缺少权限或将改动保留文件等判断点停下，随时可停止；切到后台、离开活动或结束本轮均停止执行。手动调整范围也停止当前推进，随后可继续检查。

返工的时间线是操作历史：上一条、下一条、游标和首次差异跳转指向同一帧，旧版与候选版保持同一步；从这里接新操作会形成探索分支。它不依赖连续自动播放或反应速度。减少动效只取消收据出现和状态过渡，不删除双版差异、响应次序与审计记录。

共享声音设置决定反馈音效，静音时文字仍完整。控件可用键盘操作，图标操作有可访问名称；段落、工具与文件开关的名称包含各自对象，避免多项控件只叫“允许”或“装入”。棋盘提供包含障碍、检查点与当前位置的文字描述，状态以 polite 方式播报。文件内容可键盘聚焦并滚动，时间线同时提供滑块与逐步按钮，鼠标和触摸不需要额外的拖拽专用流程。

## Do's and Don'ts

- **Do** 让参数影响可观察对象，让错误说明指向下一次可以改变的操作。
- **Do** 在窄屏保住对照关系，并让程序运行、停止和错误恢复的焦点跟随当前任务。
- **Do** 保留同一响应式组件树、语义 token、共享声音和确定性结果。
- **Do** 通过产品行为、来源、实际文件和同一输入揭示差异；让新的约定、材料或版本触发对应复查。
- **Do** 将沙盒中的停止、恢复、当前证据与历史记录解释清楚；连玩只编排独立情境，不把五关包装成已经连接的真实项目。
- **Don't** 把图片模糊与工作队列称为真实编码效果或硬件性能；它们是明确标注的教学模型。
- **Don't** 在开场公布反例、候选或修改版本的答案，或用强制计时替代关系、取舍和边界探索。
- **Don't** 把 AI 沙盒称为实时模型调用、真实文件修改、发送或发布；检查点恢复不能暗示真实发送和支付都可撤销。
- **Don't** 把通关、点击数、自动测试或 AI 试玩称为“已掌握”、长期记住或真人觉得好玩。本轮证据只说明规则、控件与反馈吻合；理解迁移与记忆保持仍需真实试学。
