# Design System: University Learning Play

## Overview

**Creative North Star: "可操作的实验台"**

这是 University 的品牌扩展组件：让学习者选择一种玩法，改变可观察的对象，看见原因与结果，再修正或总结。接线、图片细节、数轴、缓存和机器人路线各有自己的操作形状，共享同一套活动外壳与结果反馈。

本文件记录 2026-09-08 已实现的模块。它不改全站品牌；颜色、字族和基础控件由 SwimmerUIKit 提供，frontmatter 中的变量保持绑定，主题值仍以 kit 为准。断点、动效与焦点等扩展说明收在本文件，不另建全局 sidecar。API 与配课边界见 [README](README.md)，学习者行为合同见 [journey v5](../../../../docs/reference/player-journey/v5/index.html#learning-play)。

**Key Characteristics:**

- 首先呈现本轮目标和可操作物，线索由学习者主动展开。
- 反馈留下路径、读数、输入或执行步骤；错误指向可以修改的原因。
- 完成与跳过分开呈现，结果可以交给宿主组合下一段活动。

## Colors

暖中性色承载阅读和操作，橙色吸引动作注意，青色呈现关系与系统状态；明暗主题使用同一组语义变量。

- **Primary：暖橙。** 当前玩法、主要运行按钮、正在传播的信号和机器人沿用主色；文字按上下文使用 kit 的 accent ink / contrast 配对。
- **Secondary：青色。** 静态连接、工作场地的浅底和达到目标的指标使用副色。目标区、刻度与文字同时说明状态。
- **Neutral：暖纸色与深棕层次。** 面板、正文、次要文字及边线继承 panel / text / border 系列；局部浅底由现有颜色混合得到。
- **语义反馈。** 成功、可修正问题和碰撞分别使用 kit 的 success、warning、danger 系列，并配文字、图标或边框，颜色不单独承担含义。

## Typography

页面标题、活动标题和关键读数形成主要层级，说明与状态文字紧随操作物。字族继承 frontmatter 的三种绑定；坐标、指令序号和精确输入使用等宽字体，变化中的读数使用等宽数字。

活动标题为粗体（800），字号随视口变化（20–26px）；桌面活动说明为正文（14px、1.8 行高），手机说明缩为（12px）。参数与指标读数放大，单位维持次要层级。具体实现以 [共享样式](learning-play.css) 与各玩法样式为准；现有紧凑注释的小字号只描述当前布局，不作为新增课程正文的字号规范。

## Layout

试玩宿主居中限宽（1080px），五个玩法入口保持同一横排，下面依次是情境选择、活动标题、目标、操作区、反馈与辅助操作。页面底部留出空间（96px），避免手机壳导航遮住尾部内容。内嵌活动拥有容器宽度上下文，不依赖试玩页面的侧栏。

| 工作区 | 宽布局                                   | 窄布局                                            |
| ------ | ---------------------------------------- | ------------------------------------------------- |
| 接线   | 使用活动载荷的节点位置，连线位于节点之间 | 棋盘宽度小于 540px 时改为两列；场地增高以容纳节点 |
| 调参   | 对象与参数在左，指标在右                 | 容器不超过 540px 时上下排列；两个参数仍可并排     |
| 反例   | 规格、探针、运行与结果依次展开           | 容器不超过 460px 时收紧间距，承诺与实际仍并排比较 |
| 调度   | 当前请求与缓存并列，下方三条处理通道     | 容器不超过 570px 时请求、缓存与通道按一列排列     |
| 指令   | 棋盘与编辑区并列，完整轨迹在下面         | 容器不超过 620px 时棋盘在前、编辑区在后           |

**运行可见规则。** 指令启动与结果到达时检查棋盘至反馈的可见范围，必要时立即滚到棋盘标题并聚焦；手机预留底部导航空间，桌面已经可见时不额外移动。停止保留指令并返回编辑；碰撞后的“修改第几条指令”滚到对应次数输入框并聚焦。删除指令后焦点转到相邻输入，空列表则转到编辑区标题。

## Elevation & Depth

外壳使用 `GamePanel`，按钮、输入和开关保留 kit 的材质、边缘与交互反馈。玩法内部主要用浅色层次和细边线划分对象、仪表与记录；接线节点和玩法入口取消额外阴影，避免多个可操作物堆叠成浮层。棋盘的障碍通过纹理和顶边厚度区别于可走区域。

## Shapes

场地采用柔和矩形，反馈和指令行使用较小圆角，图标容器与节点略更饱满。基础卡片和面板沿用 kit 的 radius card / panel；模块内重复的反馈与棋盘圆角见 frontmatter。圆形用于连接端口、检查点、探针等位置标记。连线与图标采用 SVG，标题、规则、坐标说明和结果仍是 DOM 文字。

## Components

基础控件直接使用 `GameButton`、`GamePanel`、`GameField`、`GameInput`、`GameSlider` 与 `GameToggle`。模块负责玩法特有的排列、对象、规则与状态，不复制品牌控件实现。当前玩法使用 primary，其余入口使用 secondary；辅助操作使用 ghost。hover 与按下反馈保留 kit 行为，键盘焦点使用清楚的品牌 focus ring（3px）。

| 玩法       | 操作与可观察反馈                                                         | 修正与留下的记录                                                                                  |
| ---------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| 因果接线台 | 先点起点再点终点；箭头端点停在节点边缘外；发探针后逐段显示信号           | 连接记录可直接移除；成功与失败分支分别留下文字路径，错误说明缺失或不成立的直接关系                |
| 调参实验室 | 滑动参数时，同一组数值驱动图片细节或工作队列，以及多项目标读数           | 可保存实验对照；原始细节按钮只切换视觉对照，不伪改当前参数或指标；模型说明明确可见                |
| 反例猎手   | 开场展示规则承诺与黑盒；用数轴选点或输入精确值，再比较承诺与实际         | 测试点和历史保留探索过程；程序实现默认折叠，提示另行展开；成立的反例才完成本轮                    |
| 请求调度台 | 根据当前请求、已有缓存与成本选择通道；服务一次后更新后续可用状态         | 具体说明不兼容、缺缓存或预算问题；记录处理顺序、成本和复用。默认不限时，60 秒挑战由学习者主动开启 |
| 指令画布   | 添加前进和转向、调整顺序与重复次数；逐步呈现位置、朝向、检查点和当前指令 | 碰撞格与出错指令对应；支持停止修改或直接看结果；完整文字轨迹可展开复查                            |

**反馈规则。** 局部状态和外壳结果使用文字状态区；完成后保留本轮证据、总结、尝试与提示记录，提供重试和宿主指定的下一步。提示、重新开始与跳过在进行中可达，失败不扣课程进度。

连续运动用于信号传播与程序执行。接线逐节点推进（240ms）；程序按轨迹长度控制步进（100–420ms）。指标、图片细节和结果出现采用短过渡。`prefers-reduced-motion` 下关闭动画与过渡，接线和程序直接显示同一结果及完整文字轨迹。调度可暂停，切到后台自动暂停，超时后可继续不限时练习。

共享声音设置决定反馈音效，静音时文字仍完整。控件可用键盘操作，图标操作有可访问名称；棋盘提供包含障碍、检查点与当前位置的文字描述，状态以 polite 方式播报。鼠标和触摸不需要额外的拖拽专用流程。

## Do's and Don'ts

- **Do** 让参数影响可观察对象，让错误说明指向下一次可以改变的操作。
- **Do** 在窄屏保住对照关系，并让程序运行、停止和错误恢复的焦点跟随当前任务。
- **Do** 保留同一响应式组件树、语义 token、共享声音和确定性结果。
- **Don't** 把图片模糊与工作队列称为真实编码效果或硬件性能；它们是明确标注的教学模型。
- **Don't** 在开场公布反例答案，或用强制计时替代关系、取舍和边界探索。
- **Don't** 把通关、点击数、自动测试或 AI 试玩称为“已掌握”、长期记住或真人觉得好玩。本轮证据只说明规则、控件与反馈吻合；理解迁移与记忆保持仍需真实试学。
